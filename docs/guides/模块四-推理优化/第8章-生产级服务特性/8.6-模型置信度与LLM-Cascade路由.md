一次请求的正确性，不一定需要让 Llama3-70B（约 700 亿参数）模型从头到尾买单。论文在 Llama3-8B-Instruct（约 80 亿参数）→ Llama3-70B-Instruct 的级联实验中报告：MMLU（Massive Multitask Language Understanding，多任务语言理解）上只把约 39% 的问题升级给 70B，就达到全量 70B 的 0.739 准确率；论文表中的每 token 延迟（latency）从 0.292 秒降到 0.145 秒，即 2.03 倍改善。关键不是让小模型假装自己更聪明，而是训练它在答案后生成两个特殊置信度 token（模型词表里的特殊文本单元）`<CN>`（Confident，有把握）与 `<UN>`（Unconfident，不够有把握），再把二者的概率比交给路由器。

## 0. 读前 3 分钟：先把术语和账本钉死

### 0.1 先用一句话理解整条链路

**小模型先回答，答案出来以后再问它“你觉得刚才答对的把握有多大”；把握不足的请求才交给大模型。** 这种“从便宜模型逐级升级到昂贵模型”的链路叫 **LLM Cascade**：`Cascade` 是“级联”，意思是前一级不满足条件，才进入后一级。

这里的 **路由（routing）** 不是网络路由器转发数据包，而是一个按规则决定“这个请求由哪个模型处理”的决策过程。**路由器（router）** 可以是一个额外分类器，也可以像本文这样，直接使用小模型自己产生的置信度。

### 0.2 读者需要先知道的词

| 术语 | 白话定义 | 本文中的作用 |
|---|---|---|
| **大语言模型（Large Language Model，LLM）** | 根据上下文逐步生成文本的模型 | 小模型和大模型都属于 LLM |
| **推理（inference）** | 运行已经训练好的模型来回答问题 | 级联发生在推理阶段 |
| **token** | 模型处理文本时使用的最小片段，可能是一个字、一个词或半个词 | `<CN>`、`<UN>` 是额外加入的特殊 token |
| **batch** | 一次合并处理的多条请求或多段 token | 论文的 batch size 4 表示一次训练更新使用 4 条样本 |
| **GPU（Graphics Processing Unit，图形处理器）** | 适合并行矩阵计算的处理器 | 论文在 GPU 上训练和测量延迟 |
| **API（Application Programming Interface，应用程序接口）** | 让一个程序调用另一个服务的接口 | 级联可以把低置信请求转给大模型 API |
| **softmax** | 把一组原始分数变成总和为 1 的概率分布 | logit 经过它才成为 token 概率 |
| **logit** | softmax 之前的原始分数，还不是概率 | 用来计算 token 概率 |
| **Prefill（预填充）** | 一次处理完整输入上下文、建立初始状态的阶段 | 升级到大模型会再付一次 Prefill 成本 |
| **latency（延迟）** | 从请求到结果之间经过的时间 | 论文表报告每 token latency |
| **logprob** | 概率取自然对数后的数值，概率越大，logprob 越接近 0 | 传统置信度路线常从答案 token 的概率或 logprob 取分 |
| **校准（calibration）** | 置信度为 0.8 的样本集合，真实正确率是否接近 80% | 检查“模型说 0.8”是否真的有 80% 把握 |
| **监督微调（Supervised Fine-Tuning，SFT）** | 用“输入 → 目标输出”样本继续训练模型 | 教模型在答案后接正确的置信度 token |
| **自一致性（self-consistency）** | 对同一问题采样多次，用答案是否一致来当作不确定性信号 | 是一种对比路线，但不是本文的标签构造方法 |
| **LoRA（Low-Rank Adaptation）** | 只训练少量低秩参数，不改动全部模型权重 | 论文用它微调 8B 和 7B 小模型 |
| **tokenizer（分词器）** | 把字符串切成模型 token 的程序 | 不同 tokenizer 会改变答案 token 的概率账本 |
| **hidden state（隐藏状态）** | 模型内部随上下文变化的向量 | 置信 token 依赖完整答案后的隐藏状态 |

### 0.3 回顾：Decode 和 KV Cache 的成本在哪里

生产路由会遇到一个容易被忽略的事实：小模型已经生成了一遍答案，升级后大模型还要再生成一遍。**Decode** 指模型逐个生成输出 token 的阶段；模型每生成一个 token，都要利用前面 token 的注意力状态。**KV Cache（Key-Value Cache，键值缓存）** 就是把已经算过的注意力中间结果保存下来，下一步直接复用，避免从头重算。

这个缓存不是免费的。用 $L$ 表示层数、$H$ 表示注意力头数、$d_h$ 表示每个头的维度、$T$ 表示序列长度、$b$ 表示每个数占用的字节数，K 和 V 两份缓存的大小可以用下面的最小账本估算：

$$
\underbrace{M_{KV} = 2 \times L \times H \times d_h \times T \times b}_{\text{K、V 两份状态的显存}}
$$

直觉是“层数 × 头数 × 每头宽度 × token 数”先算一份状态，再因为 K、V 两种状态乘 2；半精度每个数占 2 字节。以 $L=32$、$H=32$、$d_h=128$、$T=1024$、$b=2$ 为例：

$$
2 \times 32 \times 32 \times 128 \times 1024 \times 2\ \text{bytes}
= 512\ \text{MiB}
$$

💡 **提示**：这是不含 GQA（Grouped-Query Attention，分组查询注意力）或 MQA（Multi-Query Attention，多查询注意力）的最小估算；如果模型让多个查询头共享 KV 头，公式中的 $H$ 应替换为 KV 头数。

所以级联的真实成本不只有“调用大模型的价格”，还包括第二次 Prefill、第二次 Decode、网络传输以及大模型侧的 KV Cache。本文后面先用论文的 latency 口径比较，再把这些遗漏项单独标出来。

## 1. 为什么生产服务需要 LLM Cascade

### 1.1 问题不是“模型会不会答”，而是“每道题值不值得用大模型答”

打个比方：医院分诊台不会让最资深的专家接待每一位普通病人。护士先做一次便宜的初筛，症状简单就直接处理，危险信号出现时才叫专家。这里的对应关系是：护士是小模型，专家是大模型，初筛规则就是路由器，危险信号就是低置信度。

用技术语言重述：小模型先生成答案和置信度；高置信度请求直接返回，低置信度请求升级给更强模型。**级联的价值不是让小模型取代大模型，而是减少大模型被调用的次数。**

### 1.2 成本公式：小模型永远先跑，升级请求再付大模型的钱

设请求总数为 $N$，小模型每个请求成本为 $c_s$，大模型每个请求成本为 $c_l$，其中 $c_l>c_s$；设升级到大模型的比例为 $r$，网络与编排成本为 $C_{net}$。如果所有请求都直接调用大模型：

$$
\underbrace{C_{\mathrm{all-large}}}_{\text{全大模型}}
= \underbrace{N c_l}_{\text{每个请求都付大模型成本}}
$$

而小模型先答、低置信度再升级的级联成本是：

$$
\underbrace{C_{\mathrm{cascade}}}_{\text{级联总成本}}
= \underbrace{N c_s}_{\text{所有请求先跑小模型}}
+ \underbrace{rN c_l}_{\text{只有升级请求再跑大模型}}
+ \underbrace{C_{net}}_{\text{网络与调度开销}}
$$

前一个公式只回答“全大模型要多少钱”；后一个公式把小模型、升级比例和网络都列出来。**不能把“少调用 60% 大模型”直接等同于“总成本省 60%”**，因为小模型仍然跑了一遍，而且跨机器网络可能很贵。

### 1.3 最小数值走查：升级 40%，总成本能省多少

先做一个明确标注为**思想实验**的算例，不把它冒充论文实测：

- 共有 100 个请求；
- 小模型每次成本 $c_s=1$；
- 大模型每次成本 $c_l=10$；
- 60 个请求被判为高置信且确实正确，直接返回；40 个请求升级；
- 暂时忽略网络成本。

全大模型：

$$
C_{\mathrm{all-large}} = 100 \times 10 = 1000
$$

级联：

$$
C_{\mathrm{cascade}} = 100 \times 1 + 40 \times 10 = 500
$$

因此节省比例是：

$$
\frac{1000-500}{1000}=50\%
$$

这个算例说明了两个边界。第一，**大模型越贵，少调用大模型越有价值**；第二，如果网络、重试或大模型端排队成本很大，级联收益会低于这个 50%。论文的 latency 表没有把跨设备网络传输计入，所以它不能直接替代你的 API 账单。

### 1.4 阈值改变什么：质量和成本是一条曲线

设置信心阈值 $\theta$：阈值越高，更多请求会被判为“不够稳”并升级，质量通常上升、成本也上升；阈值越低，升级更少、成本下降，但小模型漏掉的错误更多。阈值不是越接近 0.5 越科学，因为置信度分数只有经过验证集校准后才有概率意义。

| 阈值策略 | 升级比例 | 单请求大致成本（$c_l=10c_s$，忽略网络） | 可能的质量行为 | 来源口径 |
|---|---:|---:|---|---|
| 低阈值 | 20% | $c_s+0.2c_l=3c_s$ | 省钱，但可能放过难题 | 思想实验 |
| 中阈值 | 40% | $c_s+0.4c_l=5c_s$ | 成本与质量折中 | 思想实验 |
| 高阈值 | 70% | $c_s+0.7c_l=8c_s$ | 更接近全大模型，升级成本高 | 思想实验 |

工程上常把“质量快速上升、再加升级率收益变小”的弯折点叫 **knee point（膝点）**。论文实际做得更具体：把置信度分数按 0、5、10、……、100% 的分位数切阈值，画出准确率—升级率曲线，再取达到大模型相当准确率所需的最低升级比例。不要把“knee”写成论文的正式算法名；它是对这条实验曲线的工程读法。

## 2. 两条置信度路线：logprob 还是模型自报

### 2.1 路线 A：事后看答案 token 的 logprob

模型每一步都会先输出一组原始分数 $z_v$，其中 $v$ 遍历整个词表。softmax 把这些分数变成总和为 1 的概率：

$$
\underbrace{p(v\mid x)}_{\text{token 概率}}
= \frac{\exp(z_v)}{\sum_{u\in\mathcal{V}}\exp(z_u)},
\qquad
\underbrace{\operatorname{logprob}(v\mid x)}_{\text{概率的自然对数}}
= \log p(v\mid x)
$$

直觉是：logit 是模型的“原始投票分”，softmax 把所有票数压成概率，logprob 只是把很小的概率变成更容易相加的负数。两个候选 token 的 logit 为 $[2,1]$ 时，概率约为 $[0.731,0.269]$，对应 logprob 约为 $[-0.313,-1.313]$；概率更大的 token，其 logprob 更接近 0。

对一个长度为 $T$ 的答案，工程上常把每个答案 token 的 logprob 聚合成一个分数，例如几何平均概率：

$$
\underbrace{q_{\mathrm{logprob}}}_{\text{答案级置信度}}
= \exp\left(
\frac{1}{T}\sum_{t=1}^{T}
\underbrace{\log p(y_t\mid x,y_{<t})}_{\text{第 }t\text{ 个答案 token 的 logprob}}
\right)
$$

这个式子先把每一步的 logprob 相加，再除以答案长度，最后取指数；因此不会因为答案单纯更长就必然变成更小的总分。比如三个 token 的概率是 $[0.8,0.5,0.5]$，几何平均约为 $0.585$。**但要注意论文的精确实现**：它把这条路线称为 `Zero-shot Logits` 或 `Fine-tuned Logits`，自由文本上平均 token 概率，单 token 选择题上直接取被预测 token 的概率；上面的 logprob 公式是生产系统常见的等价表达，不应伪装成论文原文公式。

这条路线的优点是不用给模型加入特殊 token，也不用额外训练；缺点是“模型觉得这个 token 像不像语言”不一定等于“整道题答对的概率”。答案长度、格式 token、常见套话和词表切分都会影响分数。

### 2.2 路线 B：让模型在答案后自报 `<CN>` 或 `<UN>`

**Confidence Tokens 的核心不是让模型输出一句“我有 80% 把握”，而是在词表里加入两个专用的二分类 token。**

- `<CN>`：`Confident`，表示模型认为刚才的答案正确；
- `<UN>`：`Unconfident`，表示模型认为刚才的答案不正确或不够可靠。

它们不是自然语言里的“置信度 0.8”字符串，也不是论文定义的 10 档分数。模型实际生成的是二选一的特殊 token；连续置信度来自这两个 token 在同一个位置的概率归一化：

$$
\underbrace{c(x,\hat y)}_{\text{连续置信度}}
= \frac{
\underbrace{P(\texttt{<CN>})}_{\text{自报有把握}}
}{
\underbrace{P(\texttt{<CN>})+P(\texttt{<UN>})}_{\text{只在两个置信 token 之间归一化}}
}
$$

比如答案生成完后，模型在下一个位置给出 $P(\texttt{<CN>})=0.75$、$P(\texttt{<UN>})=0.25$，那么 $c=0.75$。如果把两个概率同时乘以 2，分数仍然是 0.75；这说明分数表达的是“在两个置信选项之间更偏向哪一个”，不是整个词表的绝对概率。

### 2.3 两条路线的正面对比

| 维度 | logprob / logits 路线 | Confidence Tokens / Self-REF 路线 |
|---|---|---|
| 训练改动 | zero-shot 不需要；fine-tuned logits 需要普通微调 | 需要在答案后加入 `<CN>` / `<UN>` 并做 SFT |
| 看什么 | 已生成答案 token 的语言概率 | 读完自己生成的答案后，再预测置信 token |
| 校准质量 | 原始概率常与题目正确率错位；论文中 logit 基线常需要高升级率 | 论文在四个数据集上通常给出更好的路由前沿，但不是每个校准指标都最好 |
| 推理开销 | 不额外生成置信 token；返回全量 logprob 会增加数据搬运 | 多一个置信 token 的 decode 或在该位置读取两个 logits |
| 适用条件 | 任何能暴露 logits/logprob 的模型；短答案更容易解释 | 需要能微调小模型，并且训练数据能判断答案对错 |
| 主要风险 | 长度、格式、tokenizer 和局部流畅度污染分数 | 训练分布外的“自信地错”、阈值漂移、特殊 token 被格式污染 |

📌 **关键点**：logprob 路线省掉了训练改动，但它测的是“这段文本像不像模型熟悉的文本”；Confidence Tokens 训练的是“我的答案是否正确”。两者都可能失灵，区别在于失败信号来自哪里。

### 2.4 校准不等于路由有用

一个置信度分数是否校准，可以把样本按分数分桶。假设第 $m$ 个桶里有 $|B_m|$ 个样本，桶内平均置信度是 $\operatorname{conf}(B_m)$，真实正确率是 $\operatorname{acc}(B_m)$，常见的 **ECE（Expected Calibration Error，期望校准误差）** 是：

$$
\underbrace{\operatorname{ECE}}_{\text{整体校准误差}}
= \sum_m
\underbrace{\frac{|B_m|}{N}}_{\text{该桶占全部样本的比例}}
\left|
\underbrace{\operatorname{acc}(B_m)-\operatorname{conf}(B_m)}_{\text{该桶说的与实际差多少}}
\right|
$$

直觉是“每个桶先算偏差，再按桶大小加权”。例如 10 个样本都落在 0.8 桶，实际 6 个答对，那么这个桶的误差是 $|0.6-0.8|=0.2$；如果全体样本都在这个桶，ECE 就是 0.2。

论文还报告了 **BS（Brier Score，布里尔分数）** 和 **CE（Cross-Entropy，交叉熵分数）**。这些指标主要回答“置信度像不像概率”，而级联要回答的是另一个问题：**把最低置信度的请求优先升级后，整体准确率涨得快不快。** 一个方法 ECE 更低，不保证它能把最可能错的请求排在最前面。

## 3. Confidence Tokens 怎么训练出来

### 3.1 三步流水线：先标答案，再学 token，最后取分数

下面这张图把论文的核心机制压成一条可执行流水线：训练时需要真实答案来判断 `<CN>` / `<UN>`；推理时不需要把真实答案交给模型，模型只根据自己已经生成的答案给出置信 token。

<img src="/AIInfraGuide/images/conf-confidence-token-training.svg" alt="Confidence Tokens 的训练与推理流水线" style="max-width: 92%; display: block; margin: 0 auto;" />

*图源：本文根据 arXiv:2410.13284v1 §3 与 Algorithm 1 绘制；不是论文原图。*

论文的 Self-REF 可以拆成三个因果步骤：

1. **先让基础小模型回答训练样本**：对第 $i$ 个输入 $x^{(i)}$ 生成预测 $\hat y^{(i)}$。
2. **用真实标签判断对错并追加 token**：若 $\hat y^{(i)}=y^{(i)}$，追加 `<CN>`；否则追加 `<UN>`。
3. **用追加后的样本做监督微调**：模型学会“答案结束后，依据自己的答案状态预测对应 token”；推理时读取 `<CN>` 和 `<UN>` 的概率，得到连续分数 $c$。

这里最重要的边界是：**论文的标签来自训练集真实答案，不是靠模型多次采样后看答案是否一致。** 自一致性可以作为没有标签时的工程替代信号，但它会把“答案一致”误当成“答案正确”，不属于本文论文实验。

### 3.2 最小三样本：置信标签到底怎么构造

| 样本 | 真实答案 | 基础小模型答案 | 是否相等 | 追加 token |
|---|---|---|---|---|
| 1：$2+2$ | 4 | 4 | 是 | `<CN>` |
| 2：澳大利亚首都 | Canberra | Sydney | 否 | `<UN>` |
| 3：$3\times3$ | 9 | 9 | 是 | `<CN>` |

因此增强后的训练目标可以写成：

```text
输入：2 + 2 = ?       目标：4 <CN>
输入：澳大利亚首都？   目标：Sydney <UN>
输入：3 × 3 = ?       目标：9 <CN>
```

这三个样本不是在教模型“4、Sydney、9”这几个答案本身，而是在答案末尾多放一个监督信号：**正确答案后学 `<CN>`，错误答案后学 `<UN>`。**

### 3.3 为什么错误答案后还要做梯度遮罩

如果把错误样本 `Sydney <UN>` 当作普通 SFT 样本，训练会同时推动模型提高 `P(Sydney | 澳大利亚首都？)`。这会把“学会识别错误”与“学会复现错误答案”绑在一起，方向相反。

论文的做法是：

- 正确样本：保留答案 token 和 `<CN>` 的训练梯度；
- 错误样本：遮住错误答案 token 的梯度，只保留 `<UN>` 的监督；
- 这样模型仍然保留“原任务答案能力”，同时学会在错误答案后发出不自信信号。

可以把训练目标的意图写成下面的简化伪代码。它是**算法示意，不是论文逐字源码**：

```python
# 伪代码：Self-REF 的梯度处理，不是逐字源码
for x, y, y_hat in training_samples:
    if y_hat == y:
        loss = answer_loss(x, y_hat) + confidence_loss(x, y_hat, "<CN>")
    else:
        answer_loss_value = answer_loss(x, y_hat)
        answer_loss_value = stop_gradient(answer_loss_value)  # 不教模型复现错误答案
        loss = answer_loss_value + confidence_loss(x, y_hat, "<UN>")
    update(loss)
```

### 3.4 正负样本比例：论文的 $\alpha$ 在解决什么

论文 Algorithm 1 允许对 `<UN>` 样本下采样：

$$
\underbrace{\mathcal{D}'_{\mathrm{train}}}_{\text{增强训练集}}
= \underbrace{\operatorname{subsample}_{\alpha}(\mathcal{D}'_{\mathrm{train},\texttt{<UN>}})}_{\text{只保留一部分错误样本}}
\cup
\underbrace{\mathcal{D}'_{\mathrm{train},\texttt{<CN>}}}_{\text{保留正确样本}}
$$

其中 $\alpha\in[0,1]$。如果原来有 100 条正确样本和 100 条错误样本，取 $\alpha=0.5$ 后，训练集变成 100 条 `<CN>` 样本加 50 条 `<UN>` 样本。这个数字只是说明公式怎么运行，不是论文固定默认值。

为什么不把所有样本都原样塞进去？因为小模型在某些数据集上可能本来就答错很多，错误样本过多时，`<UN>` 信号会压过原任务答案能力；但错误样本太少，又教不会模型什么时候应该不自信。论文附录通过调节 `<CN>` 与 `<UN>` 比例来避免过拟合。

论文给两个特殊 token 初始化可训练 embedding，初始值取已有 token embedding 的平均值；实验使用 LoRA（低秩适配）在 Llama3-8B-Instruct 和 Mistral-7B-v0.3-Instruct 上微调。这里的“低秩”只表示训练参数更少，不表示置信度天然更可靠。

### 3.5 推理时如何把两个 token 变成一把尺子

答案生成完成后，模型进入“置信度位置”。设这个位置上两个特殊 token 的概率为 $P(\texttt{<CN>})$ 和 $P(\texttt{<UN>})$，论文定义：

$$
\underbrace{c_{\mathcal{M}}(x,\hat y)}_{\text{模型对本次答案的连续置信度}}
= \frac{P(\texttt{<CN>})}{P(\texttt{<UN>})+P(\texttt{<CN>})}
\in[0,1]
$$

逐项看：分子是“我认为答案正确”的概率，分母只保留两个置信 token 的概率，所以输出是 0 到 1；$c$ 越大，路由器越愿意直接返回。代入 $P(\texttt{<CN>})=0.6$、$P(\texttt{<UN>})=0.4$，得到 $c=0.6$。

论文实验的推理设置是贪心解码（每一步取最高概率 token）、temperature=0（温度为零的贪心路径）、top-p=1.0（不裁剪候选），并固定随机种子（seed，随机数起点）2024。生产系统不应只复制这些值：它们是论文评测为了可复现而固定的设置，实际业务还要验证答案格式、并发和阈值漂移。

## 4. Cascade 路由：小模型答不稳就升级

### 4.1 路由规则只有一个分叉

下面的流程图把“答案先出来，再决定是否升级”画成了生产请求路径：

<img src="/AIInfraGuide/images/conf-cascade-routing.svg" alt="小模型先答并按置信度升级到大模型的 Cascade 路由流程" style="max-width: 92%; display: block; margin: 0 auto;" />

*图源：本文根据 arXiv:2410.13284v1 §3.3 与 Figure 1 的语义重绘；不是论文原图。*

给定小模型置信度 $c$ 和阈值 $\theta$，路由规则是：

$$
\operatorname{route}(x)=
\begin{cases}
\text{小模型答案}, & c\ge \theta\\
\text{大模型答案}, & c<\theta
\end{cases}
$$

直觉是把请求按“信心刻度”分成两堆：刻度达到 $\theta$ 的直接出站，低于 $\theta$ 的进入大模型。论文的原始实验就是这个规则，低置信度答案被路由到 Llama3-70B-Instruct，高置信度答案由本地小模型返回。

论文实际把原问题送给大模型，而不是默认把小模型的错误答案拼成大模型前缀。工程上可以把小模型答案作为候选、草稿或 prefix（前缀）上下文，但这会引入“错误答案污染大模型”的新变量；如果目标是复现论文，先只转发原问题。

### 4.2 阈值不是模型参数，而是业务旋钮

论文把 $\theta$ 放在小模型置信度的分位数上。若 $p=0,1,\dots,20$，就约得到 0%、5%、……、100% 的升级率。这样做的好处是不同模型的置信度尺度即使不一致，也能直接比较“升级了多少请求”；代价是分位数本身依赖验证集分布。

生产上更稳的流程是：

1. 用与线上接近的验证集记录 $(c,\text{答案是否正确})$；
2. 扫描一组阈值，得到“升级率—准确率—延迟—成本”曲线；
3. 先满足质量或安全门槛，再在曲线上选最低升级率；
4. 将阈值按业务域、模型版本和输出格式分开保存。

**不要把 $\theta=0.5$ 当成自然常数。** 只有当分数已经校准，并且业务把错误与升级的代价设成对称时，0.5 才有直觉意义。

### 4.3 级联和调度器怎样共存

路由是请求级的分支，调度器仍然要负责把小模型请求、大模型请求、已经完成的请求放进合适的批次。站内 [第 2 章 2.2 Continuous Batching](/AIInfraGuide/inference/模块四-推理优化/第2章-推理引擎核心技术/22-continuous-batching) 讲的是“按迭代步调度”：一个请求完成后立刻让出位置，新请求可以补进来；本文只补充“这个请求是否要进入更贵模型”的判断，不重复调度器的批处理机制。

这里的回顾很重要：**Continuous Batching（连续批处理）不是把所有请求永久绑在一个静态 batch 里，而是每个 token 迭代都动态增删请求。** 级联若把低置信请求突然分流到另一条大模型队列，仍然要观察两条队列的排队时间，否则“少算了大模型次数”可能被排队延迟抵消。

## 5. 论文实验：省了多少，质量掉了多少

### 5.1 实验设置：小模型可微调，大模型只做专家兜底

论文 v1 使用四个公开数据集：

- **MMLU（Massive Multitask Language Understanding）**：覆盖 57 个学科的多选题；
- **OpenBookQA**：需要结合基础科学事实和常识推理的问答数据集；
- **GSM8K**：小学数学文字题；
- **MedQA**：来自医学执照考试的专业多选题。

路由模型对是：

- Llama3-8B-Instruct（约 80 亿参数）或 Mistral-7B-v0.3-Instruct（约 70 亿参数）作为本地小模型；
- Llama3-70B-Instruct（约 700 亿参数）作为更强的大模型。

论文用 LoRA 做参数高效微调，训练时使用 batch size 4、学习率 $10^{-4}$，实验硬件为 8 张 80GB A100。路由时大模型没有继续针对每个任务做微调，而是作为可调用的强模型。这一点决定了数字的含义：它模拟“我能调小模型，但只能调用大模型 API（应用程序接口）”的生产场景。

### 5.2 路由率：Self-REF 把最可能错的请求挑出来

论文把“达到全量 Llama3-70B 相当准确率所需的最低升级比例”作为 Route Rate。下表直接整理 v1 的 routing 结果，并增加一列“未升级比例”，后者是由 $100\%-\text{Route Rate}$ 做的简单计算。

| 本地小模型 → 大模型 | MMLU | OpenBookQA | GSM8K | MedQA | 未升级比例的计算口径 |
|---|---:|---:|---:|---:|---|
| Llama3-8B → Llama3-70B | 39% | 49% | 65% | 40% | 61%、51%、35%、60% |
| Mistral-7B → Llama3-70B | 70% | 50% | 75% | 70% | 30%、50%、25%、30% |

**论文事实**：在四个数据集、两种本地小模型上，Self-REF 的准确率—升级率曲线都优于对比方法；Llama3-8B 在 MMLU 上 39% 的升级率即可达到大模型相当水平。**工程解释**：这个结果说明置信度排序比“随机抽 39% 请求升级”更有用，但它不说明任何线上业务都能固定省 61% 的大模型账单。

### 5.6 拒答实验：不能升级时，低置信度也可以变成安全出口

论文在 MMLU 和 OpenBookQA 上构造了拒答测试：约 50% 的题目把正确选项从候选列表中删除。模型即使必须从剩余选项中选一个，也应该在答案后生成 `<UN>`；系统看到低置信度后，可以返回“无法确定”或走安全默认分支。

论文用 **ROC（Receiver Operating Characteristic，受试者工作特征曲线）** 看“拒答召回率”和“误拒答率”的权衡，并报告 Self-REF 在不同阈值下都优于这些基线。原文没有在正文给出一个可直接复用的单一 ROC 曲线下面积数字，因此这里不编造；生产系统应自己用业务数据画曲线。

## 6. 失败模式：自信地错比不知道更危险

### 6.1 小模型自信地错：`<CN>` 不是安全证明

论文 v1 的案例展示了两种方向：小模型回答错误并产生 `<UN>`，升级到 70B 后得到正确答案；也展示了小模型回答正确、产生 `<CN>`，而未微调的 70B 反而答错。这个结果说明级联不是“永远相信大模型”，而是把两个模型的错误分布错开。

反面案例也很重要：

- **技术题的模式幻觉**：模型熟悉计算机科学、物理或工程题的表面格式，却在边界条件上答错；若仍生成 `<CN>`，路由器会错误地放行。
- **语境题的过度谨慎**：法律、历史或需要长上下文解释的题，模型可能答对却生成 `<UN>`，造成不必要升级。
- **大模型也会错**：级联只能减少一部分错误，不能把大模型当成真值来源；医学等高风险场景仍要保留人工或规则校验。

这些是论文案例和工程解释共同支持的边界，不应把“自报置信度”写成事实核验器。

### 6.2 格式污染：答案内容会影响置信 token

Confidence Token 是在答案末尾、依赖完整已生成答案的状态上预测的。因此答案长度、模板、思维链是否开启、结构化输出是否多了字段，都可能改变置信 token 的 hidden state。**这是工程推断，不是论文单独测出的定律。**

常见污染包括：

- 同一个问题，短答案和长解释使用同一个阈值；
- `<CN>` / `<UN>` 被用户可见模板、停止词或 tokenizer 处理成普通文本；
- 结构化 JSON（JavaScript Object Notation）和自然语言共用一套阈值，但它们的正确性判定完全不同。

正确做法是把“答案格式 + 模型版本 + 采样配置 + 置信度位置”作为一个完整版本一起校准，而不是只保存一个全局 $\theta$。

### 6.3 阈值漂移：验证集上的 0.7 不会永远是 0.7

论文用固定数据集的分位数阈值做实验；线上用户问题会发生分布变化。新增业务域、模型权重变化、系统提示词变化或答案长度变化，都会让置信度分布移动。即使小模型正确率没变，`c` 的数值也可能整体变高或变低。

因此要监控：

- 置信度的 p50（第 50 百分位）、p90（第 90 百分位）和低分尾部比例；
- 每个业务域的升级率和升级后纠错率；
- `<CN>` / `<UN>` 的生成比例以及特殊 token 解析失败率；
- 小模型与大模型的延迟、网络耗时和重试率。

## 7. 生产落地：阈值、监控与业务域

### 7.1 一个最小可落地的请求处理器

下面是把论文规则接到服务里的**简化伪代码**，不是某个推理框架的源码：

```python
# 非逐字源码：请求级 LLM Cascade 路由

def answer(request, threshold_by_domain):
    domain = classify_business_domain(request)
    small_answer, confidence = small_model.answer_with_confidence(request)
    threshold = threshold_by_domain[domain]

    if confidence >= threshold:
        return small_answer

    # 论文原始设置：把原问题交给大模型
    return large_model.answer(request)
```

这里最少要记录 `domain`、小模型版本、置信度、阈值、路由结果、大模型版本和端到端延迟。否则线上出现错误时，你只能看到“答案错了”，不知道是小模型答错、置信度错、阈值错，还是大模型调用超时。

### 7.2 按业务域调阈值，而不是全站一个数字

不同业务的“错误代价”不一样：

- **医疗、合规、支付**：升级和拒答成本低于错误行动，阈值应偏高，并设置人工或规则兜底；
- **代码补全、内部搜索**：可以用验证集选择质量—延迟 knee point，允许一定比例的升级；
- **创意写作**：正确率不是唯一指标，低置信度不一定意味着必须升级，可能只需要保留多样性。

阈值表至少按“业务域 × 模型版本 × 输出格式”分开。新增域没有标注数据时，不要直接复用最成熟域的阈值；先进入 shadow mode（影子模式，只记录路由建议但不改变真实响应）收集数据，再打开真实升级。

### 7.3 监控分布漂移和真实收益

生产监控要同时看三类指标：

1. **信号指标**：置信度分布、`<CN>` / `<UN>` 比例、低置信度尾部；
2. **决策指标**：升级率、升级后纠错率、误放行率、拒答率；
3. **系统指标**：小模型与大模型的 Prefill/Decode 延迟、队列等待、网络传输、每请求成本。

如果置信度 p50 连续偏移、升级率超过预算，先检查输入分布和格式，再重做验证集阈值 sweep。不要只把阈值临时往下调，因为那可能是在掩盖模型已经“自信地错”的事实。

### 7.4 错误做法对比

| 看起来合理的做法 | 为什么会错 | 正确做法 |
|---|---|---|
| 直接把最高答案 token 的概率当“答对概率” | 它只说明模型偏爱这段文本，未必说明事实正确 | 用带标签验证集检查排序能力；必要时训练 Confidence Tokens |
| 把错误答案和 `<UN>` 一起当普通 SFT 目标 | 模型会被推动去复现错误答案 | 对错误答案 token 做梯度遮罩，只学习 `<UN>` 信号 |
| 没有校准就固定 `threshold=0.5` | 两个模型、两个业务域的分数尺度可能不同 | 用验证集扫阈值，按质量门槛选最低升级率 |
| 看到大模型就把小模型答案拼进 prompt | 小模型错误可能污染大模型判断，且这不是论文原始设置 | 先按原问题路由；prefix（前缀）方案单独做 A/B（两组对照）测试 |
| 只看 ECE，忽略升级率和延迟 | 概率刻度漂亮，不代表低分样本真的更可能错 | 同时画 calibration 和 accuracy—routing 曲线 |

## 8. 与第 8 章及站内链路怎么接

### 8.1 与 8.5 采样和 logprobs 的分工

站内 [8.5 采样与解码算法](/AIInfraGuide/inference/模块四-推理优化/第8章-生产级服务特性/85-采样与解码算法) 讲清了 temperature、top-k、top-p、beam search 和 logprobs 的生成语义，也给出了如何从答案 token 概率读出信息；本文只把其中的 logprob 作为“事后置信度”基线，再增加“答案后生成 `<CN>` / `<UN>`”这条训练路线。两篇文章的分工是：8.5 解释采样器怎样产生 token，本文解释置信度怎样决定模型级路由。

如果采样配置改变，logprob 和 Confidence Token 都可能改变。论文为了可复现使用贪心解码；生产接入时要把采样配置纳入阈值版本，不能拿 temperature=0 的校准结果直接覆盖高温对话。

### 8.2 与第 2 章 2.1、2.2 的分工

站内 [第 2 章 2.1 PagedAttention](/AIInfraGuide/inference/模块四-推理优化/第2章-推理引擎核心技术/21-pagedattention) 讲的是 KV Cache 如何分页管理、减少连续显存预留造成的浪费；本文只在成本回顾中使用“级联会增加一轮模型状态和缓存”的结论，不重复分页地址映射。

站内 [第 2 章 2.2 Continuous Batching](/AIInfraGuide/inference/模块四-推理优化/第2章-推理引擎核心技术/22-continuous-batching) 讲的是请求如何按 token 迭代进出 batch、避免静态 batch 等待；本文的新增内容是请求级 `route` 分叉以及小模型队列、大模型队列之间的成本权衡。读者即使不打开这两篇，也能用本文的公式理解级联；打开它们可以继续看缓存和调度器的实现。

### 8.3 与投机解码的关系：都是“小模型先跑”，目标不一样

投机解码也是便宜模型先产生候选，但大模型会在 token 级并行验证，并用 rejection sampling 保证最终分布不变；它的目标是 **保质量、提速度**。站内 [5.1 Speculative Sampling 核心原理](/AIInfraGuide/inference/模块四-推理优化/第5章-speculative-decoding/51-核心原理与rejection-sampling) 讲的是 Draft + Target 的验证和无偏性；本文的 LLM Cascade 是请求级二选一，低置信请求直接改由大模型完成，目标是 **保质量、降大模型调用成本**。不要把一次请求级升级和一次 token 级验证混成同一种路由。

## 原文时代 vs 当前工程

论文 v1 发布于 2024-10，实验基于 Llama3、Mistral、Llama3-70B 和 8 张 A100；它回答的是“在这组多选题数据和硬件上，Self-REF 能否改善路由排序”。它没有给出一个适用于所有模型、所有开放式生成和所有云 API 的固定阈值。

本文的生产建议属于**文章解释或工程推断**：网络成本、隐私、队列、格式污染、按域阈值和漂移监控，不能冒充论文的直接实验结论。部署前至少要重新测三件事：

1. 你的答案格式下，`<CN>` / `<UN>` 是否仍然能稳定生成；
2. 你的验证集上，低置信度是否真的集中包含错误；
3. 加上网络、排队和重试后，级联的总成本是否仍低于全大模型。

## 📝 总结

1. **生产问题**：大模型调用成本高，理想路由器只把难请求升级；级联成本应写成 $Nc_s+rNc_l+C_{net}$，不能把升级率直接当总成本节省率。
2. **论文方法**：Self-REF 用真实答案给基础模型预测贴 `<CN>` / `<UN>` 标签，再做监督微调；错误答案 token 做梯度遮罩，避免模型学会复现错误。
3. **连续分数**：答案结束后读取两个特殊 token 的概率，$c=P(\texttt{<CN>})/[P(\texttt{<CN>})+P(\texttt{<UN>})]$；论文不是让模型输出一串自然语言百分比。
4. **与 logprob 的区别**：logprob 看答案文本的局部概率，Confidence Tokens 学答案正确性信号；论文实验中 Self-REF 的升级率通常低于 zero-shot/fine-tuned logits，但 ECE 最低不等于路由最有用。
5. **实验边界**：Llama3-8B → 70B 在 MMLU 39% 升级达到 0.739 准确率，延迟 0.292 s → 0.145 s；这些是论文 v1 设定下的历史实测，不是线上保证。
6. **工程原则**：阈值按验证集和业务域选择，监控置信度漂移、升级后纠错率、网络与队列成本；小模型“自信地错”时，路由器会把错误放行。
