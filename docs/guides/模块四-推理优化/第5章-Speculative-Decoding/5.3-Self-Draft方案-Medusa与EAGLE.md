5.1 的独立 Draft 模型方案有个绕不开的硬伤:**你要为加速专门再部署一个小模型**——双份显存、双份加载、还要操心两个模型的词表与模板对齐。Self-Draft 的答案是反过来的:**不雇外援,让 target 模型自己长出"打草稿"的能力**。先给结论:Medusa 在模型头部加一排并行解码头,Medusa-1 实测 >2.2x 加速、Medusa-2 达 2.3–3.6x;EAGLE 系列把草稿从 token 层搬到特征层,EAGLE-1 对 LLaMA2-Chat 70B 拿到 2.7x–3.5x,EAGLE-2 的动态草稿树推到 3.05x–4.26x,EAGLE-3 最高 6.5x。这条技术路线的天花板由接受率 α 决定——**每轮期望产出 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$ 个 token,α=0.8 时极限 5x,α=0.6 时只剩 2.5x**。本文把公式推导、Tree Attention、四条路线对比与工程现状一次讲透,是 5.4「收益边界」的直接前置。

## 1. 动机：独立 Draft 模型的痛点

### 1.1 双份显存、双份部署

5.1 讲过的框架:一个小模型先猜 γ 个 token,target 一次前向并行验证,rejection sampling 保证无偏。听起来很完美,但把它搬进生产系统时,工程问题一个接一个:

- **双份显存**：draft 模型虽然小,但也要完整常驻 GPU。7B target 配 1B draft,权重显存从 ~14GB 变成 ~16GB;配 7B draft 给 70B 用,更是实打实多占一份部署空间。
- **双份部署与调度**：draft 和 target 是两个独立模型、两套前向,调度器要把"draft 跑几步 + target 验证一次"组织成一个复合步骤,和 Continuous Batching、Chunked Prefill(2.4 节)的调度逻辑叠加,复杂度直线上升。
- **词表与模板对齐**：draft 和 target 必须"说同一种语言"——词表不一致、指令模板不一致,接受率都会被打折(EAGLE-1 论文专门吐槽过 TinyLLaMA 和 LLaMA2-Chat 模板对不上导致没法当 draft)。
- **最尴尬的场景**：最小的模型没有更小的同族模型可用。7B 想被加速,去哪找同词表、同模板、又足够小的 draft?

**能不能让 target 自己生成草稿,省掉整个外部模型?** 这就是 Self-Draft 路线。

### 1.2 两条 Self-Draft 路线

Self-Draft 的核心思想是:**在 target 身上"长"出一套轻量草稿机制,训练成本远低于预训练一个小模型**。具体有两条路线,本文各讲一半:

- **路线 A:额外解码头(Medusa)**——在模型最后一层 hidden state 上挂 K 个并行"预判头",每个头负责预测未来第 k 个 token。头只有单层 FFN,参数极小。
- **路线 B:特征级自回归(EAGLE 系列)**——不预测 token,而是预测"倒数第二层 hidden state"(特征)。特征比 token 更平滑、更好猜,猜中特征后用 target 自己的 LM Head 转成 token。

打个比方:独立 draft 模型像是为了加快写稿,**专门雇一个便宜的实习生坐在隔壁房间先起草**——工位、培训、对接一样不少。Self-Draft 则是不雇新人,**让主编自己练出"快速打腹稿"的手感**:Medusa 是给主编加一排"快捷词组键"(预判头),EAGLE 是让主编按"语义草图"(特征)而不是逐字默写来起草。两种做法都只动 target 的"手部肌肉",不动"大脑"。

📌 **关键点**：Self-Draft 不是免费提速,而是**把"部署第二个模型"的成本,换成"训练一组小头"的成本**。哪个更划算,取决于你有没有训练能力——这是贯穿全文的选型主线。

## 2. 先算一笔账：加速比的天花板

在讲具体方案前,先把 5.1 留下的数学补完——**加速比到底由什么决定**。这组公式是所有 2.2x、3.5x、6.5x 数字的标尺,没有它,你没法判断一个论文数字是"好"还是"贴着天花板"。

### 2.1 期望接受 token 数的推导

设每轮 target 验证 γ 个草稿 token,草稿第 k 位的接受概率为 α(先假设每位置独立同分布,后面 💡 里再拆掉这个假设)。

**步骤 1**：写出"至少接受前 k 个 token"的概率。因为每位的接受是独立事件,概率相乘:

$$
P(\text{接受数} \geq k) = \underbrace{\alpha^k}_{\text{连续 k 位都通过}}
$$

**步骤 2**：用期望的"层叠"公式算期望接受数。$E[X] = \sum_{k=1}^{\gamma} P(X \geq k)$,把等比数列求和:

$$
E[\text{接受数}] = \sum_{k=1}^{\gamma} \alpha^k = \underbrace{\frac{\alpha(1 - \alpha^{\gamma})}{1 - \alpha}}_{\text{等比数列求和}}
$$

**步骤 3**：每轮的实际产出 = 接受数 + 1。**多出的这个 1 是"保底 token"**——第一个被拒的草稿位置由 target 按 rejection sampling 重采样出一个校正 token(5.1 讲过,这是无偏性的关键)。所以每轮 target 一次前向,平均产出:

$$
E[N] = 1 + \frac{\alpha(1 - \alpha^{\gamma})}{1 - \alpha} = \underbrace{\frac{1 - \alpha^{\gamma+1}}{1 - \alpha}}_{\text{每轮 target 前向的期望产出 token 数}}
$$

**验证一致性**：γ = 1 时 $E[N] = \frac{1-\alpha^2}{1-\alpha} = 1+\alpha$,退化成"猜 1 个,平均接受 α 个"——正确;α → 1 时 $E[N] \to \gamma+1$,全猜全中,每轮产出全部 γ 个草稿加 1 个保底——正确。

💡 **提示**：这个公式有个惊人的推论——**当 γ → ∞ 时,$E[N] \to \frac{1}{1-\alpha}$**。也就是说,草稿猜得再长,加速比也翻不过 $1/(1-\alpha)$ 这道天花板:α=0.8 时极限是 5x,α=0.6 时只有 2.5x。**投机解码的收益上限由草稿质量决定,而不是由 γ 决定**——γ 只是让你"逼近"天花板。

### 2.2 数值算例与工程结论

代入数字感受一下(α=0.8,即草稿平均 80% 命中):

| γ(草稿长度) | $E[N]$(每轮期望产出) | 相对 γ=1 的提升 |
|---|---|---|
| 1 | 1.80 | 1.0x |
| 4 | $\frac{1-0.8^5}{0.2} = 3.36$ | 1.87x |
| 8 | $\frac{1-0.8^9}{0.2} = 4.33$ | 2.41x |
| ∞ | 5.00(天花板) | 2.78x |

这张表的工程结论有三条:

1. **γ 从 1 加到 4,收益最猛**(1.8 → 3.36);再加到 8,只多 1 个 token——所以主流实现把 γ 定在 3~8,再长就是浪费草稿算力。
2. **α 才是主角**：α=0.6 时天花板只有 2.5x。这就是为什么 Medusa 论文里 head 准确率 ~0.6、实测 >2.2x——**数字贴着天花板走**;而 EAGLE-1 准确率 ~0.8、实测 2.7x–3.5x,离 5x 天花板还差一截,差的这部分是草稿模型自身前向开销。
3. **端到端加速比 = 每轮产出 ÷ 每轮耗时**。每轮耗时 = draft 前向 + target 前向;draft 越轻、$E[N]$ 越高,加速比越接近 $E[N]$。

## 3. Medusa：一排预判头加 Tree Attention

Medusa(Cai et al., 2024, arXiv:2401.10774)是 Self-Draft 路线的开山之作,也是"多解码头"这一派的代表。它的卖点一句话:**不改 backbone 结构,只加几个小头,几小时就能训完,部署时还是单模型**。

### 3.1 Medusa 头：预测未来第 k 个 token

在最后一层 hidden state $h_t$ 上挂 K 个并行的解码头。原始 LM Head 照常预测第 t+1 个 token(记作第 0 个头);新增的第 k 个头,专门预测**未来第 k 个 token**(位置 t+k+1):

$$
p_t^{(k)} = \text{softmax}\left( W_2^{(k)} \cdot \left( \text{SiLU}(W_1^{(k)} \cdot h_t) + h_t \right) \right)
$$

$$
\underbrace{p_t^{(k)}}_{\text{第 k 个头预测位置 t+k+1 的分布}} \qquad \underbrace{W_1^{(k)}, W_2^{(k)}}_{\text{单层 FFN,参数 = } d \times d + d \times V}
$$

两个工程细节值得记住:

- **每头就是一层 FFN + 残差**——K 个头的总参数约 $K \times (d^2 + dV)$。对 7B 模型(d=4096、V≈32k),每头约 1.5 亿参数,K=4 时新增不到 6 亿——只占 backbone 的百分之几。
- **初始化有讲究**:$W_2^{(k)}$ 直接复制原始 LM Head 的权重,$W_1^{(k)}$ 初始化为 0。这样训练开始时每个头的预测恰好等于原始模型——**保证训练初期 Medusa 头不会带偏输出**,同时让头从一开始就"说模型的语言"。

**为什么多头能并行预测?** 因为每个头吃的是同一个 $h_t$——第 2 个头预测 t+2 时,**不需要**真的先生成 t+1 的 token。这就是"并行"的来源:一次前向算出 K+1 个位置的分布。代价是每个头的预测都只依赖 $h_t$ 这一个上下文,信息量天然比"看到真实前序 token"的 draft 模型少——这是 Medusa 准确率上限(~0.6)低于 EAGLE(~0.8)的根本原因。

### 3.2 Tree Attention：为什么能一次验证整棵树

光有头还不够。每个头给出 top-$s_k$ 候选,组合起来就是一棵**候选树**。比如第 1 个头取 top-2、第 2 个头取 top-3,就得到 $2 \times 3 = 6$ 条候选 continuation。问题来了:**target 怎么一次性验证这 6 条路径?**

最笨的办法是每条路径当成一条独立序列跑——batch 从 1 涨到 6,而且这 6 条路径共享大量前缀,KV Cache 全部重复计算。Medusa 的答案是 **Tree Attention**:

- 把整棵树的 token **拼成一条序列**放进一次前向,序列长度 = 树的总节点数(各层 $\prod s_i$ 求和)。
- 关键在 attention mask:**每个候选 token 只能 attend 到它自己路径上的前缀**——兄弟分支的 token 互相看不见。这就是"树"的结构注入 attention 的方式。
- 位置编码(如 RoPE)的位置下标也按**路径深度**重新排布,而不是按序列里的物理位置。

打个比方:主编(验证者)拿到 6 份候选草稿,但**每份草稿只"看过"自己前面的那部分内容**——第 2 份草稿的第三句话,只基于"它自己路径上的前两句"来写,不会偷看第 1 份草稿。所有草稿拼在一张纸上同时审(一次前向),共用同一个开头(共享前缀的 KV 只算一遍)。

**为什么这样能"并行验证"?** 因为验证的本质是:对树中每个节点,target 用自己的分布 $p$ 去跟草稿分布 $\hat{p}$ 做 rejection sampling(5.1 的机制,逐节点递归应用)。一次前向就能拿到**所有节点**的 $p$ 值,然后沿着树从根往下走:接受数最多的那条路径胜出,被拒节点的校正 token 照常产出——**无偏性不受影响**。

💡 **提示**：候选树不是越大越好。节点数翻倍,一次前向的计算量跟着涨,但接受率提升有限——Medusa 论文把这叫"树结构搜索"问题(EAGLE-2 会把它从"静态"变成"动态",见第 5 节)。

### 3.3 Medusa-1 与 Medusa-2：两种训练策略

Medusa 论文把训练分成两档,对应两种团队条件:

| 📊 维度 | Medusa-1 | Medusa-2 |
|---|---|---|
| 训练对象 | 只训 K 个头,backbone 完全冻结 | 头 + backbone 联合微调 |
| 损失 | 各头交叉熵加权:$\sum_k -\lambda_k \log p_t^{(k)}$,$\lambda_k = 0.8^k$ | 头的损失 + backbone 自身 next-token 损失(加权重 λ₀) |
| 额外技巧 | 可用量化后的 backbone 提供 hidden state(类似 QLoRA),单卡可训 | 差分学习率 + 头预热(两阶段:先按 Medusa-1 训头,再联合训练) |
| 成本 | Vicuna-7B 约 **5 小时**(单张 A100,60k ShareGPT 样本) | 更高(要动 backbone,且要保住模型原有能力) |
| 实测加速 | **>2.2x** | **2.3–3.6x**(论文摘要口径;v3 正文写 2.3–2.8x,以你读到的版本为准) |
| 副作用 | 无,backbone 是原版 | **checkpoint 被改动**,不再是原版模型 |

📌 **关键点**：Medusa-2 的加速来自"头 + backbone 一起调,头看得到更贴合 backbone 的上下文"。但代价很重:**你手里的模型不再是社区原版**——这会影响可复现性、后续升级、甚至合规审查。论文专门设计了"组合损失 + 差分学习率 + 头预热"三件套来防止 backbone 能力退化,但风险仍在。**默认选 Medusa-1,除非你明确要为速度牺牲原版 checkpoint**。

### 3.4 加速比、无偏性与代价

- **加速比**：Medusa-1 >2.2x,Medusa-2 2.3–3.6x(摘要口径),评估主要基于 batch=1 的本地部署场景——**单用户、低并发**,这是它的舒适区。
- **无偏性**:Medusa 框架本身可以套用 rejection sampling,此时严格无偏。但论文同时给了 **typical acceptance** 方案——用温度阈值"挑合理的候选",跳过 rejection sampling。⚠️ **注意**:typical acceptance 不再保证输出分布与 target 一致,只保证"质量差不多"。要无偏就用 rejection sampling,要更快可以接受"近似无偏"——这是论文明说的取舍。
- **已知短板**：准确率 ~0.6(来自 EAGLE-1 论文的横向对比),天花板就是 2.5x。EAGLE 系列正是冲着补这块短板来的。

## 4. EAGLE-1：把草稿搬到特征层

EAGLE-1(Li et al., 2024, arXiv:2401.15077)拿到了两个关键观察,把 Self-Draft 的准确率从 ~0.6 拉到 ~0.8,加速比翻过 2.5x 天花板。

### 4.1 关键洞察：token 级信息不够用

**观察一:特征比 token 好猜。** token 是自然语言的离散切片,同一个意思有无数种写法;而"倒数第二层 hidden state"(特征)是连续的高维向量,包含的语义信息远多于单个 token。论文实测:同样的草稿模型,在特征层做自回归,加速比 1.9x;在 token 层做,只有 1.5x。

**观察二:特征也有不确定性。** 猜特征时有个陷阱:给定特征 $f_i$,下一个特征 $f_{i+1}$ 取决于**采样结果**——"I"后面既可能接"am"也可能接"always",两种采样结果对应的特征序列完全不同。只给 $f_i$ 让模型猜 $f_{i+1}$,等于让它在多条未来之间赌。

**解法:EAGLE 把"提前一个时间步的 token 序列"也喂给模型**——预测 $f_{i+1}$ 时,输入是 $(f_i, \text{embedding}(t_{i+1}))$,其中 $t_{i+1}$ 是**已经确定的真实 token**(上一轮验证接受的)。采样结果已知,不确定性被消掉,特征预测立刻变得精准:论文里这一招把加速比从 1.9x 推到 2.8x。

说白了:**token 级草稿只知道"上一句话说了什么";EAGLE 还知道"这句话在模型脑子里形成了什么样的语义草图",外加"下一个词板上钉钉是什么"。信息量差一个数量级。**

### 4.2 EAGLE 头的结构：FC 加一个 Decoder Layer

EAGLE 的草稿模型由三块拼成,其中两块**直接复用 target、零训练**:

- **Embedding 层**:用 target 的词嵌入,把提前一步的 token 序列变成向量;
- **LM Head**:用 target 的原始输出头——预测出特征 $f_{i+1}$ 后,直接过它得到下一 token 的分布;
- **Autoregression Head(唯一训练的部分)**:一个 FC 层 + 一个 Transformer Decoder Layer。

流程串起来:

```
输入: 特征序列 (f_1, ..., f_i) + 提前一步的 token 嵌入 (e(t_2), ..., e(t_{i+1}))
  ↓ 拼接成 2×hidden 维度
FC 层降维回 hidden
  ↓
1 个 Decoder Layer(自回归)
  ↓ 预测出 f_{i+1}
target 的 LM Head(冻结) → 分布 p_{i+2} → 采样出草稿 token t_{i+2}
  ↓ 递归
(f_{i+1}, e(t_{i+2})) 作为下一步输入,继续往后猜
```

整个草稿模型只有"FC + 一层 Decoder",对 LLaMA2-Chat 70B 而言**不到 10 亿参数**。每次"猜下一个特征"都是一次小前向,但因为只跑一层,开销远小于跑整个小模型。同样可以用树结构:论文里 3 次草稿前向就能生成一棵 10 节点的树(深度 m、节点数 >m 的树只需 m 次前向)。

### 4.3 训练成本与实测加速比

- **损失**:特征回归用 Smooth L1 + token 分类用交叉熵(权重 0.1),双目标训练;训练时给特征加 $\mathcal{U}(-0.1, 0.1)$ 随机噪声做数据增强,模拟推理时特征预测的误差累积。
- **成本**:LLaMA2-Chat 70B 的 EAGLE 头,用 **70k 条 ShareGPT 对话,4×A100(40G)训 1–2 天**;7B/13B/33B 甚至单张 RTX 3090 就能训。对比一下:预训练一个 TinyLLaMA 要 3000B token——**训练成本差了三四个数量级**,这是 Self-Draft 路线的立身之本。
- **实测**:LLaMA2-Chat 70B 上 2.7x–3.5x 延迟加速、吞吐翻倍;相对 Medusa 快 1.5x–1.6x;叠加 gpt-fast 后 7B 模型在单张 RTX 3090 上跑到 160.4 token/s。
- **无偏性**:EAGLE 不微调 backbone,草稿分布与 target 同源,rejection sampling 严格保证输出分布不变——论文特别强调这一点和 Lookahead、Medusa 的 typical acceptance 划清界限。

## 5. EAGLE-2：动态 Draft Tree

EAGLE-1 用的是**静态树**:每层分支多少,提前定死(像 Medusa 的固定 top-$s_k$)。EAGLE-2(Li et al., 2024, arXiv:2406.16858)发现这个假设是错的:

**静态树假设"接受率只跟草稿位置有关"。但实测接受率还跟上下文有关**——同一个位置,遇到容易的上下文(如代码里的重复模式)接受率 90%,遇到难的上下文(开放对话)可能只有 30%。固定树要么在容易处浪费分支,要么在难处分支不够。

**EAGLE-2 的做法:用草稿模型的置信度动态决定树形。** 关键前提是 EAGLE 的草稿模型**校准良好**——它输出的置信度近似等于真实接受率(误差很小)。于是:

- 每层考察当前节点的 top-k 候选置信度,**置信度高的节点多开分支,置信度低的少开甚至截断**;
- 树的结构每轮根据上下文重新生长,同一位置不同上下文长出不同的树。

打个比方:静态树是**每道题固定给 3 个草稿格**;动态树是**先快速扫一眼题,简单的题给 1 格,难题给 5 格**——把草稿算力花在刀刃上。

实测:EAGLE-2 在三个系列 LLM、六个任务上拿到 **3.05x–4.26x** 加速,比 EAGLE-1 再快 **20%–40%**,且保持 lossless。动态树因此成为后续方案的标准配置。

---

## 6. EAGLE-3：直接预测 Token 加多层特征融合

### 6.1 论文的核心改进

EAGLE-3(Li et al., 2025, arXiv:2503.01840)观察到一个新问题:**给 EAGLE-1/2 加更多训练数据,收益越来越小**。原因是特征预测的约束——单靠"倒数第二层特征 + 提前一步 token",信息通道就这么宽,数据再多也喂不进去。

**EAGLE-3 的两处根本改动**:

1. **放弃特征预测,改回直接预测 token**——但条件不再是"顶层特征",而是**融合低、中、高多层特征**(multi-layer feature fusion),让草稿模型同时看到浅层的词法信息、中层的句法信息、深层语义信息;
2. **引入 training-time test(TTT)**:训练时就用"测试时"的输入构造方式训练草稿模型(即训练数据也按推理时的真实 token 条件来组织,配合位置衰减加权),缩小训练与推理的分布差距。

结果：加速比最高 **6.5x**，相对 EAGLE-2 再快约 **1.4x**；在 SGLang 里 batch=64 时吞吐提升 1.38x。注意最后这个数字——**batch 一大，收益就缩水**（batch≈2~4 时约 1.8x），这条曲线第 9 节还会用到。

### 6.2 工程现状：vLLM 与 AMD 的最新支持

EAGLE-3 是目前 Self-Draft 里**工程生态最完整**的一个:

- **vLLM**:官方文档已把 `method: "eagle3"` 列为标准方法,直接喂 HuggingFace 上的 EAGLE-3 草稿模型即可(社区有 RedHatAI、yuhuili 等发布的 speculator checkpoint):

```bash
# vLLM 启动 EAGLE-3 投机解码(参数格式以你所用版本为准)
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "method": "eagle3",
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 3,
    "draft_tensor_parallel_size": 1
  }'
```

- **AMD(2026-07 官方博客)**:把 EAGLE-3 的"训练 + 量化 + 部署"全链路搬上 AMD Instinct——用 vLLM 服务 target 合成 on-policy 数据、抽取多层 hidden state 训草稿,草稿与 target 都能用 AMD Quark 量化到 FP8/MXFP4。实测(Kimi-K2.5 与 MiniMax-M2.5,MI355X,1K/1K 负载):输出吞吐相对无投机基线提升 **1.38x–2.00x**,低并发时收益最大;MiniMax-M3 草稿的接受长度从 1K 上下文到 32K 上下文稳定在 ~2.65–2.69。

⚠️ **注意**:vLLM 的投机解码配置格式几经演变——V1 早期用 `--speculative_config.method=...` 的散装 flag,现在官方文档统一收口为 `--speculative-config` 传 JSON 对象(上面的写法)。两个模型的 `num_speculative_tokens`、`draft_tensor_parallel_size` 等键值也可能随版本调整,**一切以你所用版本的 `vllm serve --help` 与官方文档为准**。

## 7. Block Verification：从逐 token 验证到整块验证

前面所有方案都默认一个框架:**草稿 token 一个一个验证**(5.1 的 rejection sampling 逐位过)。2024 年 Google 的论文《Block Verification Accelerates Speculative Decoding》(Sun et al., arXiv:2403.10444, ICLR 2025)指出:**逐 token 验证不是最优的**。

- 逐 token 验证:接受/拒绝决定是一个个做的,一旦某个位置被拒,后面的草稿全部作废;
- **Block Verification(块级验证)**:把整块草稿当成一个整体,联合决定"整块过/不过"。论文证明它在"每轮期望产出 token 数"意义上**最优,永远不会比逐 token 差**;实测在多个任务上带来额外 **5%–8%** 的墙钟加速,且保持 lossless 保证,代码复杂度几乎不增加。

工程意义:这是一个**"换掉验证算法,草稿生成器全都不用动"**的即插即用优化——论文原话是"可以当作投机解码实现的默认选项"。它和 Medusa/EAGLE 的树验证(逐节点递归 rejection sampling)可以叠加,5.4 讲收益边界时不再展开。

## 9. 权衡：Self-Draft 换来了什么

讲完机制,回到贯穿全站的框架:这个技术**牺牲了什么,换取了什么**?

**换取的**:

- ✅ **免双模型**:显存省一份、部署少一套、调度少一层——7B target 配 1B draft 的方案直接消失;
- ✅ **草稿与 target 同源**:词表、模板天然对齐,不存在"draft 说的语言 target 听不懂"的接受率折扣;
- ✅ **训练成本低三四个数量级**:几小时到一两天,对比预训练小模型(3000B token 量级);
- ✅ **无偏性白拿**:EAGLE 系列不动 backbone,rejection sampling 严格保证分布不变。

**牺牲的**:

- ❌ **训练门槛**:你必须有数据(最好与 target 分布一致)、有训练算力、有"模型更新后重训头"的运维流程——**零训练能力的团队,Self-Draft 直接出局**(此时回 5.2 的 n-gram/无模型方案);
- ❌ **特征层显存**:EAGLE 系列每步都要 target 的 hidden state(训练时还要抽多层特征),推理时要为特征序列额外开内存与带宽;
- ❌ **实现复杂度**:Tree Attention 的 mask、RoPE 位置重排、动态树的生长逻辑、与 Continuous Batching/Chunked Prefill 的调度叠加(2.4 节)——框架不原生支持的话,自己造轮子成本很高;
- ❌ **不赚钱的边界明确存在**:大 batch 下收益衰减甚至倒挂(EAGLE-3 在 SGLang batch 64 只有 1.38x;vLLM 的 draft_model 实测 batch ≥128 时比 vanilla 还慢)、高温采样下草稿命中率骤降、草稿与 target 差距过大时接受率 <50%——5.4 会系统展开;
- ❌ **Medusa-2 的特殊代价**:动 backbone 后 checkpoint 不再是原版。

**落成一句话的决策规则**:

- ✅ **有训练能力 + 想省双模型** → EAGLE 系列(vLLM 直接支持 `eagle3`),先用社区现成 checkpoint 验证接受率,再决定要不要自己训;
- ✅ **只想快速试点、零训练** → 回到 5.2 的 n-gram/Suffix,或 5.1 的现成 draft model;
- ✅ **手头有同族小模型、不想训任何东西** → draft_model 方案(3.55x 实测就在这条路上);
- ❌ **别为了"最先进的 6.5x"而无视自己的框架支持与 batch 规模**——先跑 100 条业务 prompt 看接受长度(AL),AL < 2 就不值得上投机解码。

## 📝 总结

1. **动机**:独立 draft 模型有双份显存、双份部署、词表对齐三个痛点;Self-Draft 让 target 自己生草稿,把"部署成本"换成"头训练成本"。
2. **数学标尺**:每轮期望产出 $E[N] = \frac{1-\alpha^{\gamma+1}}{1-\alpha}$ 个 token,γ→∞ 收敛到 $1/(1-\alpha)$;α=0.8 天花板 5x,α=0.6 只有 2.5x——Medusa 的 >2.2x 是贴着天花板的数字。
3. **Medusa**:K 个单层 FFN 解码头并行预测未来 token;Tree Attention 用"只看自己路径前缀"的 mask 把整棵候选树塞进一次前向;Medusa-1(冻 backbone)>2.2x,Medusa-2(动 backbone)2.3–3.6x。
4. **EAGLE-1**:特征层自回归 + 提前一步 token 条件,信息量碾压 token 级草稿,准确率 ~0.8 vs Medusa ~0.6,70B 上 2.7x–3.5x,训练只要 70k 条对话。
5. **EAGLE-2/3**:动态树按校准置信度分配分支(3.05x–4.26x);EAGLE-3 弃特征预测改直接 token 预测 + 多层特征融合,最高 6.5x,vLLM `eagle3` 开箱即用。
6. **Block Verification**:块级联合验证被证明逐 token 验证非最优,额外 5%–8% 墙钟加速,可作默认。
7. **权衡**:免双模型、同源对齐、训练便宜;代价是训练门槛、特征层内存、实现复杂度,以及大 batch/高温场景的不赚边界。
