12.1 的四模型回路很重，问题是：能不能干脆把 RL（Reinforcement Learning，强化学习）回路消掉？DPO（Direct Preference Optimization，直接偏好优化）给出的答案是：在同一个 KL 散度（Kullback–Leibler divergence，衡量两个概率分布差异的方向性距离）约束目标下，把典型 RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）训练账本里的 **4 个模型角色压到 2 个**，把在线采样和强化学习更新换成离线偏好对上的二元交叉熵；原论文在 TL;DR（Too Long; Didn’t Read，Reddit 摘要数据集）任务上报告 DPO 约 61% 的胜率、PPO（Proximal Policy Optimization，一种限制策略更新步长的强化学习算法）约 57%，在 CNN/DailyMail（新闻文章摘要数据集）外部分布测试上还以 0.36 对 0.26 胜过 PPO，但它并没有免费制造探索能力——离线数据覆盖不到的行为，正是 DPO 最需要警惕的边界。

## 0. 读前 3 分钟：先把回路和符号摆上桌

### 0.1 12.1 留下的四模型回路

> 💡 **回顾：12.1 的 PPO 回路**
>
> **三要素**是监督微调、奖励模型和 PPO 策略更新：先用 SFT（Supervised Fine-Tuning，监督微调）得到一个会做任务的模型；再让它生成回答，由人或更强的模型给出偏好，训练 RM（Reward Model，奖励模型）把“哪条回答更好”变成分数；最后用 PPO（Proximal Policy Optimization，一种通过限制策略步长来更新模型的强化学习算法）让 policy（策略模型）追求高分，同时用 reference model（参考模型）计算 KL 约束。链条就是：`SFT → 当前策略采样 → 偏好标注 → RM 打分 → PPO（policy + critic）→ 新策略继续采样`。
>
> 这里的 on-policy（在线策略数据）指“样本由当前正在更新的 policy 刚刚生成”；critic（价值模型）则是帮助 PPO 估计“这一步动作大概值多少”的辅助模型。典型工程账本因此有 policy、冻结 reference、RM、critic 四个角色。12.1 已把这条回路完整展开；本篇只把它作为 DPO 的问题起点。

这条回路的问题不是某一个 API 难用，而是三个开销叠在一起：

1. **副本多**：policy、reference、RM、critic 都要占权重、激活或优化器状态；即使 RM 和 critic 比 policy 小，也会制造额外显存峰值。
2. **on-policy 采样贵**：每轮更新前，当前 policy 都要真的生成回答。生成是逐 token 的串行过程，训练既要算梯度，又要维护 rollout（采样轨迹）缓存。
3. **闭环不稳定**：RM 是人类偏好的近似，PPO 又要同时调 KL、优势估计、裁剪范围、学习率等旋钮；策略一旦跑出 RM 熟悉的数据分布，分数可能变得不可信。

**DPO 的核心变化不是“不要偏好数据”，而是“不要在训练循环里再次生成偏好数据”。** 它把 `x、y_w、y_l` 固定在离线数据集里，直接训练 policy 去提高 winner 相对 loser 的概率。

### 0.2 最小符号表：一条偏好对就够了

先把一条样本摆到桌上：给定 prompt（提示词）$x$，有两条回答 $y_w$ 和 $y_l$。下标 $w$ 是 winner（被偏好的回答），下标 $l$ 是 loser（被拒绝的回答）。DPO 的训练数据集记为：

$$
\bigl(x,\,y_w,\,y_l\bigr)\sim\mathcal D。
$$

这里的 $\mathcal D$ 不是“模型自己刚生成的一批新答案”，而是一张提前准备好的偏好表。off-policy（离线策略数据）就是训练时反复读取这张固定表，不要求样本来自当前 policy。

| 符号 | 白话含义 |
|---|---|
| $x$ | 用户问题或任务指令，称为 prompt |
| $y$ | 对 $x$ 的完整回答序列；token（词元）是文本被模型切成的最小片段 |
| $\pi_\theta(y\mid x)$ | 带参数 $\theta$、正在被训练的 policy；给定 $x$ 生成整条 $y$ 的概率 |
| $\pi_{\mathrm{ref}}(y\mid x)$ | 冻结的 reference policy；通常是 SFT 模型，作为“不要偏离太远”的基准 |
| $\pi^*(y\mid x)$ | 如果奖励函数已知、且策略可以任意表示时的理想最优策略 |
| $r(x,y)$ | 对回答质量的标量奖励；数值越大表示越偏好 |
| $\beta>0$ | KL 惩罚强度；越大越不愿离开 reference，越小越愿意追逐偏好 |
| $Z(x)$ | 配分函数：把同一个 $x$ 下所有回答的“加权票数”加起来，用于归一化 |
| $\sigma(z)$ | sigmoid 函数，$\sigma(z)=1/(1+e^{-z})$，把实数分数压到 0 和 1 之间 |

**logit** 在本文指送进 sigmoid 的“偏好比较分数”，不是模型最后一层直接输出词表分数的 raw logit。若这个分数为正，模型就在相对偏向 $y_w$；若为负，则还在偏向 $y_l$。

### 0.3 KL 只承担一个角色

KL 散度（Kullback–Leibler divergence）衡量两个概率分布之间的差异。站内 [第 2 章：数学基础](/AIInfraGuide/prerequisites/模块一-前置知识/第2章-数学基础) 的第 5 节已经用一句核心公式定义了它：$D_{\mathrm{KL}}(p\|q)=\sum_y p(y)\ln[p(y)/q(y)]$，并解释了 Softmax、交叉熵和概率分布的数值含义；那一章负责概率与 KL 的数学地基，本篇只把 KL 放进“奖励最大化减偏离惩罚”的目标中。最小走查是 $p=q$ 时每个比值都是 1，$\ln1=0$，所以 $D_{\mathrm{KL}}(p\|p)=0$：两个分布完全相同时没有偏离成本。

## 1. 问题：为什么要把 PPO 回路拆掉

### 1.1 PPO 实际在优化什么

问题是：PPO 看起来是在“训练一个更会回答的模型”，它到底在最大化哪一个数学量？固定一个 prompt $x$，RLHF 的核心目标可以写成：

$$
\max_{\pi}\quad
\mathbb E_{y\sim\pi(\cdot\mid x)}[r(x,y)]
-\beta D_{\mathrm{KL}}\!\left(\pi(\cdot\mid x)\,\middle\|\,\pi_{\mathrm{ref}}(\cdot\mid x)\right)。
$$

直觉很简单：第一项让模型多生成高奖励回答，第二项像一根橡皮筋，防止模型为了讨好 RM 跑离 reference 太远。$\pi$ 是候选策略，$r$ 是奖励，$\pi_{\mathrm{ref}}$ 是冻结基准，$\beta$ 把两种愿望放到同一张账单上。

论文 §3 的 Eq. 3 在数据分布 $x\sim\mathcal D$ 上写出同一个目标。**DPO 不是另造一个“只看标签”的目标，而是先解这个 KL 约束目标，再把解反过来写成可训练的分类损失。**

### 1.2 为什么不能直接对采样结果做普通梯度下降

一条回答是离散 token 的序列。模型先给出概率，再抽到某个 token；“抽中了哪一个 token”这一步不能像连续变量那样直接沿着采样结果反向传播。因此传统 RLHF 用 PPO 等强化学习方法，把奖励信号绕回 policy。

DPO 的诀窍是：**不在训练时重新采样 token，而是对数据集中已经存在的 $y_w$ 和 $y_l$ 做 teacher forcing（把真实前缀逐步喂给模型，计算每个真实 token 的概率）**。训练因此可以回到普通的最大似然和二元交叉熵路径。

## 2. 核心思想：把奖励函数藏进策略概率比

能不能不用单独训练 RM，仍然表达“这条回答比那条好”？**可以，只要用 policy 相对 reference 的概率比来充当隐式奖励。**

对固定的 $x$ 和一条回答 $y$，DPO 关心的不是 $\pi_\theta(y\mid x)$ 的绝对大小，而是它相对于 reference 改变了多少：

$$
\hat r_\theta(x,y)=\beta\ln\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}。
$$

如果这个比值大于 1，当前 policy 比 reference 更愿意生成 $y$，隐式奖励为正；比值小于 1，隐式奖励为负。这个式子里的“奖励模型”不是另一个网络，而是由 policy 和冻结 reference 的两个 log probability（对数概率）相减得到的分数。

<img src="/AIInfraGuide/images/dpo-ppo-vs-dpo.svg" alt="PPO 在线采样闭环与 DPO 离线偏好训练流程对比" style="max-width: 95%; display: block; margin: 0 auto;" />

这一步像把“老师打分”改成“相对于旧答案，模型自己给这条答案增加了多少信任”：只看相对变化，就能在偏好对上比较，而不必先搭一个独立的分数机器。

但这还只是直觉。要证明它确实等价于原来的 KL 目标，需要沿着三步走：

1. **Step 1**：先解 KL 约束，得到最优策略的闭式解。
2. **Step 2**：把奖励反解成策略概率比，并让 Bradley–Terry 偏好模型消掉 $Z(x)$。
3. **Step 3**：把结果写成只依赖 $\pi_\theta$ 和 $\pi_{\mathrm{ref}}$ 的二元交叉熵。

### 3.1 Step 1：KL 约束下的最优策略

问题是：既要多拿奖励，又不能离 reference 太远，最好的概率分布长什么样？**它等于 reference 概率乘上一个由奖励决定的指数权重，再做一次归一化。**

先固定一个 prompt $x$，把 $q_y=\pi(y\mid x)$、$p_y=\pi_{\mathrm{ref}}(y\mid x)$、$r_y=r(x,y)$ 写得短一点。目标变成：

$$
\max_{q}
\quad
\sum_y q_y r_y
-\beta\sum_y q_y\ln\frac{q_y}{p_y},
\qquad
\text{约束：}\sum_y q_y=1。
$$

- $q_y$ 是候选策略给回答 $y$ 的概率。
- $p_y$ 是 reference 给同一回答的概率。
- $r_y$ 是这条回答的奖励。
- $\beta$ 控制偏离惩罚。
- $\sum_y q_y=1$ 是概率分布必须加起来为 1 的约束。

**拉格朗日乘子的一句话作用**：乘子 $\lambda(x)$ 只负责把“概率总和等于 1”写进目标；求导后它对所有 $y$ 都是同一个常数，最后会被归一化常数 $Z(x)$ 吸收。

把约束写进去：

$$
\mathcal L(q,\lambda)
=
\sum_y q_y r_y
-\beta\sum_y q_y\ln\frac{q_y}{p_y}
+\lambda\left(\sum_y q_y-1\right)。
$$

对某一个 $q_y$ 求偏导。这里用到了
$\frac{\partial}{\partial q_y}[q_y\ln(q_y/p_y)]=\ln(q_y/p_y)+1$：

$$
\frac{\partial\mathcal L}{\partial q_y}
=
 r_y-\beta\left(\ln\frac{q_y}{p_y}+1\right)+\lambda
=0。
$$

把对数项单独留在左边：

$$
\ln\frac{q_y}{p_y}
=
\frac{r_y}{\beta}+\frac{\lambda}{\beta}-1。
$$

两边取指数。右侧最后两项只依赖 $x$，不依赖具体回答 $y$，所以可以合并成一个只关于 $x$ 的常数 $C(x)$：

$$
q_y=C(x)\,p_y\exp\left(\frac{r_y}{\beta}\right)。
$$

再用 $\sum_yq_y=1$ 求 $C(x)$：

$$
1
=C(x)\sum_y p_y\exp\left(\frac{r_y}{\beta}\right)，
\qquad
Z(x)=\sum_y p_y\exp\left(\frac{r_y}{\beta}\right)。
$$

因此 $C(x)=1/Z(x)$，得到论文 Eq. 4 的闭式解：

$$
\boxed{
\pi^*(y\mid x)
=
\frac{1}{Z(x)}\,
\pi_{\mathrm{ref}}(y\mid x)
\exp\left(\frac{r(x,y)}{\beta}\right)
}
$$

每一项的意思是：

- $\pi^*(y\mid x)$：KL 约束下真正的最优策略。
- $\pi_{\mathrm{ref}}(y\mid x)$：旧模型原本给这条回答的概率，提供“不要凭空跑远”的底座。
- $\exp(r/\beta)$：奖励越高，放大越多；$\beta$ 越小，放大越激进。
- $Z(x)$：同一个 prompt 下所有回答的加权总和，保证最终概率仍然加起来为 1。

**最小数值走查。** 假设一个 prompt 只有两条候选回答 A、B：

| 量 | A | B |
|---|---:|---:|
| $\pi_{\mathrm{ref}}(y\mid x)$ | 0.6 | 0.4 |
| $r(x,y)$ | 1 | 0 |
| $\beta$ | 1 | 1 |
| 未归一化权重 $\pi_{\mathrm{ref}}e^{r/\beta}$ | $0.6e\approx1.6308$ | $0.4e^0=0.4$ |

所以：

$$
Z(x)=1.6308+0.4=2.0308，
\qquad
\pi^*(A\mid x)=\frac{1.6308}{2.0308}\approx0.803，
\qquad
\pi^*(B\mid x)\approx0.197。
$$

reference 原本只给 A 0.6，奖励差 1 后，最优策略把 A 提到约 0.803。**奖励的作用不是凭空创造概率，而是在 reference 的概率上做指数倾斜。**

💡 **提示：$Z(x)$ 为什么暂时不能直接算？** $y$ 是任意长度的完整回答，求和要遍历几乎所有可能的 token 序列。学生幻灯片第 15 页用 $|V|=50000$、长度 $L=200$ 的思想实验说明，候选数约为 $|V|^L\approx10^{940}$；这不是一个可以在训练中逐个枚举的词表。因此 DPO 的下一步不是估计 $Z(x)$，而是让它在偏好比较中自动相消。

### 3.2 Step 2：把奖励改写成策略比，配分函数相消

问题是：既然 $Z(x)$ 巨大到不能算，能不能从 Step 1 的式子反过来解出 $r(x,y)$？**可以，取对数后，奖励由“当前最优策略相对 reference 的 log 概率比”加上一个只依赖 prompt 的常数组成。**

从 Step 1 开始：

$$
\pi^*(y\mid x)
=\frac{1}{Z(x)}\pi_{\mathrm{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right)。
$$

两边先取自然对数：

$$
\ln\pi^*(y\mid x)
=-\ln Z(x)+\ln\pi_{\mathrm{ref}}(y\mid x)+\frac{r(x,y)}{\beta}。
$$

把奖励项移到左边，再乘以 $\beta$：

$$
\boxed{
 r(x,y)
=\beta\ln\frac{\pi^*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}
+\beta\ln Z(x)
}
$$

这就是论文 Eq. 5。第一项随回答 $y$ 变化，第二项 $\beta\ln Z(x)$ 对同一个 prompt 的所有回答都相同。

接下来引入 Bradley–Terry 模型。它是一个“二选一投票模型”：给定同一个 $x$ 的两条回答，奖励差越大，第一条被选中的概率越高：

$$
P(y_1\succ y_2\mid x)
=\sigma\bigl(r(x,y_1)-r(x,y_2)\bigr)。
$$

这里 $\succ$ 表示“被偏好”，$\sigma$ 是前面定义的 sigmoid。括号里的奖励差就是偏好 logit：正得越多，第一条越可能赢。

令 $y_w$ 是 winner、$y_l$ 是 loser，把 Step 2 分别代入：

$$
\begin{aligned}
&r(x,y_w)-r(x,y_l) \\
&=\left[\beta\ln\frac{\pi^*(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}+\beta\ln Z(x)\right] \\
&\quad-\left[\beta\ln\frac{\pi^*(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}+\beta\ln Z(x)\right] \\
&=\beta\ln\frac{\pi^*(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-\beta\ln\frac{\pi^*(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}。
\end{aligned}
$$

**为什么相消？** 因为比较的是同一个 prompt $x$ 下的两条回答。它们共享同一个“所有候选回答的总票箱” $Z(x)$，所以差值里出现的是 $\beta\ln Z(x)-\beta\ln Z(x)=0$。如果两条回答属于不同的 prompt，就不能这样直接相减。

因此：

$$
P(y_w\succ y_l\mid x)
=
\sigma\left(
\beta\ln\frac{\pi^*(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\beta\ln\frac{\pi^*(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right)。
$$

**最小数值走查。** 设 $\beta=0.5$，当前暂时用理想策略的两个概率比：

$$
\frac{\pi^*(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}=2，
\qquad
\frac{\pi^*(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}=0.5。
$$

令 $\ln Z(x)=\ln3$（先为演示随便给一个值，反正相减时会消掉），那么两条隐式奖励分别是：

$$
\begin{aligned}
r_w&=0.5\ln2+0.5\ln3,\\
r_l&=0.5\ln0.5+0.5\ln3。
\end{aligned}
$$

相减时，两个 $0.5\ln3$ 消失：

$$
 r_w-r_l
=0.5(\ln2-\ln0.5)
=0.5\ln4
\approx0.693。
$$

所以：

$$
P(y_w\succ y_l\mid x)=\sigma(0.693)\approx0.667。
$$

你可以看到，**不知道 $Z(x)$ 的具体值，并不妨碍比较同一个 $x$ 下的两条回答**。DPO 正是把计算从“枚举所有答案做归一化”换成“只比较数据中出现的 winner 和 loser”。

### 3.3 Step 3：得到 DPO 二元交叉熵

问题是：Step 2 里还是理想策略 $\pi^*$，训练时我们手里只有带参数的 $\pi_\theta$，应该怎样让它靠近理想策略？**把 $\pi^*$ 换成 $\pi_\theta$，再最大化数据中 winner 被选中的概率，就得到 DPO 损失。**

先定义一条偏好样本的比较分数：

$$
\Delta_\theta(x,y_w,y_l)
=
\beta\ln\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\beta\ln\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}。
$$

它由两部分组成：

- **winner 相对提升**：$\ln[\pi_\theta(y_w\mid x)/\pi_{\mathrm{ref}}(y_w\mid x)]$。当前 policy 比 reference 更看好 winner 时，这项为正。
- **loser 相对提升**：$\ln[\pi_\theta(y_l\mid x)/\pi_{\mathrm{ref}}(y_l\mid x)]$。它前面有减号，所以当前 policy 越抬高 loser，这个比较分数越低。
- **$\beta$**：把两个相对 log 概率一起缩放，控制 sigmoid 的尖锐程度和 KL 约束强度。

对标签“winner 应该赢”做二元交叉熵，标签为 1 时就是对预测概率取负对数：

$$
\boxed{
\mathcal L_{\mathrm{DPO}}(\theta)
=-\mathbb E_{(x,y_w,y_l)\sim\mathcal D}
\left[
\ln\sigma\left(
\beta\ln\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\beta\ln\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right)
\right]
}
$$

这就是论文 Eq. 7。$\mathcal L_{\mathrm{DPO}}$ 是平均损失，$\theta$ 是 policy 参数，$\mathcal D$ 是偏好数据集，$\pi_\theta$ 只在训练中更新，$\pi_{\mathrm{ref}}$ 冻结不更新。**损失越小，表示 policy 越有把握让 winner 的相对概率高于 loser。**

#### 两个数就能看出“偏好被强化”的方向

取 $\beta=1$，先只看一条偏好对。这里的比值是整条回答序列的概率比，不是单个 token 的 raw logit：

| 状态 | winner 比值 $\pi_\theta/\pi_{\mathrm{ref}}$ | loser 比值 $\pi_\theta/\pi_{\mathrm{ref}}$ | 比较 logit $\Delta$ | $\sigma(\Delta)$ | loss $-\ln\sigma(\Delta)$ |
|---|---:|---:|---:|---:|---:|
| 当前 | 2 | 0.5 | $\ln2-\ln0.5=\ln4\approx1.386$ | $0.800$ | $0.223$ |
| 偏好强化后 | 4 | 0.25 | $\ln4-\ln0.25=\ln16\approx2.773$ | $0.941$ | $0.061$ |

第一行表示 policy 相对于 reference 抬高 winner、压低 loser；第二行把这个相对差距继续拉大。损失从 0.223 降到 0.061，方向完全符合“winner 更应该赢”。

注意一个容易混淆的点：DPO 不是无条件地把 $\pi_\theta(y_w\mid x)$ 拉到 1。它一直比较 reference，并通过 $\beta$ 控制偏离幅度。**“偏好”是相对 reference 的改变，不是脱离 reference 的绝对崇拜。**

#### 为什么 DPO 不是 chosen-only SFT

论文还给出了梯度的机制解释。定义隐式奖励：

$$
\hat r_\theta(x,y)=\beta\ln\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}。
$$

则梯度可以写成：

$$
\nabla_\theta\mathcal L_{\mathrm{DPO}}
=-\beta\,\mathbb E\left[
\underbrace{\sigma\bigl(\hat r_\theta(x,y_l)-\hat r_\theta(x,y_w)\bigr)}_{\text{当前排序越错，权重越大}}
\left(
\underbrace{\nabla_\theta\ln\pi_\theta(y_w\mid x)}_{\text{提高 winner 概率}}
-
\underbrace{\nabla_\theta\ln\pi_\theta(y_l\mid x)}_{\text{降低 loser 概率}}
\right)
\right]。
$$

这条式子做了两件事：方向上同时提高 winner、降低 loser；权重上优先修正当前 policy 还把 loser 排在 winner 前面的难样本。沿用上一张表，当前行的 $\hat r_w=\ln2\approx0.693$、$\hat r_l=\ln0.5\approx-0.693$，权重为 $\sigma(-1.386)\approx0.2$；如果两者顺序反了，权重会变大。**所以 DPO 比“只在 chosen（被选中的回答，即 $y_w$）上做 SFT、对 rejected（被拒绝的回答，即 $y_l$）做惩罚”多了一层动态排序权重。**

### 3.4 一条完整的推导链

把三步压缩成一句可背诵、又不丢数学的链：

$$
\underbrace{\pi^*(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)e^{r(x,y)/\beta}}_{\text{Step 1：KL 约束的最优策略}}
\quad\Longrightarrow\quad
\underbrace{r(x,y)=\beta\ln\frac{\pi^*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}+\beta\ln Z(x)}_{\text{Step 2：奖励重参数化}}
\quad\Longrightarrow\quad
\underbrace{\mathcal L_{\mathrm{DPO}}=-\ln\sigma(\Delta_\theta)}_{\text{Step 3：对偏好标签做交叉熵}}。
$$

前一箭头解的是优化问题，中间一步只是取对数并移项，后一箭头利用了同一个 $x$ 下的 Bradley–Terry 奖励差。DPO 的“直接”二字，指的是直接对 policy 做最后一步训练，不是跳过前两步的数学依据。

## 4. 训练时到底跑什么：DPO 的前向与反向

### 4.1 训练输入不是新回答，而是三元组

每条训练样本只有：

```text
x   = prompt（提示词，用户问题）
y_w = preferred completion（被偏好的回答，即 winner）
y_l = dispreferred completion（被拒绝的回答，即 loser）
```

模型不需要在这一步生成 $y_w$ 和 $y_l$。它只需要在已知的真实前缀下，逐 token 算出两条回答的 log probability：

$$
\ln\pi_\theta(y\mid x)
=
\sum_{t=1}^{T_y}
\ln\pi_\theta(y_t\mid x,y_{<t})。
$$

- $T_y$ 是回答的 token 数。
- $y_t$ 是第 $t$ 个 token。
- $y_{<t}$ 是它之前的真实 token。
- 求和把整条回答的条件概率乘积变成了更稳定、也更容易累加的 log probability。

**最小数值走查。** 假设回答只有 3 个 token，policy 给出的条件概率是 $[0.5,0.8,0.25]$，那么整条回答概率是 $0.5\times0.8\times0.25=0.1$，log probability 是：

$$
\ln\pi_\theta(y\mid x)
=\ln0.5+\ln0.8+\ln0.25
\approx-0.693-0.223-1.386=-2.302
=\ln0.1。
$$

实际实现会对 policy 和 reference 各做一次前向，得到两条回答的 sequence log probability（整条回答的序列对数概率），再代入 Step 3。reference 虽然不反向更新，却不能凭空消失：它提供 KL 基准和相对概率比。

### 4.2 非逐字源码的训练伪代码

下面是按论文 Appendix B 的 `dpo_loss` 改写的**简化示意，不是逐字源码**。变量名保留算法主干，省略了 padding、mask 和分布式数据加载细节。

```python
# x, yw, yl：一批 prompt、winner、loser
# pi：可训练 policy；ref：冻结 reference
# beta：KL 约束强度

pi_w = sum_token_logprob(pi, x, yw)       # teacher forcing
pi_l = sum_token_logprob(pi, x, yl)
ref_w = sum_token_logprob(ref, x, yw)     # 不反向
ref_l = sum_token_logprob(ref, x, yl)

winner_margin = (pi_w - ref_w) - (pi_l - ref_l)
loss = -log_sigmoid(beta * winner_margin)

loss.backward()                           # 只更新 pi
optimizer.step()
```

这段流程的因果顺序是：

1. **同一条 pair 过两套模型**：policy 负责学习，reference 负责提供固定坐标系。
2. **先做 policy/reference 的 log probability 差**：把绝对概率转成“相对 reference 的偏好变化”。
3. **再做 winner 与 loser 的差**：消掉只依赖 $x$ 的配分函数，形成可比较的 margin。
4. **最后过 sigmoid 和负对数**：把“winner 应该赢”变成一个普通的二元分类损失。
5. **只让 policy 反向**：reference 的权重和 log probability 都固定。

### 4.3 训练时省掉了什么，仍然保留了什么

DPO 在微调循环里省掉的是：

- 当前 policy 逐 token 生成新回答的 on-policy rollout；
- 单独拟合 RM 的训练阶段；
- critic、优势估计和 PPO 裁剪更新；
- 为了维持探索而不断重建样本池的闭环。

它仍然需要：

- 一份可用于比较的 reference policy；
- 一批质量足够高的 chosen/rejected 偏好对；
- policy 和 reference 对这些序列的前向 log probability；
- `beta`、学习率、batch size、长度截断等训练配方。

所以“DPO 不需要采样”要说完整：**DPO 不需要在微调循环里从当前 policy 在线采样；数据集制作阶段仍可能需要采样，评测阶段也仍然可能使用 temperature（温度）和 top-p（累计概率截断）等采样参数。**

## 5. PPO vs DPO：把训练成本和显存账本算清

### 5.1 角色从 4 个变成 2 个

把 12.1 的典型 PPO 角色和 DPO 的角色并排摆出来：

| 维度 | PPO/RLHF 典型回路 | DPO | 账本口径 |
|---|---|---|---|
| 模型角色 | policy + 冻结 reference + RM + critic | 可训练 policy + 冻结 reference | 角色数：4 → 2 |
| 数据来源 | 当前 policy 生成的 on-policy 回答，再打分/标注 | 预先收集的 offline $(x,y_w,y_l)$ | 训练循环不再生成 pair |
| 更新目标 | 奖励、KL、优势估计、裁剪后的 RL 目标 | Bradley–Terry 偏好概率的二元交叉熵 | DPO 直接优化 policy |
| RM | 训练并在线提供奖励 | 训练阶段不需要独立 RM | 不是说偏好数据不需要标注 |
| critic | 估计价值，辅助 PPO 稳定更新 | 不需要 | 去掉价值网络和优势估计 |
| reference | 计算 KL，通常保留 | 计算每条 pair 的 log probability，必须保留 | 冻结不等于免费 |
| 探索 | 当前策略可以发现新回答 | 受固定偏好数据覆盖范围限制 | PPO 换取探索，DPO 换取稳定和成本 |
| 训练稳定性 | 受 rollout 分布、RM 误差和 RL 超参数影响 | 目标是普通分类损失，通常更易实现 | “更稳定”是论文实验结论，不是无条件定理 |

### 5.2 权重和显存的两层账本

先用符号算角色账。设一份完整模型权重占 $M$ 字节：

$$
\begin{aligned}
\text{PPO 角色权重账}&=M_{\pi}+M_{\mathrm{ref}}+M_{\mathrm{RM}}+M_{\mathrm{critic}}+\text{rollout 缓存},\\
\text{DPO 角色权重账}&=M_{\pi_\theta}+M_{\pi_{\mathrm{ref}}}+\text{偏好 pair 的临时激活}。
\end{aligned}
$$

若只是做最粗的同尺寸思想实验，令四个角色都约等于 $M$，则是 $4M$ 对 $2M$。但真实工程不能把“角色数减半”直接翻译成“峰值显存减半”：RM 和 critic 可能更小，PPO 的 rollout 很大；DPO 的 policy 仍要保存梯度和优化器状态，reference 只保存推理权重。

**一个 7B（约 70 亿参数）权重的纸笔账。** 若只看 FP16（16 位浮点数）权重，每个参数 2 字节：

$$
7\times10^9\times2\text{B}=14\text{GB}。
$$

把这个 14 GB 当作 $M$：四个同尺寸角色的权重思想实验是 $4\times14=56$ GB，两个角色是 $2\times14=28$ GB。这个数字是**文章思想实验，不是论文实测峰值**，它只用来说明 4 → 2 的角色账；真正训练还要加 policy 的梯度、优化器状态、激活和 batch。

📌 **关键点**：DPO 的显存收益主要来自**不再同时驻留 RM、critic 和 rollout 回路**，不是一句“policy 还要加一份 reference，所以显存一定减半”。在显存紧张时，先按“模型权重 + 梯度 + 优化器 + 激活 + reference”逐项核算，再决定是否使用参数高效微调或分片。

### 5.3 牺牲了什么，换取了什么

- **DPO 牺牲探索，换取训练闭环更短**：不再让当前 policy 主动去数据分布外试错，换来固定 pair 上的稳定优化。
- **DPO 牺牲一个独立 RM，换取相对 log probability**：模型本身通过 $\beta\ln(\pi_\theta/\pi_{\mathrm{ref}})$ 表示隐式奖励，但也失去了一个可以单独校准、单独评测的分数接口。
- **DPO 牺牲在线适应，换取可复现**：同一份 pair、同一 reference 和同一随机种子更容易做回归；但数据本身若有偏，训练会稳定地放大这种偏差。
- **PPO 牺牲工程简单度，换取探索能力**：当你有大量新 prompt、可靠的在线奖励和足够算力时，on-policy 回路可能值得付费。

落成一句话的选型规则：**偏好数据已经覆盖目标分布、主要瓶颈是训练成本和实现复杂度时先选 DPO；需要在线探索、奖励可验证且数据覆盖不足时，才认真考虑 PPO。**

## 6. 偏好数据工程：DPO 不是没有数据，只是把数据搬到训练前

### 6.1 一条偏好数据是怎样做出来的

DPO 的输入很小，但生产它并不简单。最小流程是：

1. **准备 prompt**：从通用指令、摘要任务、对话任务或目标领域收集 $x$。
2. **得到多个候选回答**：由 SFT/reference 或其他模型生成若干 $y$。
3. **产生偏好信号**：人类或强模型比较回答，选出 $y_w$ 和 $y_l$；也可以按情感、事实性、帮助性等规则自动构造 pair。
4. **做质量过滤和切分**：保留 prompt、winner、loser，记录来源、长度和评测维度，避免训练集和评测集泄漏。
5. **固定 reference 再训练**：如果数据本来由 $\pi^{\mathrm{SFT}}$ 生成，论文建议直接设 $\pi_{\mathrm{ref}}=\pi^{\mathrm{SFT}}$；如果没有 SFT 模型，则可以先在 chosen completion 上做最大似然，把它当作 reference 的近似。

这里要区分两个规模：**候选回答规模**和**最终 preference pair 规模**。四条回答可以产生多条两两比较，但训练表里的一行仍然是一个 $(x,y_w,y_l)$。

### 6.2 UltraFeedback：合成反馈为什么能把数据做大

讲师幻灯片第 24 页把 UltraFeedback（用多模型候选和强模型反馈构造的偏好数据集）简写为 UltraF，并把它归在 Synthetic preference data：不是逐条依赖人工比较，而是用 GPT-4（OpenAI 的大型语言模型，在这里充当合成反馈与评审器）等强模型对同一 prompt 的多个回答做细粒度反馈，再整理为 chosen/rejected pair。它的工程价值是把“人工标注速度”换成“模型调用规模”，同时保留多个维度的分数，而不是只留下一个模糊的胜负标签。

**数字要读对。** 讲师幻灯片 Table 1 给出的 Tülu 2 13B（13B 参数的指令微调模型）DPO 训练口径是 **60,908 条 UltraF preference samples**，不是 60,908 个 prompt，也不是 DPO 原论文的数据规模。表中 UltraF overall 的平均得分为 60.3，fine-grained 版本为 61.0；SFT 基线为 56.8。幻灯片的结论是：带 per-aspect annotations（按多个维度分别评分再综合：幻灯片举例为 helpfulness、harmlessness，底层 Tülu 2 实验实际按 factuality、reasoning、coding、truthfulness、safety、instruction-following 六维）的合成数据表现最好。

这组数字属于讲师幻灯片中的后续工程材料，不能倒写成 DPO 2023 论文的实验结果。它告诉你的不是“GPT-4 永远比人可靠”，而是：**数据规模、候选多样性和标注维度，都是 DPO 成败的一部分。**

### 6.3 RM 规模与 Best-of-N：奖励模型变强，不等于 policy 同比例变强

讲师幻灯片把 RM（奖励模型）实验拆成两个旋钮。RewardBench（检验奖励模型能否正确排序 chosen/rejected 对的基准）和 Best-of-N（每个 prompt 采样 N 条回答、挑分最高者）用来观察这两个旋钮：

- **训练数据规模**：`UltraF. RM` 只用 UltraFeedback；`Mix RM` 混合 UltraFeedback、HelpSteer（帮助性打分数据集）、Nectar（多模型综合偏好数据集）、StackExchange（问答社区爬取的偏好数据）、HH-RLHF（安全对话偏好数据，§7.1 会展开）和 PRM800k（过程监督推理标注数据）等不同来源的偏好或推理数据集。这里列名称是为了对齐讲师表格，不逐个展开各自的数据 schema。
- **模型规模**：比较 13B（约 130 亿参数）和 70B（约 700 亿参数）的 reward model。

Best-of-N（每个 prompt 采样 N 条回答、挑分最高的一条）是一个很容易和 DPO 混淆的基线：它不是训练 policy，而是对每个 prompt 采样 $N$ 个回答，再用 RM 选分最高的一个。$N=16$ 时，推理成本已经变成 16 份候选生成加一次排序；DPO 则把偏好直接写进 policy，推理时不需要同时跑 RM 做筛选。

讲师表给出了一个有用的反直觉账本：

| RM | RewardBench 分数 | Best-of-N 相对 SFT 的平均提升 | PPO 训练平均表现 | 来源口径 |
|---|---:|---:|---:|---|
| 13B UltraF. RM | 61.0 | +5.8 | 62.2 | 讲师幻灯片 Table，引用口径 |
| 13B Mix RM | 79.8 | +7.3 | 61.6 | 讲师幻灯片 Table，引用口径 |
| 70B UltraF. RM | 73.6 | +10.3 | 62.8 | 讲师幻灯片 Table，引用口径 |
| 70B Mix RM | 73.9 | +9.5 | 61.8 | 讲师幻灯片 Table，引用口径 |

**关键点**：RewardBench 分数提高，并不会线性转化成 policy 的下游收益；幻灯片明确提醒，奖励模型的规模和数据变好后，平均 policy 表现只得到有限改善。RM 可以是训练 PPO 或 Best-of-N 的工具，但 DPO 的主线是绕开独立 RM 做 policy 优化，二者不能混成同一个成本模型。

### 6.4 领域 prompt 工程：摘要、对话和情感生成不是一套数据

偏好训练不是只换一个 loss 就结束，prompt 分布会决定 policy 看见什么：

| 领域 | prompt 与候选 | 论文/幻灯片实验口径 | 工程含义 |
|---|---|---|---|
| 情感生成 | IMDb（电影评论数据集）前缀，目标是生成正向续写 | 论文 §6：用情感分类器构造偏好；GPT-2-large（GPT-2 的大规模版本）做 SFT | 标签相对清晰，适合验证 reward/KL frontier |
| 摘要 | Reddit TL;DR 论坛帖子，目标是摘要 | 论文 §6.2：GPT-J（开源自回归语言模型）SFT；GPT-4 评估与 reference summary 比较 | 要同时控制信息覆盖和简洁性，温度会影响胜率 |
| 单轮对话 | 用户问题与一轮回答 | 论文 §6.2：Anthropic Helpful and Harmless（帮助且无害）数据，Pythia-2.8B（约 28 亿参数的开源语言模型）作为起点 | “有帮助”更开放，候选覆盖和评审 prompt 更重要 |
| 数学/代码扩展 | 讲师材料中的 GSM8K（小学数学文字题评测集，幻灯片简写为 GSM）数学题、代码 prompt 或混合 prompt | 讲师幻灯片 33–34：20 个 UltraFeedback prompt、Mined Math、GSM train、Mixed | 领域 prompt 要和评测目标对齐，不能拿通用对话数据替代 |

讲师材料还给出一个边界：使用更大、更多数据训练的 RM 时，直接使用领域内 prompt（例如来自 GSM train 的数学题）更容易获得收益；较弱 RM 更难跳出训练 prompt 的分布。这里的“领域 prompt 工程”本质是让训练时的偏好监督覆盖你真正关心的输入分布。

### 6.5 原论文配方：把可复现实验参数留下

论文 Appendix B 给出了可复现的默认值：$\beta=0.1$、batch size（一次更新读入的偏好 pair 数）为 64、RMSprop 优化器（用梯度平方的滑动平均调节步长）、学习率 $10^{-6}$，学习率线性 warmup 150 steps；TL;DR 摘要使用 $\beta=0.5$。这些是论文实验设置，不是所有模型的通用推荐。

论文的采样评测还扫描了 temperature（温度，控制分布尖锐程度）0.0 到 1.0。站内 [8.5 采样与解码算法](/AIInfraGuide/inference/模块四-推理优化/第8章-生产级服务特性/85-采样与解码算法)——该文定义 temperature、top-k（只保留概率最高的 k 个 token）、top-p（保留累计概率达到 p 的候选）、logprobs（记录 token 的对数概率）、`n`（并行生成的回答数）和 beam search（保留多条候选路径的搜索），并用 $p_i=e^{z_i/T}/\sum_j e^{z_j/T}$ 计算采样分布；本篇只在复现实验和解释“胜率随温度变化”时引用它，不重复展开采样器实现。

如果你要做 DPO 的 A/B 测试（让两套设置在相同条件下对照），至少固定：偏好数据版本、reference checkpoint（保存的一组参考模型权重）、$\beta$、训练步数、随机种子、评测 prompt 集、temperature 和评审模型。否则你看到的“DPO 赢了”可能只是采样温度或评测 prompt 变了。

## 7. 实验：论文到底赢在哪里，边界在哪里

### 7.1 三组任务和比较对象

论文用三种开放式文本生成任务测试 DPO：

- **情感生成**：IMDb 电影评论前缀，正向情感分类器提供可控的 ground-truth reward。这里 ground-truth 指实验者已知的真实评测函数，不是人工偏好模型。
- **摘要**：Reddit TL;DR，使用 GPT-J 的 SFT 模型，GPT-4 判断生成摘要与 reference summary 的胜负。
- **单轮对话**：Anthropic Helpful and Harmless（帮助且无害）数据集，使用 Pythia-2.8B，GPT-4 判断回答是否更有帮助。

比较对象包括 SFT、Preferred-FT（只在 chosen completion 上做监督微调）、PPO、PPO-GT（情感实验中直接使用真实 reward 的 PPO）和 Best-of-N。论文的核心比较不是“DPO 在所有指标都第一”，而是：**在相同偏好目标和相近 KL 约束下，DPO 能用更简单的训练过程达到 PPO 相当或更好的结果。**

### 7.4 论文结论和工程推断要分开

> **论文结论**：DPO 在情感生成、摘要和单轮对话上表现为与 PPO 相当或更好；它用几乎不需要调参的简单交叉熵目标，降低了从偏好训练语言模型的门槛。论文实验模型最大到 6B（约 60 亿参数）。

> **工程推断**：DPO 更适合“目标分布已有高质量偏好对”的场景；如果生产流量不断出现新任务，DPO 不会像 on-policy PPO 那样主动收集新区域的反馈。你需要增加 prompt 覆盖、重做偏好数据，或保留在线优化通道。

> **论文边界**：论文没有证明 DPO 在任意规模、任意偏好标注器、任意分布外任务上都优于 PPO；它还指出 GPT-4 评审结果会受评审 prompt 影响，未来需要更系统的评估研究。

## 8. 错误做法与边界：为什么“抬高 chosen 概率”不等于 DPO

### 8.1 只在 chosen 上做 SFT

❌ **看起来合理但不完整**：只最大化 $\ln\pi_\theta(y_w\mid x)$，完全不看 $y_l$ 和 reference。

问题在于它没有回答“winner 比 loser 好多少”，也没有控制 policy 相对于 reference 的偏移。一个模型可以同时把 winner 和 loser 的概率都抬高，只要 winner 还略高，chosen-only SFT 就会认为自己在进步。

✅ **正确做法**：计算两条回答相对 reference 的 log probability，再取 winner margin；DPO 的动态权重会优先修正当前排序错误的 pair。

### 8.2 以为“没有 RM”就不需要 reference

❌ **常见误读**：DPO 删除了显式 RM，于是只加载一份 policy。

问题在于 $\pi_{\mathrm{ref}}$ 出现在每个 log ratio 里。没有 reference，就没有“相对偏好”也没有 KL 锚点；你退化成了另一个 chosen/rejected 损失，而不是论文 Eq. 7 的 DPO。

✅ **正确做法**：加载一份冻结 reference，缓存或计算它对 winner/loser 的 sequence log probabilities，反向时只更新 policy。

### 8.3 把离线数据当成无限探索

❌ **错误推断**：DPO 训练很稳定，所以它会自动发现数据集中没有的更好回答。

DPO 只在已有 pair 上获得直接偏好梯度。若目标流量从 Reddit 摘要变成金融客服、代码修复或长链数学题，而训练数据没有覆盖这些输入和失败模式，policy 的分布外行为只能靠泛化猜测。

✅ **正确做法**：把 prompt 覆盖、候选回答多样性和评审一致性当作训练资源；定期用目标流量做离线评测，再补采样和标注。若确实需要当前 policy 的在线探索，DPO 不是自动替代 PPO 的万能开关。

### 8.4 符号方向写反

❌ **错误实现**：把 $y_l$ 放在前面，使用
$\sigma(\hat r_\theta(y_l)-\hat r_\theta(y_w))$，却仍然把标签当成“winner=1”。

最小反例：若 winner 比值为 2、loser 比值为 0.5，正确 margin 是 $\ln4>0$，预测 winner 概率约 0.8；符号反过来后 margin 是 $-\ln4$，预测概率约 0.2，训练会把正确 pair 越推越反。

✅ **正确做法**：固定约定：$y_w$ 是偏好回答，$y_l$ 是非偏好回答，loss 使用
$-\ln\sigma(\beta[\ln ratio_w-\ln ratio_l])$。

### 8.5 忽略 reference 的支持集和 $\beta$

论文 Appendix A.6 的定理假设 $\pi_{\mathrm{ref}}(y\mid x)>0$，且 $\beta>0$。工程上若 reference 对某条序列的概率在数值上变成 0，log ratio 会出现无穷；若 $\beta$ 过小，模型可能为了拟合 pair 过度偏离 reference；若过大，偏好信号又可能被压平。

这不是“把 beta 调到越小越强”的单调竞赛。论文默认 $\beta=0.1$，TL;DR 使用 $0.5$；换模型、换数据、换长度后都要重新做验证。至少记录训练损失、chosen/rejected 的 log ratio、KL 近似值、长度分布和目标任务胜率。

## 📝 总结

1. **问题**：RLHF/PPO 的典型训练回路要维护 policy、reference、RM、critic，反复做 on-policy 采样，成本高且容易受到 RM 误差和 RL 超参数影响。
2. **Step 1**：KL 约束下的最优策略是 $\pi^*(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)e^{r(x,y)/\beta}$；reference 提供底座，奖励提供指数倾斜。
3. **Step 2**：奖励可以写成 $r=\beta\ln(\pi^*/\pi_{\mathrm{ref}})+\beta\ln Z(x)$；同一个 prompt 的 winner 和 loser 共享 $Z(x)$，所以 Bradley–Terry 的奖励差会把它消掉。
4. **Step 3**：把理想策略换成可训练 policy，就得到 DPO 二元交叉熵；它直接提高 winner 相对 reference 的概率、降低 loser 的相对概率。
5. **工程账本**：DPO 把典型角色从 4 个压到 policy + 冻结 reference 2 个，去掉 RM、critic 和训练循环中的在线 rollout，但 reference、偏好数据和优化器状态仍然要付费。
6. **数据边界**：UltraFeedback 说明合成、细粒度、多领域偏好数据可以做大；Best-of-N 和 RM 实验同时提醒，奖励模型变强不等于 policy 下游收益线性变强。
7. **适用规则**：偏好数据已覆盖目标分布时，DPO 是简单、稳定、成本友好的首选；需要在线探索或面对大量分布外输入时，不能把 DPO 当成 PPO 的无条件替代。
