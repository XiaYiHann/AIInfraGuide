InstructGPT 的关键不是把 GPT-3（论文中的预训练生成式语言模型）再做大，而是把目标从“猜网页里的下一个 token”改成“按人类偏好完成指令”：论文报告 1.3B（约 13 亿参数）InstructGPT 在人工评测中优于 175B（约 1750 亿参数）GPT-3，且 175B InstructGPT 相对 175B GPT-3 的偏好胜率为 $85\pm3\%$。代价也很具体：训练从一个模型读固定数据，变成监督微调、奖励模型和 PPO（Proximal Policy Optimization，近端策略优化，一种限制每次策略更新幅度的强化学习算法）三段流水线；PPO 还要反复在线采样，并维护负责生成的策略模型、冻结的参考模型、负责打分的奖励模型和负责估值的评论家模型四类角色。

这里的 InstructGPT 指论文在 GPT-3 上做了人类反馈微调后的模型。先把数字口径钉住：论文对“1.3B InstructGPT vs 175B GPT-3”给出的是人工偏好上的胜负结论，没有在正文给出这一对比较的单独百分比；$85\pm3\%$ 是 175B InstructGPT 对 175B GPT-3 的直接比较，另一个 $71\pm4\%$ 是对 few-shot（给模型附带少量示例的提示方式）175B GPT-3 的比较（论文 §1、Figure 1）。

## 0. 读前 3 分钟：先把术语和符号放在桌上

如果把一篇语言模型论文直接塞满 `policy`、`reward`、`logprob` 和 `KL`，读者很容易在第二个公式前迷路。先用一句白话固定角色，后面所有公式都沿用这张表。

| 术语 | 白话定义 | 本文中的作用 |
|---|---|---|
| **token** | 模型读写文本时使用的最小片段，可能是一个汉字、一个词或半个词 | 生成回答时，每一步选择一个 token |
| **prompt / response** | `prompt` 是用户给模型的输入，`response` 是模型生成的回答 | 记作 $x$ 与 $y$ |
| **RLHF** | Reinforcement Learning from Human Feedback，即把人的示范和偏好转成训练信号，再用强化学习更新模型 | 论文的总流程 |
| **SFT** | Supervised Fine-Tuning，有标准答案示范时，逐 token 学习“应该怎样写” | 第一阶段，得到初始策略 |
| **RL** | Reinforcement Learning，强化学习；模型通过动作、回报和策略更新来改进 | 第三阶段的更新方式 |
| **preference** | 人在两个或多个回答之间表达的“我更喜欢哪个” | 第二阶段的监督信号 |
| **reward model（奖励模型，RM）** | 输入 prompt 和 response，输出一个标量分数，分数越高表示模型估计的人类偏好越强 | 把文字偏好变成 PPO 能使用的数值 |
| **policy（策略）** | 当前负责生成回答的模型，也就是“看到输入后怎样选下一个 token 的规则” | PPO 要更新的对象，记作 $\pi_\phi$ |
| **reference model（参考模型）** | 冻结的 SFT 模型副本，用来测量当前 policy 偏离初始能力有多远 | KL 惩罚的锚点，记作 $\pi^{\mathrm{SFT}}$ |
| **critic / value function（评论家 / 价值函数）** | 预测“从当前状态继续走下去大概能拿多少回报”的模型 | 帮 PPO 判断某一步动作是否比预期好 |
| **logprob** | 模型给某个 token 的概率取自然对数；例如概率 $0.5$ 的 logprob 是 $\log 0.5$ | 计算 SFT 损失、KL 惩罚和 PPO 概率比 |
| **KL** | Kullback–Leibler divergence，比较两个概率分布差异的非负指标；这里用来惩罚 policy 远离 reference | 防止模型只追逐奖励模型漏洞 |
| **on-policy** | 用“当前 policy 刚刚生成的数据”训练当前 policy，而不是反复使用一份固定旧数据 | 解释 PPO 为什么每轮都要重新采样 |
| **rollout** | 让当前 policy 完整生成一条 response，并把状态、动作、概率和结果记录下来 | PPO 每轮的采样数据 |
| **bandit** | 只有一次完整出手机会的环境；这里一次 prompt-response 就结束一个 episode（一次完整尝试） | InstructGPT 的简化 RL 环境 |
| **batch** | 一次并行送进模型的一组训练样本 | RM 中一个 batch 由多个 prompt 组成，PPO 中一个 batch 由多个 episode 组成 |
| **minibatch** | 把一个 batch 再切成的较小子批次 | PPO 在一轮 rollout 上分批做参数更新 |
| **FP16 / FP32** | 16 位 / 32 位浮点数；位数越高通常越占显存，但能表示更细的数值 | 用于四模型权重和优化器状态估算 |
| **epoch** | 把一份训练数据完整遍历一次 | 解释 SFT、RM 和 PPO 的重复训练次数 |
| **checkpoint** | 训练过程中保存的一份模型状态 | 论文用奖励模型分数选择 SFT checkpoint |
| **Adam** | 用一阶、二阶动量帮助更新参数的优化器 | 计算可训练 policy/critic 的附加状态 |
| **GPU** | 图形处理器；本文指承担模型计算的加速卡 | 说明模型副本和利用率的硬件成本 |
| **B / GB / Bytes** | B 在 7B 中表示 billion（十亿）；GB 是十进制 $10^9$ Bytes，Byte 是字节 | 统一参数量和显存单位 |
| **FLOPs** | 浮点运算次数 | 说明为什么论文数字不足以推出实测训练时间 |
| **LLM** | Large Language Model，大型语言模型 | 本章讨论的模型类型 |

后文还会出现两个符号：$r_\theta(x,y)$ 表示奖励模型给回答的分数，$\sigma(z)=1/(1+e^{-z})$ 是把任意实数压到 $0$ 到 $1$ 之间的 sigmoid 函数。$\binom{K}{2}$ 表示从 $K$ 个回答中任选两个的组合数。

## 1. 为什么 next-token 目标会偏离人类意图

### 1.1 训练目标到底在奖励什么

问题是：一个模型把句子续得很像互联网文字，为什么仍可能答非所问、编造事实或生成有害内容？**因为“下一个 token 可能是什么”和“用户希望模型完成什么”是两道不同的题。**

打个比方：你让学生把一篇网页文章逐字补完，评分标准只看“下一个字像不像原文”。这个学生会越来越擅长模仿文章，却没有被明确要求回答用户问题、拒绝有害请求或检查事实。语言模型预训练的核心目标就是这套“逐字补完”评分。

设文本被切成 $T$ 个 token，$w_{<t}$ 表示第 $t$ 个 token 前面的所有 token，预训练常见的损失可以写成：

$$
L_{\text{next}}(\theta)=\underbrace{-\sum_{t=1}^{T}\log p_\theta(w_t\mid w_{<t})}_{\text{让真实的下一个 token 概率变大}}
$$

- $p_\theta(w_t\mid w_{<t})$：参数为 $\theta$ 的模型，在已有前缀下给真实 token 的概率。
- $\log$：把连续相乘的概率变成相加的分数，方便训练。
- 负号：最大化真实 token 的 logprob，等价于最小化损失。

**数值走查：**如果一句三 token 的答案中，模型给真实 token 的概率分别是 $0.8$、$0.5$、$0.9$，那么这段损失是：

$$
L_{\text{next}}=-(\log0.8+\log0.5+\log0.9)\approx0.916
$$

这个数字只回答“真实续写的概率有多大”。它没有额外的一项去检查“是否遵守了只写两段”“是否指出了错误前提”“是否编造了输入没有给出的事实”。这不是 next-token 目标“算错了”，而是**训练标签没有承载这些行为要求**。

### 1.2 论文观察到的三类错位

论文 §1 把问题说得很直接：大模型可能生成不真实、带偏见或有毒的文本，也可能根本不按用户指令做。把它翻译成工程问题，就是下面三种目标缺口。

| 训练目标没有明确约束的事情 | 模型可能出现的行为 | 论文证据 |
|---|---|---|
| **帮助用户完成任务** | 不按指令回答，或者只会继续写看似流畅的文字 | §1；§4.1 的“attempts correct instruction”与“follows explicit constraints”评测 |
| **保持事实真实** | `hallucination`（幻觉，即编造输入没有提供或现实中不存在的事实） | §1；闭域任务的幻觉率为 21% vs 41%（InstructGPT vs GPT-3） |
| **避免伤害性输出** | 生成带毒性、偏见或其他有害内容 | §1、§4.2；尊重提示下毒性输出约减少 25%，但偏见指标没有显著改善 |

这里的“对齐”不是一句抽象口号。论文把它具体化为：模型要尽可能 helpful（帮用户完成任务）、truthful（陈述事实而非编造）和 harmless（不造成伤害）。但这些目标很难直接写成一个“正确 token”，所以作者先收集人类示范，再收集人类对多个回答的比较。

📌 **关键点**：预训练解决的是“从互联网文字中学会语言”，RLHF 试图补上“在具体用户意图下，哪个回答更值得被选中”。后者需要一个新的监督接口：不是唯一答案，而是偏好排序。

## 2. 一句话核心思想：把偏好变成可优化的奖励

能不能直接让人类每次 PPO 更新都站在旁边打分？**成本太高，所以 RLHF 把人的判断压缩成一个可重复调用的奖励模型。**

生活中的对应关系很简单：

- 人类示范像“老师先写几份标准答案”。
- 人类比较像“老师看几份草稿后说 A 比 B 好”。
- 奖励模型像“把老师的评分习惯学会的自动阅卷器”。
- PPO 像“让学生反复写新答案，自动阅卷器打分，再按分数调整写法”。

用技术语言重述，InstructGPT 的主线是：

1. **SFT**：用人类写的 `(prompt, response)` 示范，把预训练模型初始化成更会遵守指令的 policy。
2. **奖励模型**：对同一个 prompt 生成 $K$ 条 response，由人类排序；奖励模型学习“哪一条更可能被偏好”。
3. **PPO**：让 policy 自己在线生成 response，奖励模型给出标量 reward，再用 PPO 更新 policy；同时用 reference 的 KL 惩罚限制漂移。

论文从这些来源构造三份数据：SFT 训练约 13k 个 prompt，奖励模型训练约 33k 个 prompt，PPO 使用约 31k 个 prompt。注意这里统计的是 prompt 数，不是奖励模型展开后的成对比较数；一个 prompt 的 $K$ 条回答会产生最多 $\binom{K}{2}$ 个比较（论文 §3.2、Table 6、Appendix A.3）。

## 3. 三阶段流水线：SFT → 奖励模型 → PPO

### 3.1 第一段：SFT 先学会“像示范一样回答”

为什么不直接从预训练模型开始 PPO？**因为 PPO 需要一个已经会基本遵守指令的起点，否则奖励模型还没来得及纠偏，policy 就可能在巨大的输出空间里乱走。**

SFT（监督微调）阶段给模型一组人类示范。对 prompt $x$，人类写出 response $y=(y_1,\ldots,y_T)$。模型逐 token 学习这条示范：

$$
L_{\text{SFT}}(\phi)=\underbrace{-\sum_{t=1}^{T}\log\pi_\phi(y_t\mid x,y_{<t})}_{\text{提高示范中每个 token 的概率}}
$$

- $\pi_\phi$：参数为 $\phi$ 的生成 policy。
- $y_{<t}$：response 中第 $t$ 个 token 之前已经写出的部分。
- 这个损失把一条完整回答拆成多个“下一个 token”任务，但训练数据已经由人类把意图写进了示范。

**数值走查：**如果示范回答只有三个 token，模型当前给它们的条件概率是 $0.8$、$0.5$、$0.9$，SFT 损失同样约为 $0.916$。把这个损失降下来，意味着模型更愿意沿着这条人类示范生成；但它仍然没有看到“另一条回答为什么更差”。

这就是 SFT 的边界：它擅长行为克隆，却不直接表达多个可接受答案之间的相对优劣。一个问题可能有十条都不错的回答，人类没有必要只写出唯一标准答案；偏好数据正好补上这部分信息。

论文里有两个容易混淆的训练配置：

- **通用 SFT 模型**：§3.5 报告训练 16 个 epoch，并用奖励模型分数选择最终 checkpoint。
- **作为 RLHF 初始化的模型**：Appendix C.3 报告在示范数据上训练 2 个 epoch，同时混入 10% 预训练数据，目的是让后续 PPO 更稳定。

它们服务的实验目的不同，不能把两个数字拼成一条“所有 SFT 都训练 16 个 epoch”的规则。

### 3.2 第二段：奖励模型把回答压成一个分数

人类比较的是“回答 A 比回答 B 好”，PPO 需要的是一个可计算的数。**奖励模型（reward model，下面简称 RM）就是一个输入 `(x,y)`、输出标量 $r_\theta(x,y)$ 的模型。**

论文的实现从 SFT 模型出发，去掉最终把隐藏表示映射回词表的 unembedding 层（把隐藏表示映射成候选 token 分数的输出层），换成输出一个标量的投影层。这里的标量不是事实真值，也不是“回答绝对优秀”的分数，而是模型对人类偏好的近似。

假设一个 prompt $x$ 有四条回答：

- $y_1$：准确、完整、遵守约束；
- $y_2$：内容基本对，但漏掉约束；
- $y_3$：语言流畅，但编造了事实；
- $y_4$：答非所问。

标注者可能给出 $y_1\succ y_2\succ y_3\succ y_4$。奖励模型训练时不会被要求输出“$y_1$ 是 7.2 分”；它只需要学到一个排序趋势：$r_\theta(x,y_1)>r_\theta(x,y_2)>r_\theta(x,y_3)>r_\theta(x,y_4)$。

### 3.3 Bradley-Terry：从分数差得到偏好概率

问题是：如何把“$y_w$ 比 $y_l$ 好”写成损失函数？**Bradley-Terry 模型用两个回答的分数差表示偏好强度，再用 sigmoid 把它变成概率。**

在这里，$y_w$ 是人类偏好的回答，$y_l$ 是被排在后面的回答。Bradley-Terry 的概率模型为：

$$
P(y_w\succ y_l\mid x)=\underbrace{\sigma\left(\underbrace{r_\theta(x,y_w)-r_\theta(x,y_l)}_{\text{奖励分数差}}
\right)}_{\text{预测“偏好回答”的概率}}
$$

分数差越大，预测概率越接近 1；分数相等时，概率是 $0.5$。论文 Equation 1 的交叉熵损失是：

$$
L_{\text{RM}}(\theta)=\underbrace{-\frac{1}{\binom{K}{2}}}_{\text{同一 prompt 的成对比较取平均}}
\mathbb{E}_{(x,y_w,y_l)\sim D}
\left[\underbrace{\log\sigma\left(r_\theta(x,y_w)-r_\theta(x,y_l)\right)}_{\text{希望人类偏好的回答概率更高}}
\right]
$$

每个符号对应一个动作：

- $r_\theta(x,y)$：奖励模型对 prompt $x$ 和 response $y$ 的标量输出。
- $D$：人类比较数据集，每个样本记录 prompt、winner（人类偏好的回答）和 loser（被排在后面的回答）。
- $\mathbb{E}$：对数据集中的比较样本取平均。
- $\binom{K}{2}$：同一个 prompt 的 $K$ 条回答产生的成对比较数；除以它是为了对这些比较取平均。
- 负号：把“最大化偏好概率”写成常见的“最小化损失”。

**最小数值走查：同一个 prompt 只有两条回答。**设奖励模型给偏好回答 $y_w$ 打分 $1$，给 $y_l$ 打分 $0$：

$$
\Delta r=1-0=1，\qquad P(y_w\succ y_l)=\sigma(1)\approx0.731，\qquad L=-\log(0.731)\approx0.313
$$

如果分数顺序反过来，$\Delta r=-1$，偏好概率变为 $\sigma(-1)\approx0.269$，损失变成约 $1.313$。因此梯度会推动 winner 与 loser 的分数差扩大。

这里还有一个重要边界：**奖励分数的绝对零点没有意义。**如果给所有回答的分数都加同一个常数 $c$，差值变成：

$$
(r_\theta(x,y_w)+c)-(r_\theta(x,y_l)+c)=r_\theta(x,y_w)-r_\theta(x,y_l)
$$

偏好概率与损失完全不变。论文因此在进入 RL 前用一个 bias 把标注示范的平均奖励归一到 0；这是校准分数零点，不是增加了新的偏好信息。

### 3.4 为什么同一 prompt 的 K 条回答要放在同一批

为什么不把所有 pair（成对偏好比较样本）打散后全局随机洗牌？**因为同一个 prompt 的比较高度相关；打散后，模型会在一次 epoch 里反复看到同一组回答，容易把这组样本记住，而不是学到可泛化的偏好。**

论文让标注者一次看 $K=4$ 到 $K=9$ 条回答并排序。组合数是：

$$
\binom{K}{2}=\frac{K(K-1)}{2}
$$

代入两个小数字：

| $K$ | 成对比较数 $\binom{K}{2}$ | 论文含义 |
|---:|---:|---|
| 4 | $4\times3/2=6$ | 一个 prompt 产生 6 个 pair |
| 9 | $9\times8/2=36$ | 一个 prompt 产生 36 个 pair |
| 64 个 prompt、$K=9$ | $64\times36=2304$ | 论文 Appendix C.2 给出的单批最多比较数 |

正确的 batch 组织方式不是“只取一个 pair”，而是：

1. 对一个 prompt 的 $K$ 条 response 各做一次奖励模型前向，得到 $K$ 个分数。
2. 在这 $K$ 个分数上计算全部 $\binom{K}{2}$ 个 pair loss。
3. 把这个 prompt 的全部 pair 作为一个 batch element，再与其他 prompt 一起组成 batch。
4. 下一次更新切换到其他 prompt，而不是把同一 prompt 的 pair 拆成许多独立样本反复更新。

这样做有两笔收益：

- **计算更省**：先得到 $K$ 个分数，再复用它们计算所有 pair，而不是每个 pair 都重新跑一次奖励模型。
- **统计更稳**：同一 prompt 的相关比较在一次聚合梯度中出现，减少单个 prompt 在一个 epoch 内制造多次更新的机会。

论文明确报告：如果把比较全局打散，单次遍历数据就会让奖励模型过拟合；把同一 prompt 的全部比较作为一个 batch element 后，验证准确率和 log loss 都明显改善（§3.5）。

### 3.5 第三段：PPO 用奖励更新策略

奖励模型已经能给回答打分，为什么不直接把分数当作监督标签？**因为回答是 policy 自己生成的，训练需要解决“哪些生成动作导致了高回报，以及怎样更新概率分布”的问题，这正是强化学习的任务。**

PPO 阶段从 SFT policy 开始：

- 输入一个 prompt $x$。
- policy 生成完整 response $y$。
- 奖励模型输出 $r_\theta(x,y)$。
- critic 估计每个生成状态的价值，帮助计算 advantage（优势值，即实际回报相对 critic 预测值的差）。
- PPO 用奖励和 advantage 调整 policy，但限制一次更新不要改变太多。

InstructGPT 把每个 prompt-response 过程写成一个很短的 bandit 环境：环境给一个随机 prompt，模型给出一个 response，episode（一次完整的 prompt → response 尝试）立即结束（论文 §3.5）。这里的“bandit”可以理解成只有一次出手机会的试题，不需要像游戏那样走很多环境状态；但 response 内部仍然由多个 token 动作组成。

## 4. PPO 训练回路：一轮更新究竟做了什么

### 4.1 把语言生成改写成强化学习

在语言生成里，强化学习的“状态”和“动作”并不神秘：**状态是 prompt 加已经生成的前缀，动作是下一个 token。**

设第 $t$ 步的状态与动作是：

$$
s_t=(x,y_{<t}),\qquad a_t=y_t
$$

policy 给动作的概率是 $\pi_\phi(a_t\mid s_t)$。critic 给状态一个价值估计 $V_\psi(s_t)$，表示“从这里继续生成，预期还能拿到多少回报”。为了说明 PPO 在做什么，可以先用最简单的 advantage 近似：

$$
A_t=\underbrace{R_t}_{\text{这次轨迹实际得到的回报}}-\underbrace{V_\psi(s_t)}_{\text{critic 原来预测的回报}}
$$

- $A_t>0$：这一步比 critic 预期更好，应该提高它的概率。
- $A_t<0$：这一步比预期差，应该降低它的概率。
- 工程实现可以用 generalized advantage estimation（一种结合多步回报的优势值估计方法）等更细的估计；本文只用这个式子建立输入到输出的直觉。

PPO 还要比较“更新前后，这个动作的概率改变了多少”。rollout（让当前 policy 完整生成一条 response 并记录轨迹）完成后，设 $\pi_{\text{old}}$ 是采样这批 rollout 时保存的旧 policy，概率比为：

$$
\rho_t(\phi)=\frac{\pi_\phi(a_t\mid s_t)}{\pi_{\text{old}}(a_t\mid s_t)}
$$

PPO 的 clipped surrogate（裁剪后的目标函数）可以写成：

$$
L_{\text{clip}}(\phi)=\mathbb{E}_t\left[\min\left(\rho_t A_t,
\operatorname{clip}(\rho_t,1-\varepsilon,1+\varepsilon)A_t\right)\right]
$$

这个式子做两件事：如果新 policy 只小幅改变，使用真实的概率比；如果改变超过 $\varepsilon$，就把比例截在区间 $[1-\varepsilon,1+\varepsilon]$ 内。这里的 $\mathbb{E}_t$ 表示对采样轨迹中的时间步取平均，$\operatorname{clip}$ 表示把数截进指定区间；论文 Appendix C.4 的 PPO clip ratio 是 $\varepsilon=0.2$。

**数值走查：**假设旧 policy 给某 token 的概率是 $0.2$，更新后是 $0.24$，且 $A_t=0.5$：

$$
\rho_t=0.24/0.2=1.2，\qquad \rho_t A_t=1.2\times0.5=0.6
$$

它刚好在 $1+\varepsilon=1.2$ 的边界上，不需要额外截断。如果更新后概率变成 $0.4$，则 $\rho_t=2$，未截断的贡献是 $1.0$，截断后的贡献是 $1.2\times0.5=0.6$，取两者较小值后，PPO 不允许这次样本用一个过大的比例主导更新。

这里要区分两个“旧模型”概念：

- **old policy**：为了计算 PPO 概率比，保存的是本轮 rollout 采样时的旧策略概率；它控制“一次 update 走多远”。
- **reference model**：冻结的 SFT 副本；它控制 RL policy 相对“有用的初始行为”漂移多远。

它们的作用不同，不能把 `old policy` 和 `reference` 合并成一个概念。

### 4.2 KL 惩罚：为什么必须保留 reference 副本

只最大化奖励模型分数会发生什么？**policy 可能学会钻奖励模型的漏洞：输出某种奖励模型偏爱的模式，却不再像一个可靠的指令模型。**

论文 Equation 2 的 PPO 目标是下面这个式子。论文把加入预训练分布梯度的变体称为 PPO-ptx（在 PPO 更新中混入预训练数据梯度的 PPO 变体）：

$$
\begin{aligned}
J(\phi)=&\;\mathbb{E}_{(x,y)\sim D_{\pi_\phi^{\mathrm{RL}}}}
\left[\underbrace{r_\theta(x,y)}_{\text{奖励模型分数}}
-\underbrace{\beta\log\frac{\pi_\phi^{\mathrm{RL}}(y\mid x)}{\pi^{\mathrm{SFT}}(y\mid x)}}_{\text{相对 SFT 的 KL 型漂移惩罚}}
\right]\\
&+\underbrace{\gamma\mathbb{E}_{x\sim D_{\text{pretrain}}}
\left[\log\pi_\phi^{\mathrm{RL}}(x)\right]}_{\text{PPO-ptx 才加入的预训练分布项}}
\end{aligned}
$$

其中，$\pi_\phi^{\mathrm{RL}}$ 是正在学习的 policy，$D_{\pi_\phi^{\mathrm{RL}}}$ 是当前 policy 产生 rollout 的分布，$\pi^{\mathrm{SFT}}$ 是冻结的 SFT reference，$D_{\text{pretrain}}$ 是预训练数据分布，$\beta$ 控制 KL 惩罚强度，$\gamma$ 控制预训练分布项强度；论文的普通 PPO 令 $\gamma=0$，PPO-ptx 才保留该项。

论文对第一行的 KL 项按 token 实现。把 response 写成 $T$ 个 token，可以看到它的样子：

$$
R_{\text{total}}(x,y)=r_\theta(x,y)-\beta\sum_{t=1}^{T}
\underbrace{\left[\log\pi_\phi(y_t\mid x,y_{<t})-\log\pi^{\mathrm{SFT}}(y_t\mid x,y_{<t})\right]}_{\text{该 token 的 logprob 差}}
$$

直觉是“回答得好”与“别离开 SFT 太远”同时计分。严格地说，KL 是对整个概率分布取期望后的差异；在一条 policy 已采样的轨迹上，工程实现用 logprob 差作为可计算的逐 token 奖励信号。

**数值走查：**论文默认 $\beta=0.02$。假设一个三 token response 中，policy/reference 的概率比分别都是 $1.5$，则漂移项为：

$$
\text{penalty}=0.02\times3\log(1.5)\approx0.0243
$$

如果奖励模型给出 $r_\theta=2.0$，这一条轨迹的净奖励约为 $2.0-0.0243=1.9757$。奖励变高可以继续推动 policy，但每一步偏离 reference 都会付费。

为什么必须是“副本”？因为惩罚需要一个不跟着 policy 移动的坐标系：

- 如果直接拿 policy 自己和自己比，$\pi_\phi/\pi_\phi=1$，log ratio 永远是 0，KL 项失去作用。
- 如果 reference 每次跟 policy 一起更新，坐标系也在移动，policy 可能不断漂移，却始终看起来只偏离一点点。
- 固定 SFT 副本后，所有 PPO 迭代都相对于同一个起点计量漂移。

这就是“reference 多占一份显存”的根本原因：它不是为了再生成一份答案，而是为了提供固定的比较基准。

### 4.3 PPO 的裁剪：为什么不能一步走太远

KL 已经在惩罚漂移，为什么还要 PPO clip？**两者管的是不同时间尺度的风险：KL 管 policy 相对 SFT 的累计偏离，clip 管单个 rollout batch 内一次更新相对 old policy 的跳步幅度。**

可以把它们放进同一张坐标图：

| 约束 | 比较对象 | 防止的事情 | 论文/算法中的位置 |
|---|---|---|---|
| PPO clip | 当前 policy vs 本轮 rollout 的 old policy | 一个 batch 让概率突然改变太多 | PPO surrogate，论文 Appendix C.4 报告 $0.2$ |
| KL penalty | 当前 policy vs 冻结 SFT reference | 多轮更新后逐渐偏离初始能力 | InstructGPT Equation 2，$\beta=0.02$ |
| critic | 实际回报 vs 价值预测 | advantage 估计噪声过大 | value function，论文 §3.5/Appendix C.4 |

换句话说，clip 像给方向盘加“单次转角限幅”，KL 像在地图上画一条“不能离起点太远”的护栏。只放其中一个，另一种风险仍然存在。

### 4.4 从 rollout 到更新：在线循环

这张图讲的是一次 PPO 迭代的真实数据流：先由当前 policy 生成数据，再由三个辅助角色打分，最后更新 policy 和 critic；旧 rollout 用完后，下一轮重新生成。

<img src="/AIInfraGuide/images/rlhf-ppo-loop.svg" alt="PPO 训练回路：policy 生成 rollout，reference、奖励模型和 critic 打分，合成奖励后更新 policy 与 critic，再重新采样" style="max-width: 100%; display: block; margin: 0 auto;" />

*图：本文根据 InstructGPT §3.5、Appendix C.4 与讲师幻灯片绘制；图中把论文文字压缩成一条工程数据流。*

一轮循环可以拆成六步：

1. **抽 prompt**：从 PPO prompt 分布取一个或一批 $x$。
2. **policy rollout**：当前 policy 逐 token 解码，得到 $y$，同时保存每个动作的 logprob。
3. **三路前向**：reference 计算 SFT logprob，奖励模型计算 $r_\theta(x,y)$，critic 计算 $V_\psi(s_t)$。
4. **合成信号**：用奖励模型分数减去逐 token 的 KL 惩罚，再计算 advantage。
5. **PPO 更新**：把本轮 batch 切成 minibatch，按裁剪后的目标函数更新 policy，并拟合 critic。
6. **丢弃旧 rollout**：下一轮由更新后的 policy 重新采样，而不是把旧数据当成永远有效的离线数据。

论文 Appendix C.4 给了很具体的运行配置：

| 项目 | 论文设置 | 来源口径 |
|---|---:|---|
| RL episode 数 | 256k | 论文 Appendix C.4 |
| 唯一 prompt 数 | 约 31k | 论文 Appendix C.4，过滤个人身份信息并按公共前缀去重后 |
| 每轮 batch | 512 个 episode | 论文 Appendix C.4 |
| 每轮 minibatch | 64 个 episode | 论文 Appendix C.4 |
| 每轮 minibatch 数 | $512/64=8$ | 由论文设置计算 |
| 内部 epoch | 1 次 | 论文 Appendix C.4 |
| rollout temperature（采样温度） | 1 | 论文 Appendix C.4 |
| PPO clip ratio | 0.2 | 论文 Appendix C.4 |
| KL 系数 $\beta$ | 0.02 | 论文 Appendix C.4 |
| PPO-ptx 预训练系数 $\gamma$ | 27.8 | 论文 Appendix C.4 |

**采样账的最小算术：**如果每轮都使用满 512 个 episode，那么 rollout batch 数约为：

$$
N_{\text{rollout batches}}=\frac{256000}{512}=500
$$

每轮有 8 个 minibatch，因此至少有 $500\times8=4000$ 次 minibatch 级的 policy/critic 参数更新。论文没有报告平均 response 长度，只报告最大 response 长度为 1k token，所以总生成 token 数只能写成：

$$
N_{\text{generated tokens}}=256000\times\bar{T}\le256000\times1000=256\text{M}
$$

其中 $\bar{T}$ 是平均 response 长度，$256\text{M}$ 是“每条都达到最大长度”的上界，不是论文报告的实测值。每个 rollout batch 的上界是 $512\times1000=512\text{k}$ 个新 token。

论文还报告了 PPO 的实现细节：学习率前 10 次迭代 warmup，从峰值的十分之一开始；使用衰减率 $0.992$ 的权重指数移动平均；估计 generalized advantage 时不使用 discount。这些数字属于 InstructGPT 当时的实验设置，不是 PPO 的通用默认值。

这笔账还没有换算成 FLOPs，因为论文没有给出目标硬件、实际平均长度、模型实现和计算内核利用率。能确定的工程事实是：每一轮都要重新做 policy 的自回归解码，随后至少要做 reference、reward model、critic 的前向评分；旧数据不能像普通离线监督数据那样无限复用。

## 5. 工程代价账本：四模型、在线采样与超参数

### 5.1 四模型副本：先算权重，再算训练状态

为什么 RLHF 比 SFT 贵，不能只回答“PPO 更复杂”？**第一笔硬成本是模型角色从一个增加到四个；第二笔硬成本是其中至少 policy 和 critic 还要保存训练状态。**

先做一个统一的 7B 例子。这里的 7B 表示 $7\times10^9$ 个参数，是工程估算口径，不是 InstructGPT 论文实际使用的模型规模。FP16 每个参数占 2 Bytes，因此：

$$
M_{\text{one copy}}=7\times10^9\times2\text{ Bytes}\approx14\text{ GB}
$$

<img src="/AIInfraGuide/images/rlhf-four-model-ledger.svg" alt="RLHF 四模型副本显存账本：7B FP16 的 policy、reference、reward model、critic 各约 14GB，权重合计约 56GB" style="max-width: 100%; display: block; margin: 0 auto;" />

*图：本文按四模型角色绘制的 7B 权重账本；不是 InstructGPT 论文的硬件实测图。*

| 模型角色 | 参数量 | 权重精度 | 权重账 | 是否训练 | 角色 | 来源口径 |
|---|---:|---|---:|---|---|---|
| policy | 7B | FP16 | $7\text{B}\times2\text{B}=14$ GB | 是 | 生成 response，接受 PPO 更新 | 本文统一示意 |
| reference | 7B | FP16 | 14 GB | 否 | 冻结的 SFT 副本，提供 KL 锚点 | 本文统一示意 |
| reward model | 7B | FP16 | 14 GB | 通常冻结 | 把 `(prompt, response)` 打成标量奖励 | 本文统一示意 |
| critic | 7B | FP16 | 14 GB | 是 | 预测价值，帮助计算 advantage | 本文统一示意 |
| **合计** | **28B 参数副本** | — | **56 GB** | — | **只算权重，不含训练附加状态** | **本文估算** |

论文的实际角色并不是“四个都 7B”：policy 有 1.3B、6B、175B 三种规模，reference 对应 SFT policy，reward model 固定为 6B，value function 也固定为 6B。若用“角色独立驻留”的权重估算看 175B policy，参数副本约为：

$$
175\text{B policy}+175\text{B reference}+6\text{B RM}+6\text{B critic}=362\text{B}
$$

如果四者都以 FP16 权重驻留，静态权重约为 $362\text{B}\times2\text{ Bytes}=724$ GB。这是从论文模型规模推出的工程估算，不是论文报告的显存实测；论文明确报告的是 6B RM/value 选择可以节省计算，175B RM 训练更不稳定（Appendix C.2、C.4）。

接着把可训练副本的 Adam 状态加上。沿用站点常用的混合精度账本，单个可训练副本每参数的简化状态是：

$$
M_{\text{train}}(\Psi)=\underbrace{2\Psi}_{\text{FP16 参数}}
+\underbrace{2\Psi}_{\text{FP16 梯度}}
+\underbrace{4\Psi}_{\text{FP32 主权重}}
+\underbrace{4\Psi+4\Psi}_{\text{Adam 一阶、二阶动量}}
=16\Psi\text{ Bytes}
$$

7B policy 或 critic 单独按这个模型状态口径估算：

$$
16\times7\text{B}=112\text{ GB}
$$

如果 policy 与 critic 都是独立的 Adam 训练副本，而 reference 与 reward model 只保存 FP16 权重，则：

$$
M_{\text{four roles}}=\underbrace{112+112}_{\text{policy + critic 训练状态}}
+\underbrace{14+14}_{\text{reference + RM 权重}}
=252\text{ GB}
$$

这 252 GB 仍然没有算激活、采样过程中的缓存、临时 buffer、通信 buffer 和显存碎片。它的价值不是预测某个框架的精确 `nvidia-smi` 数字，而是让你在设计训练系统时先回答：**四个角色的权重账已经 56 GB，若再给两个角色配完整训练状态，静态模型状态就可能超过 250 GB。**

💡 **回顾：训练显存账本是什么**

训练显存不能只看“参数 × 精度”。以一个 $\Psi$ 参数模型的混合精度 Adam 训练为例，参数、梯度、FP32 主权重和两份 Adam 动量合计约 $16\Psi$ Bytes；7B 模型就是约 112 GB，还没有激活值。模块三 [1.1 分布式训练总论：显存账本与五大并行策略全景](/AIInfraGuide/distributed/模块三-分布式训练/11-分布式训练总论)——该文逐项推导训练状态和五种并行策略；本文保留同一公式，是为了把一个模型的账扩展成 PPO 四个模型角色的账，不把本篇核心推导外包给站外文章。

工程上可以用参数分片、量化、共享底座或分离 rollout 与 update 来降账，但每一种都牺牲了别的东西：分片换来通信，量化换来精度验证，共享换来实现耦合，异步分离换来调度与一致性复杂度。它们不是 InstructGPT 论文的实验结论，本文只把它们作为成本账之后的设计空间。

### 5.2 on-policy 采样：每轮都重新前向和解码

为什么不能把第一轮 PPO 生成的 31k 个 response 保存下来，像 SFT 数据一样训练很多轮？**因为 PPO 的训练分布来自当前 policy；policy 一变，旧 response 对“当前 policy 的概率”和 advantage 的解释就变旧了。**

把 rollout 账写成最小公式。设 PPO 有 $I$ 个迭代，每轮取 $B$ 个 prompt，每个 response 平均生成 $T$ 个 token：

$$
N_{\text{rollout tokens}}=I\times B\times T
$$

每轮至少有四类工作：

| 工作 | 输入 | 是否需要重新做 | 数量关系 | 来源口径 |
|---|---|---|---|---|
| policy rollout | prompt + 当前 policy | 需要 | $B\times T$ 次 token 选择；解码是自回归的 | PPO 机制解释 |
| reference scoring | prompt + response | 需要 | 对 response 做前向，得到 SFT logprob | PPO 机制解释 |
| RM scoring | prompt + response | 需要 | 对 response 做前向，得到一个标量奖励 | PPO 机制解释 |
| critic scoring | 每个生成状态 | 需要 | 对状态做前向，得到 $V_\psi(s_t)$ | PPO 机制解释 |
| PPO 更新 | rollout 与 advantage | 每轮使用一次旧样本 | 论文每轮 8 个 minibatch、1 个内部 epoch | Appendix C.4 |

注意“重新前向和解码”不是说四个模型都要自回归生成：policy 需要逐 token 解码；reference、RM 和 critic 通常对已经生成的完整序列做评分前向。但四个角色都要为这一轮样本工作，所以 on-policy 的代价远高于“固定文本上反复算一个交叉熵”。

按论文数字，256k episodes、每轮 batch 512，约有 500 个 rollout batch；每轮 8 个 minibatch，形成约 4000 个 minibatch update。由于最大 response 长度是 1k token，生成 token 上界是 256M；平均长度没有报告，不能把这个上界写成实测吞吐。

**工程推断：**如果模型很大、response 很长，PPO 的瓶颈可能不是一次反向传播，而是“生成一批新样本需要多久，以及四个角色如何共享 GPU”。这也是为什么讲师幻灯片把 PPO 称为在线训练，并把“训练多个语言模型 + 采样在训练环路内”列为主要计算成本（Slides 88–91）。

### 5.3 超参数敏感性：稳定不是默认属性

RLHF 的另一笔账是调参和排障时间。论文不是只报告“用了 PPO”，还给出了很多稳定性边界：

| 旋钮 | 论文观察 | 这意味着什么 | 来源口径 |
|---|---|---|---|
| RM epoch | 多个 epoch 很快过拟合；单 epoch 更稳 | 比较数据不能像普通大数据集一样无脑重复 | Appendix C.2 |
| RM 学习率 | 改变约 50% 时表现相近 | RM 对学习率相对不敏感，但对 epoch 敏感 | Appendix C.2 |
| PPO batch | 在 64、128、256、512、1024 中，1.3B 实验选 512 | batch 不是“越大越稳定”的无条件规律 | Appendix E.11 |
| PPO minibatch | 32 略优于 64，但最终用 64 以获得更好 GPU 利用率 | 统计最优与系统吞吐最优可能不同 | Appendix C.4、E.11 |
| PPO 学习率 | 1.3B、无预训练混合的 PPO 中，大于 $8.05\times10^{-6}$ 的运行都发散 | 学习率是硬稳定边界，不是只影响收敛速度 | Appendix E.8 |
| 训练轮数 | 1.3B PPO-ptx 超过 256k episodes 没有发现收益 | on-policy 继续跑不等于一定继续变好 | Appendix E.11 |
| KL 系数 $\beta$ | 默认 $0.02$；单独把 KL 调大不能完全修复公开自然语言处理任务退化 | KL 只解决漂移的一部分，不等于能力保持开关 | Appendix C.4、E.6 |
| 预训练混合系数 $\gamma$ | PPO-ptx 使用 $27.8$，并混入约 8 倍于 RL episode 数量的预训练样本 | 用额外预训练梯度缓解 alignment tax，但增加计算与调参维度 | Appendix C.4 |

论文还报告了“alignment tax”（对齐税，即对齐训练导致其他任务能力回归）：默认 PPO 在 SQuADv2（阅读理解数据集）、DROP（离散推理问答数据集）、HellaSwag（常识推理数据集）、WMT 2015（机器翻译评测集）等任务上出现回归。PPO-ptx 可以明显减轻这些回归，但并非所有任务都完全恢复。这里的教训是**奖励更高不等于所有能力都更高**。

## 6. 论文结果与失败模式：小模型为何能赢，以及哪里仍会错

### 6.1 人工偏好上的结果

论文的比较对象要看清：主要评测是在留出的 prompt 上由人工标注者比较回答，不是只看 next-token loss，也不是只看一个自动 benchmark。

| 论文报告 | 数字 | 来源口径 |
|---|---:|---|
| 1.3B InstructGPT vs 175B GPT-3 | InstructGPT 被偏好 | §1、Figure 1；论文没有给这一对比较的独立百分比 |
| 175B InstructGPT vs 175B GPT-3 | $85\pm3\%$ 的比较中被偏好 | §1、§4.1；人工偏好，误差条为 95% 置信区间 |
| 175B InstructGPT vs few-shot 175B GPT-3 | $71\pm4\%$ 的比较中被偏好 | §1、§4.1；人工偏好，误差条为 95% 置信区间 |
| 闭域任务幻觉率 | 21% vs 41% | §1；InstructGPT vs GPT-3 |
| 尊重提示下的毒性输出 | 约减少 25% | §1；论文也说明偏见数据集没有显著改善 |
| TruthfulQA（真实性问答评测集） | InstructGPT 生成真实且有信息答案的频率约为 GPT-3 的两倍 | §1；具体比例随评测设置变化 |

因此，“1.3B 胜过 175B”真正说明的是：**在这组人工偏好分布上，后训练改变行为的收益可以超过单纯扩大参数量的收益。**它不是“1.3B 在所有任务上都比 175B 强”，也不是“参数量不重要”。论文明确指出模型仍有能力退化、毒性和简单错误。

### 6.2 后训练工程最重要的三个失败模式

这三个失败模式值得单独记住，因为它们不是“模型还不够大”能直接解决的问题，而是偏好数据、奖励模型和泛化之间的错位。

#### 失败模式 1：错误接受问题中的假前提

题目如果问“为什么某个并不存在的事实成立”，模型有时会顺着假前提继续解释，而不是先指出前提错误。论文 Figure 9 给出的例子是：用户问“冥想后为什么要吃袜子”，InstructGPT 没有拒绝前提，反而编造了多个解释。

- **论文事实**：作者推测训练数据里“带错误前提的 prompt”太少，模型对这类输入泛化不好（§4.3）。
- **本文工程推断**：如果 preference 数据只覆盖“正常问题 → 礼貌答案”，RM 可能无法奖励“先检查问题前提”这种少见动作；修复它需要反事实或对抗式 prompt，而不是只增大 policy。

#### 失败模式 2：过度 hedging，而不是直接回答

`hedging` 在这里指模型为了显得谨慎，列出许多“可能情况”，却不在证据足够时给出清晰结论。论文的例子是“高速炮弹打中南瓜会怎样”，模型列出很多不确定因素，却没有给出最可能的结果。

- **论文事实**：作者推测标注者被要求奖励 epistemic humility（认识到自己可能错，并在不确定时保持谨慎），奖励模型可能学到了“多 hedging 总是更好”（§4.3）。
- **本文工程推断**：谨慎是一种有条件的好行为；如果 RM 把“表达不确定”当作普遍高分捷径，policy 就会用免责声明替代推理。评测应把“事实不确定时谨慎”和“上下文已经足够时回避”分开标注。

#### 失败模式 3：多约束指令下退化

例如“列出 10 部 1930 年代制作、故事发生在法国的电影”，同时约束数量、年份和地点；或者要求摘要必须正好若干句。论文观察到，约束越多，模型越容易漏掉其中一项（§4.3）。

- **论文事实**：多约束任务是定性观察，不是论文给出的一条统一百分比。
- **本文工程推断**：SFT 示范如果很少覆盖约束组合，RM 的 pair label 也可能只奖励“总体读起来不错”，却没有显式惩罚漏约束。后训练系统需要把“每个约束是否满足”拆成可检查指标，而不是只用一个总分。

📌 **关键点**：这些失败模式告诉你，后训练不是把“人类喜欢”压成一个越高越好的旋钮。偏好数据怎样覆盖边界情况，RM 怎样表达局部约束，PPO 怎样避免奖励投机，三者缺一都可能留下行为漏洞。

## 7. ⚠️ 三个容易读错的结论

### ❌ 把“1.3B 胜 175B”读成参数量不重要

错误做法：把一次人工偏好评测推广成“后训练模型永远可以替代更大模型”。

正确读法：论文比较的是同一 GPT-3 架构下、不同训练方式和参数规模，在特定 prompt 分布、特定标注者偏好上的行为质量。结论是“对齐投入可能比单纯扩参更划算”，不是“扩参没有价值”。

### ❌ 把 reward model 分数当成真实质量

错误做法：看到 $r_\theta(x,y)$ 更高，就断言回答更真实、更安全。

正确读法：Bradley-Terry 只保证在训练比较分布上拟合“更可能被偏好”，分数还有任意平移不变性。奖励模型可能被 hedging、格式套路或其他代理特征欺骗；真实质量仍要用人工偏好、事实性、毒性和约束满足等多维评测验证。

### ❌ 把 PPO rollout 当成可以无限复用的离线数据

错误做法：第一轮 policy 生成一次数据，之后只在这批数据上继续训练很多 epoch，以为这样能省掉采样成本。

正确做法：PPO 每轮使用当前 policy 重新生成数据；同一轮内部可以按论文设置切成 8 个 minibatch、训练 1 个内部 epoch，但下一轮要回到 rollout。**省掉在线采样，改变的不是一个小优化，而是训练算法的统计假设。**

💡 **回顾：SFT 在这篇文章里是什么**

SFT 是用人类写好的 `(prompt, response)` 示范，逐 token 最大化 $\pi_\phi(y_t\mid x,y_{<t})$ 的监督微调；它提供 policy 的初始行为，也提供 KL reference 的冻结副本。本文后面再写“reference”时，指的就是这份固定 SFT 行为，而不是本轮 PPO 的 old policy。

💡 **回顾：AllReduce 与本文的边界**

AllReduce 是“各卡把自己的部分结果相加，最后每张卡都拿到同一份完整结果”的集合通信原语。DDP（DistributedDataParallel，分布式数据并行，每卡保存完整模型并同步梯度）和 FSDP（FullyShardedDataParallel，把参数、梯度或优化器状态分片保存）都可能使用它。PPO 当然可以用数据并行把 policy、RM 或 critic 放到多卡，但本文的核心代价发生在四个模型角色、rollout 解码和评分前向；AllReduce 的语义、Ring（把多张卡组织成环的数据通信算法）通信量与 DDP/FSDP 选型属于分布式训练基础，不在本篇重新展开。

## 📝 总结

1. **目标先错位**：next-token 损失只奖励“像训练文本一样续写”，没有直接编码 helpful、truthful、harmless 和多约束遵循。
2. **三阶段补监督**：SFT 从人类示范学初始行为，奖励模型用 Bradley-Terry 拟合成对偏好，PPO 再用可计算的 reward 更新 policy。
3. **RM 不是绝对裁判**：同一 prompt 的 $K$ 条回答产生 $\binom{K}{2}$ 个比较；把它们作为一个 batch element，既复用 $K$ 次前向分数，也减少相关样本导致的过拟合。
4. **PPO 有两把尺**：clip ratio $0.2$ 限制单轮相对 old policy 的跳步，KL 系数 $\beta=0.02$ 约束多轮相对冻结 SFT reference 的漂移。
5. **系统成本是四角色加在线循环**：7B FP16 四个权重副本约 56 GB；若 policy 与 critic 都保留 Adam 训练状态，简化账本约 252 GB，还未包括激活、缓存和通信。
6. **结果有边界**：论文报告 1.3B InstructGPT 被人工偏好胜过 175B GPT-3，175B InstructGPT 对 175B GPT-3 是 $85\pm3\%$；但假前提、多 hedging 和多约束指令仍会失败。

- [Long Ouyang et al.，Training language models to follow instructions with human feedback，arXiv:2203.02155](https://arxiv.org/abs/2203.02155) —— 本文的主来源；§1 给出目标错位与结果，§3.1/§3.5 给出三阶段、Equation 1/2 与训练配置，§4.1/§4.3 给出人工偏好和失败模式。
- [John Schulman et al.，Proximal Policy Optimization Algorithms，arXiv:1707.06347](https://arxiv.org/abs/1707.06347) —— PPO clipped surrogate 的原始算法来源；本文用它解释概率比与 clip，并明确区分它和 InstructGPT 论文的 Equation 2。

### 讲师幻灯片

- [Jonathan Zheng、Tarek Naous，Training language models to follow instructions with human feedback](https://raw.githubusercontent.com/cocoxu/CS8803-LLM-spring2026/main/slides/01_RLHF_InstructGPT.pdf) —— Slides 16–19 讲三段式流程，32–39 讲比较批处理、PPO 与 KL，84–91 讲失败模式、复杂度与 online PPO。
