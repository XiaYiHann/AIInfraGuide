> 原文：[ZeRO: Memory Optimizations Toward Training Trillion Parameter Models](https://arxiv.org/abs/1910.02054)（Samyam Rajbhandari, Jeff Rasley, Olatunji Ruwase, Yuxiong He,SC 2020,arXiv:1910.02054 v3,2020-05;本文访问日期 2026-08-15）

大模型训练的第一个问题是“装不下”：**数据并行（DP，每个 GPU 各存一份完整模型）在 32GB 显存的 GPU 上只能训 1.4B 参数**（§1），而模型状态（参数 + 梯度 + 优化器状态）在混合精度训练里要占 **16Ψ 字节**（Ψ 为参数量，Adam 优化器，§3.1）——1.5B 的 GPT-2 光模型状态就要 24GB。ZeRO 的回答是把“复制”改成“分区”：**三段式 P_os / P_os+g / P_os+g+p 分别把优化器状态、梯度、参数切到各卡上，显存从 16Ψ 降到 4Ψ（4×）、2Ψ（8×）、16Ψ/N_d（N_d 倍，N_d 为 DP 度数）**，通信量却只从 DP 的 2Ψ 涨到 3Ψ（1.5×，§7）。实测：400 张 V100 训 170B 参数模型（SOTA 的 8 倍），聚合吞吐 **15 Petaflops**（§10.2），并训练出当时世界最大模型 Turing-NLG（17B）。今天 PyTorch FSDP、DeepSpeed ZeRO-3 都是它的直系后代。本文先把“内存去哪了”的账算清，再逐段拆三段分区与通信账，最后对照 2026 年的工程现状。

## 0. 读前 3 分钟：两组直觉

**第一组：数据并行是“每人抱一份完整乐谱”，模型并行是“每人拿几页，但每翻一页都要喊一嗓子”。** 数据并行（DP）：每张卡存完整模型，每步训练后 all-reduce 平均梯度——计算高效但内存冗余（模型多大，每张卡就存多大）。模型并行（MP）：把模型切成几段分到各卡——省内存但通信频繁，跨节点时带宽骤降（§1：Megatron 在两个 DGX-2 节点间训 40B 模型时每卡只有约 5 Tflops，不到硬件峰值的 5%）。ZeRO 的立场：**两种都别选，把 DP 的“复制”改成“分区”，保留 DP 的计算效率。** 而且多数模型状态（优化器状态、梯度、参数）**不是每一步都需要**——比如某层的参数只在那一层的前向/反向时用得上（§4.1 洞察 c）。

**第二组：混合精度训练里，fp16 参数只是冰山一角。** 用 Adam 优化器训练时，除了 fp16 参数（2Ψ 字节）和 fp16 梯度（2Ψ），还要存 fp32 参数（4Ψ）、fp32 momentum（4Ψ）、fp32 variance（4Ψ）——总共 16Ψ 字节。**优化器状态（12Ψ）比参数本身（2Ψ）大 6 倍**。这就是为什么“模型才 3GB”却“32GB 显卡装不下”。

## 1. 内存去哪了：16Ψ 字节的账本

论文 §3 把训练内存分成两类：

**模型状态（model states）**——优化器状态、梯度、参数。混合精度训练（fp16 前向/反向 + fp32 更新，§3.1）：

| 组件 | 精度 | 字节/参数 |
| --- | --- | --- |
| 参数（forward/backward 用） | fp16 | 2Ψ |
| 梯度 | fp16 | 2Ψ |
| 参数（优化器维护的 fp32 主副本） | fp32 | 4Ψ |
| momentum（一阶矩） | fp32 | 4Ψ |
| variance（二阶矩） | fp32 | 4Ψ |
| **合计** | | **16Ψ** |

记 $K$ 为优化器状态的内存倍数（Adam 的 momentum + variance + fp32 参数 = 12Ψ，即 $K=12$），总内存 $2\Psi + 2\Psi + K\Psi = 16\Psi$ 字节（§3.1 原文公式）。**GPT-2 1.5B 参数 → 至少 24GB**，比纯 fp16 参数的 3GB 高 8 倍——这就是“1.4B 模型都训不动”的根源（§1）。

**残差状态（residual states）**——激活、临时缓冲区、碎片（§3.2）：

- **激活**：1.5B GPT-2（序列 1K、batch 32）约 **60GB**；activation checkpointing（激活检查点：只存部分激活、反向时重算）能降到约 **8GB**，但代价是 **33% 重算开销**；100B 模型即使加检查点也要约 60GB（batch 32）。
- **临时缓冲区**：梯度 all-reduce 前会融合成一个扁平 fp32 buffer，1.5B 模型就要 6GB；3B 模型 12GB（§6.2 也提到）。
- **内存碎片**：训练中长短生命周期张量交错分配，极端情况下 **30% 以上内存空闲仍会 OOM**（§3.2）。

## 2. ZeRO-DP：三段式分区（公式逐项拆解）

**要解决什么**：DP 把模型状态复制 N_d 份。ZeRO-DP 把三类状态**分区**（partition）到 N_d 个数据并行进程上，每进程只存 1/N_d 份并只更新自己那 1/N_d 的参数（§5.1）。

### 阶段一：P_os（优化器状态分区，§5.1）

把优化器状态（12Ψ）切成 N_d 份，第 i 个进程只存第 i 份并只更新对应参数。内存从 $4\Psi + K\Psi$ 降到 $4\Psi + \frac{K\Psi}{N_d}$（fp32 参数副本 4Ψ 仍每卡保留？不——注意公式：$4\Psi + \frac{K\Psi}{N_d}$，fp16 参数 2Ψ + fp16 梯度 2Ψ = 4Ψ 保持复制，优化器状态 12Ψ 分区）。N_d 大时 → $4\Psi$，**4× 降幅**。通信量不变：每步结束时 all-gather 全量更新后的参数。

### 阶段二：P_g（梯度分区，§5.2）

因为每进程只更新自己那份参数，它只需要自己那份参数的梯度。反向传播时，每个梯度**只归约到负责该参数更新的进程**（Reduce-Scatter），用完即可释放。内存从 $2\Psi + \frac{14\Psi}{N_d}$ 起步降到 ≈ $2\Psi$——注意 $2\Psi$ 是 fp16 参数（保留复制），梯度从 2Ψ 降到 2Ψ/N_d、优化器状态已分区。累计 **8× 降幅**。通信量仍与 DP 相同（见第 5 节）。

### 阶段三：P_p（参数分区，§5.3）

参数也分区：每个进程只存自己那份。前向/反向需要其他进程的参数时，由持有者 **broadcast**（广播）过来，用完即弃（§7.2.2 描述了按层流水化的 broadcast 调度）。内存降到 **16Ψ/N_d**——N_d 越大模型越大，**模型大小与卡数成正比**。通信量最多 **1.5×** DP。

### 为什么能这么干：时间局部性（§4.1 洞察 c）

参数、梯度、优化器状态**不是全程都需要**：某层参数只在该层前向/反向时用。分区 + 按需通信，就是用“通信调度”换“内存冗余”。三个阶段的组合记忆口诀：**P_os 省 4×、P_os+g 省 8×、P_os+g+p 省 N_d×**。

## 3. 手算账本：7.5B 模型、64 卡

论文 Fig.1 与 §5.1-5.3 的数值例子（Ψ = 7.5B，N_d = 64，K = 12）：

| 配置 | 公式 | 数值（7.5B，64 卡） |
| --- | --- | --- |
| 标准 DP（无 ZeRO） | 16Ψ | 120 GB |
| + P_os | $4\Psi + 12\Psi/64$ | 30 + 1.4 = **31.4 GB** |
| + P_os+g | $2\Psi + 14\Psi/64$ | 15 + 1.6 = **16.6 GB** |
| + P_os+g+p | 16Ψ/64 | **1.9 GB** |

（Ψ=7.5B 时：16Ψ = 120GB；4Ψ = 30GB；12Ψ = 90GB；2Ψ = 15GB；14Ψ = 105GB。数字核对 §5.1-5.3 原文。）

**上界推演（§5.4,Table 1）**：N_d = 64 时，P_os / P_os+g / P_os+g+p 分别能装 7.5B / 14B / 128B 参数模型（32GB V100 集群）；N_d = 1024 时，P_os+g+p 能装 **1 万亿参数**——1T 模型的 16TB 模型状态 ÷ 1024 = 每卡 16GB（§1）。

## 4. ZeRO-R：激活、缓冲区与内存碎片

模型状态省下来后，残差状态成为新的瓶颈。ZeRO-R 三招（§4.2、§6）：

**P_a（分区激活检查点，§6.1）**：MP 下激活是复制的（把线性层纵向切分到两张卡，每张卡都需要完整输入激活）。ZeRO 把激活检查点**分区**存储，需要时 all-gather 重建（一次一个激活层）。100B 模型、MP16、batch 32：每卡激活检查点从约 **33GB 降到约 2GB**；再配合 CPU offload（P_a+cpu）几乎降到 0。通信开销 < MP 基线通信量的 **10%**（§8）。

**CB（常量大小缓冲区，§6.2）**：梯度 all-reduce 融合缓冲区的开销与模型大小成正比（3B 模型 fp32 融合 buffer = 12GB）。ZeRO 用固定大小的融合缓冲区——不随模型增长，又足够大以保持效率。

**MD（内存碎片整理，§6.3）**：前向的检查点（长命）与可丢弃激活（短命）、反向的参数梯度（长命）与激活梯度（短命）交错分配造成碎片。ZeRO 预先分配连续内存块，把激活检查点与梯度搬到预分配区域——既避免“有内存但不够连续”的 OOM，也减少分配器搜索时间。

## 5. 通信账：为什么只多 50%

**标准 DP（§7.1）**：每步 all-reduce 梯度 = reduce-scatter（Ψ 数据移动）+ all-gather（Ψ）= **2Ψ**。

**P_os+g（§7.2.1）**：梯度只做 scatter-reduce（Ψ，各进程收到自己那份），参数更新后 all-gather 一次（Ψ）——合计 **2Ψ，与 DP 完全相同**。这就是“省 8 倍内存不花通信钱”的来源。

**P_os+g+p（§7.2.2）**：前向按层 broadcast 参数（Ψ，摊到整个前向，用完即弃）+ 反向再 broadcast 一次（Ψ）+ 梯度 scatter-reduce（Ψ）= **3Ψ = 1.5× DP**。

**直觉**：分区不增加总数据量——本来 all-reduce 也是“每个人收到所有人的梯度”，只是 ZeRO 让“每人只收自己那份的最终结果”。多出来的 Ψ 是参数 broadcast 的往返。

## 6. 评测：170B、15 Petaflops、超线性

实现为 ZeRO-100B（P_os+g + ZeRO-R，§10.1），硬件 400 张 V100（25 个 DGX-2 节点，800Gbps 节点间带宽），基线为 PyTorch DDP 与 Megatron-LM。

- **模型大小（§10.2,Fig.2）**：170B 参数模型（400 GPU），比 Megatron 可高效扩展的 40B 大 **8 倍以上**。
- **吞吐（§10.2）**：8B-100B 模型上平均聚合 **15 Petaflops**（超过峰值 30%），相对 SOTA 最高 **10× 加速**。MP 基线衰减的根源：跨节点后带宽从 NVSwitch 的 300GB/s/链路 跌到 InfiniBand EDR 的 12.5GB/s/链路。
- **超线性扩展（§10.3,Fig.3）**：60B 模型从 64 卡到 400 卡，**卡数翻倍性能翻倍以上**——因为 DP 度数增大让每卡内存占比下降，能装更大 batch。
- **民主化（§10.4,Fig.5）**：128 卡无任何 MP/PP 训 **13B** 参数（>40 TFlops/卡）；对比 DDP 无 ZeRO 时 1.4B 就 OOM（<20 TFlops/卡）。数据科学家不需要改模型就能用（接口兼容 torch.nn.module）。
- **世界纪录（§1,Fig.5）**：Turing-NLG **17B** 参数，当时世界最大语言模型。
- **迈向 1T（§9）**：按 BERT-Large 的训练量推算，1T 模型在同等硬件上要 **140 天**以上——“装得下”不等于“训得起”，论文明确承认计算能力的缺口（需要 exa-flop 级系统）。

## 🕰️ 原文时代 vs 当前工程：FSDP 与 ZeRO-3 的今天

ZeRO 论文写于 2019-2020 年（V100 时代）。2026 年再看，机制延续、形态演化（以下均标注来源与访问日期 2026-08-15）：

| 主题 | 原文时代（锚点） | 当前工程 |
| --- | --- | --- |
| 实现形态 | ZeRO-100B 只实现了 P_os+g + ZeRO-R（§10.1），P_p（stage 3）计划“2020 年 5 月底发布”（§1） | DeepSpeed 完整实现 ZeRO-1/2/3 + ZeRO-Offload + ZeRO-Infinity（官方仓库）；PyTorch 原生 FSDP 提供等价的 full sharding（官方文档） |
| 训练框架中的位置 | 论文期 DP 的替代品 | 现代大模型训练标配：DeepSeek-V3 训练用 ZeRO-1 DP 配合 16-way PP + 64-way EP（报告 §3.2）；GLM-5 等报告沿用类似组合 |
| 与 MP 的关系 | ZeRO 主张“DP 分区可替代大部分 MP”（§1） | 实践共识是**组合**：tensor parallel 仍用于单节点内（Megatron PTD-P 体系），ZeRO/FSDP 负责数据维度的参数切分；Megatron 团队实测 PTD-P 相比 ZeRO-3（纯 DP 用法）在 175B/530B 模型上快 6%-70%（SC21 论文 Table 2/Fig.10，2021 数据） |
| 硬件语境 | V100 32GB、NVLink 300GB/s、EDR 12.5GB/s（§10.2） | H100/B200 显存 80-192GB、NVLink 900GB/s 级；但“模型状态 > 单卡显存”的矛盾依旧存在，FSDP/ZeRO-3 仍是千亿级训练的标准答案 |

**结论边界**：ZeRO 论文的“1T 参数可训练”主张在 2020 年只是内存可行性分析（§9 承认算力缺口）；今天 1T+ 稠密模型仍未普及，MoE（如 DeepSeek-V3 的 671B 总参）用“激活稀疏 + 专家并行”绕开了同等问题——两种路线并存。论文里“DP 通信 2Ψ、ZeRO 3Ψ”的分析对现代实现仍成立，但实际系统还叠加了梯度压缩、通信重叠等后续优化（官方文档）。

## 7. 常见误读与错误做法

- **误读 1：“ZeRO 就是省显存，训练会变慢。”** 错。P_os 与 P_os+g 的通信量与标准 DP **完全相同**（§7.2.1）；P_p 多 50% 但换来 N_d 倍内存降幅。论文实测 10× 加速（§10.2）——省显存换来的更大 batch 直接提高吞吐。
- **误读 2：“ZeRO-3（P_p）能装下任意大的模型。”** 部分对。内存上确实任意大（16Ψ/N_d，§5.4），但 **compute（算力）是硬约束**：论文自己算了 1T 模型要 140 天（§9）。“装得下”和“训得起”是两个问题。
- **误读 3：“ZeRO 与模型并行互斥。”** 错。论文明确 ZeRO 可与 MP 组合（§1：理论降幅 N_d × N_m），ZeRO-100B 的评测本身就是 ZeRO-DP + Megatron MP 组合跑的（§10.1）。今天 FSDP + TP 的组合正是这个思路的延续。
- **错误做法 1（选型）**：小模型（<13B）直接上 P_p 全分区。P_p 的 1.5× 通信在算力富余的小模型上可能是纯开销；论文的 ZeRO-100B 只实现 P_os+g 不是没原因的（§10.1）——按模型大小与带宽选阶段。
- **错误做法 2（理解 FSDP）**：把 FSDP 当成“每层参数 all-gather 后完整副本参与计算”就以为没有通信。FSDP 的通信量就是 ZeRO 的 3Ψ 分析（前向/反向各一次 broadcast + 梯度 reduce-scatter），现代实现用分片与流水化隐藏它；不懂这条账，就无法解释为什么 FSDP 在小 batch 下反而慢（官方文档也建议与 TP 组合）。

## 📝 总结

1. **模型状态是内存大头**：Adam 混合精度下 16Ψ 字节，其中优化器状态 12Ψ——1.5B 的 GPT-2 光状态就要 24GB，DP 只能在 32GB 卡上训 1.4B。
2. **ZeRO-DP 三段分区用通信换内存**：P_os 省 4×、P_os+g 省 8×（通信不变）、P_os+g+p 省 N_d×（通信 1.5×）；配合 ZeRO-R（激活分区、常量缓冲区、碎片整理）处理残差状态。
3. **实测与影响**：400 张 V100 训 170B 模型、15 Petaflops、8× 模型规模、10× 速度、超线性扩展；今天 FSDP/ZeRO-3 是它的直系后代，仍是千亿级训练的标准配置。
