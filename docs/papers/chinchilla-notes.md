固定训练算力时，先把模型做到最大并不划算：Chinchilla 用约 **70B 个参数（模型中会被训练更新的数字）训练 1.4T 个 token（模型处理文本的最小片段）**，在与 **280B 参数、300B token 的 Gopher** 近似相同的训练 FLOPs（浮点运算次数）下，MMLU（Massive Multitask Language Understanding，多学科语言理解基准）5-shot（先给模型 5 个示例再答题）平均准确率达到 **67.6% 对 60.0%**，模型参数还小 4 倍。把这笔账抽象出来，记 $N$ 为参数量、$D$ 为训练 token 数、$C$ 为总训练 FLOPs：它们应近似满足 $N\propto C^{0.5}$、$D\propto C^{0.5}$，实际规划时可以先用 **约 20 个训练 token / 参数**作为起点。

## 0. 读前 3 分钟：先把三本账对齐

### 0.1 $N$、$D$、$C$ 到底各记什么

先把三个字母放回工程现场。**$N$ 是模型参数量，$D$ 是训练 token 数，$C$ 是一次预训练作业的总计算量。**

- **Token**：模型处理文本时使用的最小离散片段，可以是一个字、半个词或标点，不一定等于人类眼中的“词”。$D=1\ \text{T}$ 表示训练过程中模型看过约 $10^{12}$ 个 token。
- **参数 $N$**：模型里会被训练更新的数字，例如矩阵中的权重。$N=70\ \text{B}$ 表示约 $7\times10^{10}$ 个可学习数字。
- **数量级后缀**：$M$ 表示百万，$B$ 表示十亿，$T$ 表示万亿；例如 $1\ \text{T}=10^{12}$。
- **损失 $L$**：模型预测下一个 token 时犯错程度的平均分数，越低越好。论文主要分析预训练语言建模损失，而不是把所有下游能力压成一个分数。
- **计算预算 $C$**：把一次训练中执行的浮点运算总数加起来。它不是 GPU（图形处理器，一种擅长并行浮点运算的加速器）的每秒速度，而是这次作业最终要付出的计算总量。

这里的 **FLOP** 是一次浮点运算，例如一次浮点加法或乘法；**FLOPs** 是这类运算的总数。工程上常写“训练用了 $10^{23}$ FLOPs”，意思是总共做了约 $10^{23}$ 次浮点运算。

### 0.2 先回顾 scaling law，再看 Chinchilla 改了什么

**Scaling law（缩放定律）**是从很多次训练实验中观察到的经验规律：当模型参数、训练数据或计算量按比例变大时，损失通常沿着可预测的幂律（形如 $x^p$ 的比例关系）或对数曲线变化。它不是“模型越大永远越好”的口号，而是一个可以用来做预算外推的拟合工具。

💡 **回顾：Scaling law 是什么**

Scaling law 用一条经验曲线回答“规模变大，质量大约怎样变”。站内 [模块一 3.7 Transformer Decoder Block 完整解析](/AIInfraGuide/prerequisites/模块一-前置知识/transformer/37-transformer-decoder-block完整解析)用它解释只含解码器的 Decoder-only 模型（根据前文逐个预测下一个 token）为什么可以通过堆叠层数和扩大宽度持续扩展；**本文把问题往工程预算推进**：不只问模型变大是否更好，还要在固定 $C$ 下决定 $N$ 和 $D$ 的分配。这个链接补充架构扩展直觉，本文负责训练算力账本与 Chinchilla 的实证结论。

### 0.3 为什么训练 FLOPs 先近似成 $6ND$

一个 token 经过一个有 $N$ 个参数的密集模型时，前向传播要让输入和权重做大量乘加。把一次“乘法 + 加法”按 2 个 FLOPs 计，**前向传播约为 $2ND$**。反向传播还要沿计算图求梯度，Chinchilla 的 Appendix F 沿用常见近似：反向 FLOPs 约为前向的 2 倍，也就是 **$4ND$**。

把两段相加：

$$
C\approx
\underbrace{2ND}_{\text{前向：每个参数、每个 token 约 2 个 FLOPs}}
+
\underbrace{4ND}_{\text{反向：约为前向 2 倍}}
=
\underbrace{6ND}_{\text{一次训练的主干 FLOPs}}
$$

逐项看，$N$ 负责“每个 token 要经过多少权重”，$D$ 负责“这样的 token 有多少个”，6 则来自前向 2 加反向 4。代入一个常见量级：

$$
C\approx6\times(70\times10^9)\times(10^{12})
=4.2\times10^{23}\ \text{FLOPs}
$$

这不是说每个模型的精确 FLOPs 永远等于 $6ND$。论文 Appendix F 还把 embedding（把 token 映射成向量的表）、attention（按相关性汇总其他 token 信息的计算）和最后的 logits（送入概率归一化前的未归一化分数）等项逐项算进去，并在 Table A4 说明精确值与 $6ND$ 的差异很小；所以本文用 $6ND$ 做可手算的预算主干，引用论文的最终训练 FLOPs 时仍以论文报告为准。

⚠️ **注意**：这里的“反向约为前向 2 倍”是训练大模型的工程近似，不是所有网络、精度和算子都严格满足的物理定律。它足以做规模规划，但真正开跑前还要用目标模型的计算图核对。

## 1. 问题：固定算力为什么不能只做大模型

### 1.1 固定 $C$ 后，真正要优化的是什么

**问题不是“我能把模型做多大”，而是“在同一笔 $C$ 里，模型容量和训练样本各买多少”。**

模型太小，参数容量不足，即使继续看数据也很难再降损失；模型太大，单个 token 的计算太贵，固定预算下只能看很少的数据，模型还没有训练充分。把这种“容量”和“训练充分度”放在同一张账上，论文写成：

$$
\left(N_{\mathrm{opt}}(C),D_{\mathrm{opt}}(C)\right)
=
\underset{N,D\,:\,\mathrm{FLOPs}(N,D)=C}{\arg\min}\ L(N,D)
$$

- $N_{\mathrm{opt}}(C)$：预算为 $C$ 时损失最低的参数量；
- $D_{\mathrm{opt}}(C)$：同一预算下应看的训练 token 数；
- $L(N,D)$：给定模型大小和数据量后的最终预训练损失；
- 约束 $\mathrm{FLOPs}(N,D)=C$：钱只有这么多，不能同时把 $N$ 和 $D$ 无限增大。

用一笔思想实验把约束算出来。若 $C=1.2\times10^{23}$ FLOPs，下面三组方案都满足 $6ND=C$：

| 方案 | $N$ | $D=C/(6N)$ | 直觉判断 | 来源口径 |
| --- | ---: | ---: | --- | --- |
| A | $10\ \text{B}$ | $2\ \text{T}$ | 模型较小，可能容量受限 | 本文思想实验 |
| B | $20\ \text{B}$ | $1\ \text{T}$ | 参数和数据较平衡 | 本文思想实验 |
| C | $40\ \text{B}$ | $0.5\ \text{T}$ | 模型较大，可能训练不足 | 本文思想实验 |

三组方案花掉的主干 FLOPs 一样，但最终损失不会一样。**固定算力把问题从“单变量变大”变成了“两个变量怎样配平”。**

### 1.2 为什么 2020 年的答案偏向更大的 $N$

Kaplan 等人在 2020 年给出的预算分配结论是：

$$
N_{\mathrm{opt}}\propto C^{0.73},\qquad D_{\mathrm{opt}}\propto C^{0.27}
$$

也就是算力扩大 10 倍时，参数量大约扩大 $10^{0.73}\approx5.4$ 倍，训练 token 只扩大 $10^{0.27}\approx1.9$ 倍。这个答案看起来很合理：参数越多，单步表达能力越强；而且当时很多前沿模型都在约 300B token 附近训练，继续把参数做大容易形成可见的模型规模竞争。

Chinchilla 的批判不是“幂律拟合这种数学方法错了”，而是**实验协议可能把大模型的欠训练误测成了规模优势**。论文在 Related Work 与 §3 中点出三件事：

1. **固定 token 预算**：不同大小的模型都看差不多数量的 token。大模型每个 token 更贵，在固定总预算下本来应该减少或增加 token？如果把 token 数硬锁死，实验就无法公平比较“这个大模型多看数据后会怎样”。
2. **LR schedule 不匹配**：learning rate（学习率）是每次参数更新迈多大步的步长；**LR schedule（学习率调度计划）**规定这个步长怎样随训练进度变化，cosine schedule 则是按余弦曲线逐步降低学习率的一种计划。若所有实验都使用同一条固定长度的 cosine schedule，短训练和长训练都不一定在各自合适的进度上结束。
3. **$N$ 与 $D$ 没有充分联合变化**：要回答“参数和数据怎样分配”，必须同时改变模型大小和训练 horizon（训练到多少 token 的终点），再观察同一 $C$ 下的损失谷底。只在少数固定配置里改变一个变量，不能直接识别二维分配关系。

Chinchilla 因此训练了 **400 多个模型**，规模从约 70M 到超过 16B 参数，训练数据从 5B 到超过 400B token，并为同一参数量安排多个训练 horizon。这里的 400 多个是论文报告数字，不是本文估算。

## 2. 核心结论：参数和数据要一起长

### 2.1 三个指数先记住

论文用三种方法估计“固定 $C$ 时的最优点”。三种方法的细节不同，但都得到近似结论：

$$
\boxed{N_{\mathrm{opt}}\propto C^{0.50}},
\qquad
\boxed{D_{\mathrm{opt}}\propto C^{0.50}}
$$

这两个 $0.50$ 的直觉是平方根：预算扩大 4 倍，参数量和训练 token 各扩大约 2 倍；预算扩大 10 倍，两者各扩大约 $\sqrt{10}\approx3.16$ 倍。**不是把新增算力几乎全投给参数，而是让参数与数据近似同步增长。**

这里的“近似”很重要。论文 Table 2 的三组结果是：训练曲线包络给 $0.50/0.50$，IsoFLOP 给 $0.49/0.51$，参数化损失模型给 $0.46/0.54$。它们不是一个跨越所有模型族、数据质量和训练阶段的自然常数，而是在论文实验范围内相互支持的经验前沿。

### 2.2 约 20 个 token / 参数从哪里来

如果 $N$ 和 $D$ 都按 $C^{0.5}$ 增长，它们的比值不会随着预算剧烈变化。Chinchilla 把这个比值转成了工程配方：**每个参数大约配 20 个训练 token。**

论文 Table 3 的方法一（Approach 1）投影如下：

| 参数量 | 论文投影的最优 token | token / 参数 | 来源口径 |
| ---: | ---: | ---: | --- |
| $67\ \text{B}$ | $1.5\ \text{T}$ | $22.4$ | 论文 Table 3 |
| $175\ \text{B}$ | $3.7\ \text{T}$ | $21.1$ | 论文 Table 3 |
| $280\ \text{B}$ | $5.9\ \text{T}$ | $21.1$ | 论文 Table 3 |
| $1\ \text{T}$ | $21.2\ \text{T}$ | $21.2$ | 论文 Table 3 |

实际验证模型叫 Chinchilla，使用 **70B 参数和 1.4T token**，约等于 20 token / 参数。67B/1.5T 是 Table 3 的四舍五入规划点，70B/1.4T 是 §4 的实际模型配置；不要把两个数字误读成两次不同实验。

📌 **关键点**：20 不是“看到 20 个 token 就足够训练任何模型”，而是把论文 2022 年的 dense autoregressive transformer（稠密自回归 Transformer：每个 token 都经过同一套完整参数）实验压缩成一个便于开工的起点。数据质量、重复率、架构、后训练和部署成本变化后，比例需要重新测。

## 3. 三种互补估计：怎样找到谷底

三种方法像三把不同的尺子：第一把沿着训练过程找最低包络，第二把在固定算力切片上直接扫模型大小，第三把先拟合一张平滑损失曲面再求导。它们回答的是同一个问题，但误差来源不同。

### 3.1 方法一：训练曲线包络，把很多次训练压成一条前沿

**要解决什么？** 单次训练只能告诉你一个 $(N,D,L)$ 点，无法说明另一个参数量是否更划算。包络法的输入是大量不同模型大小、不同训练长度的曲线，输出是“每一笔 $C$ 该选哪一个点”。

把流程沿着数据流走一遍：

1. **固定一个 $N$，安排多个训练 horizon**：同一模型大小不只跑到一个 token 数，而是让 cosine schedule 的长度随训练 token 改变。论文方法一（Approach 1）对每个参数量安排 4 个训练序列长度。
2. **把横轴统一成 FLOPs**：每条训练曲线原本以训练进度为横轴，通过 $C\approx6ND$ 转成“已经花了多少计算”。
3. **取下包络**：对每个 FLOP 值，比较所有运行点的损失，只保留最低的那个。这个最低点告诉你在这笔预算下当前最好的 $N$ 和 $D$。
4. **拟合预算前沿**：把选出的 $N_{\mathrm{opt}}$ 和 $D_{\mathrm{opt}}$ 对 $C$ 做幂律拟合，得到 $0.50/0.50$。

为了让公式承担直觉，可以用一个局部的对数收益模型表示包络：

$$
L_{\mathrm{env}}(N,D)=E-a\ln N-b\ln D
$$

- $E$：理想数据分布和模型都足够好时的损失底座；
- $a\ln N$：扩大参数量带来的对数收益；
- $b\ln D$：增加训练 token 带来的对数收益；
- $\ln$：自然对数，表示“从 1 到 2”和“从 100 到 101”不是同样的相对增幅；
- $a,b>0$：在观察范围内拟合出的收益敏感度。

例如若局部 $a=0.50$，把参数从 $N$ 加倍，模型损失的参数收益项变化约为 $0.50\ln2\approx0.347$；这是公式的局部解释，不是整篇论文的统一损失数值。

**一个容易混淆的地方**：$L_{\mathrm{env}}=E-a\ln N-b\ln D$ 本身只是把收益写成对数直线的教学近似。固定 $C$ 代入 $D=C/(6N)$ 后，如果恰好 $a=b$，这条过度简化的式子不能单独决定唯一的 $N/D$ 比例。真正的比例来自论文对大量有限训练曲线取包络后得到的经验前沿；“$a\approx b\approx0.50$”在课程和结果摘要里对应的是最优前沿的两个 $C$ 指数，而不是可以脱离实验单独求出谷底的两个常数。

用最小数字检查“平方根增长”：若某个经验前沿在 $C_0$ 时选 $N_0=1\ \text{B}$、$D_0=20\ \text{B}$，预算变成 $4C_0$ 时，

$$
N_1=N_0\sqrt{4}=2\ \text{B},\qquad
D_1=D_0\sqrt{4}=40\ \text{B}
$$

参数和 token 都翻 2 倍，乘积 $ND$ 翻 4 倍，刚好支付 4 倍主干 FLOPs。这个小算例是本文解释，不是论文某一条具体训练记录。

### 3.2 方法二：IsoFLOP 切片，沿等算力线直接找 U 型谷底

**IsoFLOP** 可以直译为“固定 FLOPs 的切片”：先把总训练算力锁定，再扫不同的参数量。因为 $C\approx6ND$，一旦给定 $C$ 和 $N$，训练 token 数就被迫变成：

$$
D(N;C)=\frac{C}{6N}
$$

这条式子做的事很单纯：$N$ 加倍，若总预算不变，$D$ 就减半。于是你可以把每个参数量的最终损失画在同一条“等算力”横线上，横轴是 $N$，纵轴是 $L$。论文观察到曲线呈 **U 型**：左边模型太小，容量不足；右边模型太大，token 不够、训练不足；最低点就是该 $C$ 的最优模型大小。

*图源：本文根据 Chinchilla §3.2、Fig. 3 重绘；曲线形状为机制示意，不是原图像素复制。*

#### 纸笔走查：一条等算力线怎样找到谷底

取一个便于计算的预算 $C=1.2\times10^{23}$ FLOPs。沿着这条切片选三个 $N$，用 $D=C/(6N)$ 算出对应数据量，再假设我们测得一组**示意损失**：

| $N$ | $D=C/(6N)$ | 示意损失 $L$ | 位置判断 | 来源口径 |
| ---: | ---: | ---: | --- | --- |
| $10\ \text{B}$ | $2.0\ \text{T}$ | $2.00$ | 左侧，模型可能太小 | 本文思想实验 |
| $20\ \text{B}$ | $1.0\ \text{T}$ | **$1.82$** | **谷底，当前最优** | 本文思想实验 |
| $40\ \text{B}$ | $0.5\ \text{T}$ | $1.96$ | 右侧，模型可能没训够 | 本文思想实验 |

怎么算第一行？$6\times10\ \text{B}\times2\ \text{T}=1.2\times10^{23}$ FLOPs；第二、三行同理。损失数字只是让 U 型“谷底”可以被纸笔识别的教学观测，不能当成 Chinchilla 论文报告值。

论文方法二（Approach 2）在 9 个固定 FLOP 预算上做这件事，预算范围约为 $6\times10^{18}$ 到 $3\times10^{21}$ FLOPs；每条曲线用抛物线拟合谷底位置，再对谷底随 $C$ 的变化拟合，得到 $N$ 指数 $0.49$、$D$ 指数 $0.51$。

📌 **关键点**：IsoFLOP 的价值是把“模型太大导致 token 不够”直接画成右侧上升段。你不需要先相信某个理论，只要在相同预算下把 $N$ 扫过去，最低点就会自己露出来。

### 3.3 方法三：参数化拟合，给损失曲面装一把可求导的尺

**要解决什么？** 前两种方法依赖训练曲线和离散扫描，参数化方法希望把所有观测点压进一张平滑损失曲面，然后在 $6ND=C$ 上求最小值。

论文 §3.3 的参数化模型是：

$$
\hat L(N,D)=E+\underbrace{\frac{A}{N^{\alpha}}}_{\text{模型容量不足的损失}}
+\underbrace{\frac{B}{D^{\beta}}}_{\text{训练数据有限的损失}}
$$

这里：$E$ 是不可约损失底座，$A,B$ 是尺度常数，$\alpha$ 控制扩大模型带来的收益衰减速度，$\beta$ 控制增加数据带来的收益衰减速度。两个幂次项都随着 $N$ 或 $D$ 变大而下降，但下降会越来越慢。

固定 $C$，把 $D=C/(6N)$ 代入。令 $N$ 为自变量，损失变成一条一维曲线。求最优点只需要下面这一行核心推导：

$$
\frac{d\hat L}{dN}
=
-\alpha A N^{-\alpha-1}
+\beta B\left(\frac{6}{C}\right)^{\beta}N^{\beta-1}=0
\Longrightarrow
N_{\mathrm{opt}}=G\left(\frac{C}{6}\right)^{\frac{\beta}{\alpha+\beta}},\quad
D_{\mathrm{opt}}=G^{-1}\left(\frac{C}{6}\right)^{\frac{\alpha}{\alpha+\beta}}
$$

其中

$$
G=\left(\frac{\alpha A}{\beta B}\right)^{\frac{1}{\alpha+\beta}},\qquad
\text{参数指数 }a=\frac{\beta}{\alpha+\beta},\qquad
\text{数据指数 }b=\frac{\alpha}{\alpha+\beta}
$$

这一步的直觉是：在谷底处，继续增大模型所能省下的损失，恰好等于因为少训 token 而增加的损失。论文拟合得到 $a=0.46$、$b=0.54$，比前两种方法略偏向数据，但仍然是“参数和数据近似一起长”。

#### 最小求导算例

为了让导数不只停留在符号上，设一个玩具损失：$E=0$、$A=B=1$、$\alpha=\beta=1$，并把预算写成 $C=6ND=600$，因此 $ND=100$。代入后：

$$
\hat L(N)=\frac{1}{N}+\frac{1}{D}
=\frac{1}{N}+\frac{N}{100}
$$

求导：

$$
\frac{d\hat L}{dN}=-\frac{1}{N^2}+\frac{1}{100}=0
\Longrightarrow N=10,
\qquad D=\frac{100}{10}=10
$$

在这个对称玩具模型里，参数和数据相等时落在谷底；真实论文的 $A,B,\alpha,\beta$ 不对称，所以最优比例是约 20 token / 参数，而不是数学上永远为 1。

### 3.4 三把尺子是否互相打架

把论文 Table 2 和 Kaplan 的结论放在同一张表里：

| 方法 | 它怎样找最优点 | $N_{\mathrm{opt}}$ 指数 | $D_{\mathrm{opt}}$ 指数 | 来源口径 |
| --- | --- | ---: | ---: | --- |
| 训练曲线包络 | 每个 $C$ 取最低损失运行点 | $0.50$ | $0.50$ | 论文 Table 2 |
| IsoFLOP 切片 | 固定 $C$ 扫 $N$，找 U 型谷底 | $0.49$ | $0.51$ | 论文 Table 2 |
| 参数化损失 | 拟合 $\hat L$ 后在 $6ND=C$ 上求导 | $0.46$ | $0.54$ | 论文 Table 2 |

## 4. 证据与反例：Chinchilla 为什么赢

### 4.1 同样训练 FLOPs，模型小四倍、数据多很多

论文没有停在小模型外推，而是做了一个关键验证：根据前沿预测，Gopher 使用的预算最适合约 40–70B 参数的模型。于是 DeepMind 训练了 **70B 的 Chinchilla**，使用 **1.4T token**，并与 **280B、300B token 的 Gopher** 对比。论文明确说两者使用相同数量级的训练 FLOPs；参数和 token 的四舍五入数字代入 $6ND$ 后不完全相等，是因为论文报告的是更精确的架构级 FLOPs，而表格只展示了整齐的 B/T 数字。

### 4.2 论文报告的基准数字，以及一个重要的公平性提醒

先定义一个论文里的指标。**Perplexity（困惑度）**可以理解成模型对真实 token 的平均“犹豫程度”；在自然对数损失口径下，常写成 $\mathrm{PPL}=e^L$，其中 PPL 是 perplexity 的常用缩写，越低越好。**MMLU** 是 Massive Multitask Language Understanding，多学科语言理解基准，包含 57 个学科任务；**5-shot** 表示答题前给模型 5 个示例，让它按示例格式完成新题。

论文 Table 6 报告了：

| 评测 | Gopher | Chinchilla | 差值 | 来源口径 |
| --- | ---: | ---: | ---: | --- |
| MMLU 5-shot 平均准确率 | $60.0\%$ | **$67.6\%$** | **+7.6 个百分点** | 论文 Table 6 |
| MMLU 单任务表现 | — | 51/57 高于 Gopher，2/57 持平，4/57 低于 | 多数任务提升 | 论文 §4.2.2 |
| WikiText-103 困惑度 | $7.75$ | **$7.16$** | 越低越好 | 论文 §4.2.1 |

MMLU 的对比尤其有说服力：70B 的 Chinchilla 在 57 个任务中有 51 个超过 Gopher，说明差异不只来自某一个语言建模数据集。但 WikiText-103（语言建模数据集）和 The Pile（多源文本集合）一类语言建模结果要谨慎解读，因为 Chinchilla 训练数据约多 4 倍，论文自己提醒训练集与测试集泄漏可能放大优势。因此，论文把 MMLU、BIG-bench（Beyond the Imitation Game Benchmark，多任务行为评测）和闭卷问答等泄漏风险相对不同的任务看得更重要。

### 4.3 ⚠️ 看起来合理但错误：token 固定，参数一路做大

**错误做法**：先把训练 token 固定在约 300B，再把模型从 70B 扩到 280B、530B，最后根据损失曲线断言“新增算力应该优先买参数”。

它错在哪里？先用 $C\approx6ND$ 看一眼：如果 $D=300\ \text{B}$ 不变，$N$ 从 70B 变成 280B，单纯的参数乘积就扩大 4 倍。对于更大的模型，固定 token 数意味着它们在更少的“相对训练机会”下结束；模型还没把新增容量用熟，实验却已经给它打了最终分数。

| 看起来合理的做法 | 实际引入的偏差 | Chinchilla 的修正 |
| --- | --- | --- |
| 所有模型都训约 300B token | 大模型被迫提前停止，欠训练被误认为规模收益变慢 | 让 $D$ 随 $N$ 一起变化 |
| 所有运行复用同一 LR schedule 终点 | 短跑可能在不合适的学习率阶段结束，无法公平比较 | cosine schedule horizon 约匹配训练 token 数 |
| 只改变模型大小，少改变训练长度 | 无法观察二维 $N$–$D$ 权衡 | 400 多个模型联合扫 $N$ 与 $D$ |

Chinchilla 在 Appendix B 的观察是：当 cosine schedule 的衰减长度大致匹配训练 token 数时，最终损失更好。用生活场景说，给短跑和马拉松都发同一张“在第 10 公里才开始减速”的训练计划，短跑选手会在错误的节奏下结束；这不是选手的能力差异，而是 schedule 没和赛程长度对齐。

📌 **正确的判断**：Kaplan 的 $0.73/0.27$ 不能简单说成“数学上错”，更准确的说法是：Chinchilla 认为旧协议在固定 token、固定 schedule 和联合变化不足的条件下，系统性低估了“多喂数据给较小模型”的收益。

## 5. 工程算账：从预算反推训练 recipe

### 5.1 给定 $C=10^{23}$ FLOPs，应该训多大

现在不看论文表格，直接用“平方根关系 + 20 token / 参数”手算一遍。设经验比例为

$$
D=kN,\qquad k\approx20
$$

其中 $k$ 是每个参数对应的训练 token 数。把它代回主干 FLOPs：

$$
C\approx6ND=6kN^2
\quad\Longrightarrow\quad
N\approx\sqrt{\frac{C}{6k}},
\qquad
D\approx k\sqrt{\frac{C}{6k}}
$$

给定 $C=10^{23}$ FLOPs、$k=20$：

$$
N\approx\sqrt{\frac{10^{23}}{6\times20}}
=\sqrt{8.333\times10^{20}}
\approx2.89\times10^{10}
\approx\boxed{28.9\ \text{B 参数}}
$$

再算 token：

$$
D\approx20\times28.9\ \text{B}
\approx\boxed{577\ \text{B token}=0.577\ \text{T token}}
$$

最后把结果乘回去验算：

$$
6\times(28.9\times10^9)\times(5.77\times10^{11})
\approx1.00\times10^{23}\ \text{FLOPs}
$$

所以，在这个简化口径下，**$10^{23}$ FLOPs 级别的训练作业，起始规划点约是 29B 参数 + 0.58T token**。这不是论文直接训练过的配置，而是把论文的经验比例套进 $6ND$ 后得到的本文手算。

把两种极端方案放在旁边，账会更直观：

| 固定 $C=10^{23}$ FLOPs 的方案 | $N$ | 由 $D=C/(6N)$ 算出的 $D$ | token / 参数 | 工程判断 |
| --- | ---: | ---: | ---: | --- |
| **平方根起点** | $28.9\ \text{B}$ | $0.577\ \text{T}$ | $20$ | 先做基线，再用曲线验证 |
| 模型优先 | $70\ \text{B}$ | $0.238\ \text{T}$ | $3.4$ | 大模型可能欠训练 |
| 数据优先 | $10\ \text{B}$ | $1.67\ \text{T}$ | $167$ | 小模型可能容量受限，数据成本高 |

这里的“可能”不是偷懒，而是诚实边界：只有真实 loss 曲线、数据质量和下游验证才能判定谷底。工程上应把 29B/0.58T 当成待测起点，而不是把 20 当成永远正确的配置。

还可以用论文 Table 3 的规划点做交叉检查。以 $C_0=5.76\times10^{23}$ FLOPs、$N_0=67\ \text{B}$、$D_0=1.5\ \text{T}$ 为近似锚点：

$$
\sqrt{\frac{10^{23}}{5.76\times10^{23}}}
\approx0.417
$$

因此

$$
N\approx67\times0.417\approx27.9\ \text{B},\qquad
D\approx1.5\times0.417\approx0.626\ \text{T}
$$

它与前面的 28.9B/0.577T 在同一数量级。两组结果的差异来自“20 token / 参数”和 Table 3 的 22.4 token / 参数，以及表中 B/T 数字和 FLOPs 的四舍五入；不能把这种小差异当成方法冲突。

### 5.2 从数学起点到真正的训练计划

**20 token / 参数只负责把第一笔预算切开，不能替你完成训练 recipe。** 开工前至少还要检查四件事：

1. **数据够不够且是否重复**：$D$ 是 token 数，不等于独立信息量。重复网页、低质量合成文本和泄漏数据都会让“20”失去原来的含义。
2. **LR schedule 是否跟 $D$ 对齐**：训练到 $0.58T$ token，就要让 schedule 的衰减终点围绕这个 horizon 设计，而不是机械复制另一条训练长度的计划。
3. **精确 FLOPs 与吞吐**：$6ND$ 是主干估算，真实模型要加上 embedding、attention、logits、通信和重计算等开销；硬件能否把这些 FLOPs 变成有效训练速度，另算一笔。
4. **用实际 loss 验证谷底**：至少在目标架构附近扫几个 $N/D$ 点，画出固定预算的 U 型曲线。没有这一步，预算公式只是起始假设。

落成一句话的工程规则：**预算只够训一轮时，先用 $N\approx\sqrt{C/(120)}$、$D\approx20N$ 生成候选，再用等算力 sweep 校准；不要因为参数量看起来更大，就把 token 数压到 3–5 个 / 参数。**

## 6. 边界与延伸：20 tokens/parameter 不是永恒常数

### 6.1 这篇论文真正覆盖了什么

Chinchilla 的强结论来自一个明确范围：2022 年前后的**稠密、自回归语言模型**，以预训练损失为主要优化目标，用模型大小和训练 token 数解释固定训练 FLOPs。它说明在这套条件下，很多大模型相对预算训练得不够久。

它没有单独证明下列场景仍然必须使用 20 token / 参数：

- 混合专家模型：总参数和每个 token 实际激活参数不再是同一笔计算账；
- 多模态模型：图像 patch、文本 token、跨模态模块的“一个 token”成本不同；
- 合成数据和重复数据：原始 token 数增加，不代表有效信息线性增加；
- 强化学习或长思考后训练：训练目标不再只是论文里的 next-token loss；
- 只看部署总成本的产品：预训练多花的 FLOPs，可能换来长期推理成本下降。

因此，“20”更像一个**compute-optimal pretraining 的起始旋钮**。你真正要优化的目标如果包含部署年限、并发、延迟或安全数据成本，最优比例就会随目标函数改变。

### 6.2 Llama 系的“小模型训多 token”：不是反驳，而是换了目标

后续 Llama 系路线常把较小、易部署的模型训练在远高于 Chinchilla 时代经验比例的数据上。这可以理解为 **deliberate over-training（有意过度训练）**：训练阶段多花算力和数据，换取更低的单 token 推理成本、更小的显存门槛和更好的长期服务经济性。它不是把 Chinchilla 的固定训练预算结论推翻，而是把“训练一次”和“部署很多次”的总账一起纳入优化；具体 token 配方留给后续交叉引用阶段核对 [Llama 系技术报告（链接待补）]。

### 6.3 训练算力分配与测试时算力分配是正交的两层问题

Chinchilla 解决的是**预训练内部**的分配：固定 $C_{\mathrm{train}}$，怎样在 $N$ 和 $D$ 之间切。推理时代还会出现另一层预算：固定一次请求的推理 FLOPs，应该多生成几个候选、做更深搜索，还是换更大的模型。

💡 **回顾：训练 vs 推理的 FLOPs 账本**

站内 [1.2 同样的 FLOPs 给预训练还是给推理？测试时计算与最优分配](/AIInfraGuide/inference/模块四-推理优化/第1章-llm推理基础/12-测试时计算与推理算力分配)把测试时计算拆成候选生成、搜索、验证和修订，并说明相同 FLOPs 不等于相同延迟和显存；**本文只处理预训练阶段的 $N/D$ 分配**，不把推理时“想得更久”的预算混进 $6ND$。这个链接负责推理预算和 serving 代价，本文负责训练配方，两个问题可以组合但不能互相替代。

这两个层次的关系可以写成：

$$
\text{总生命周期成本}
=\underbrace{C_{\mathrm{train}}(N,D)}_{\text{一次性预训练}}
+\underbrace{\text{部署请求数}\times C_{\mathrm{inference}}(N,\text{推理策略})}_{\text{反复支付的推理}}
$$

如果模型要服务数十亿次请求，选择更小的模型并在训练时多喂数据，可能比严格追求一次预训练 FLOPs 最优更划算；如果模型只离线使用一次，训练账和部署账的权重又不同。这是目标函数的变化，不是指数互相矛盾。

### 6.4 2022 原文时代与当前工程的边界

| 层次 | 本文采用的口径 | 不能直接外推的地方 |
| --- | --- | --- |
| 原文时代 | 2022 年模型族、自然语言预训练、固定训练 FLOPs、密集 Transformer | 新架构、新数据形态和后训练目标可能改变比例 |
| 当前工程 | 数据质量、合成数据、部署推理、测试时计算共同影响总成本 | 不能把后续经验倒写成 Hoffmann 等人的原文结论 |
| 实际决策 | 用 20 token / 参数生成候选，再用 IsoFLOP sweep 和下游评测校准 | 没有目标硬件、数据和负载时，不应声称一个普适最优数字 |

论文的证据最强之处是“同预算的 70B 与 280B 对照”，最需要保留的限制是“前沿由较小模型外推，旗舰验证主要依赖一组 Chinchilla–Gopher 对比”。因此，今天使用这条规律时，应该把它当作可检验的预算先验，而不是物理常数。

## 📝 总结

1. **问题建模**：把固定训练算力写成 $\min L(N,D)\ \text{s.t.}\ C\approx6ND$；$N$ 是参数量，$D$ 是训练 token 数，$C$ 是总 FLOPs。
2. **6 的来源**：一次乘加按 2 个 FLOPs 计，前向约 $2ND$，反向按前向两倍约 $4ND$，合计 $6ND$；论文 Appendix F 的精确账与它接近。
3. **核心结论**：Chinchilla 的三种方法都支持 $N_{\mathrm{opt}}\propto C^{0.5}$、$D_{\mathrm{opt}}\propto C^{0.5}$，实际规划可先用约 20 token / 参数。
4. **三种方法**：训练曲线包络取每个预算的最低点，IsoFLOP 沿等算力线找 U 型谷底，参数化拟合在 $6ND=C$ 上对损失求导。
5. **数值手算**：$C=10^{23}$ FLOPs、$D\approx20N$ 时，$N\approx28.9$B、$D\approx0.577$T；这是本文依据论文比例的估算，不是论文直接报告的训练运行。
6. **实证对照**：70B/1.4T 的 Chinchilla 与 280B/300B 的 Gopher 使用同训练 FLOPs，MMLU 5-shot 为 67.6% 对 60.0%，Chinchilla 还少 4 倍参数。
7. **方法论批判**：固定 300B token、LR schedule 不匹配、$N/D$ 联合变化不足，会让大模型提前结束并把欠训练误判成规模规律。
8. **工程边界**：20 是 2022 年 dense autoregressive 预训练的起点，不是混合专家模型、多模态、合成数据、强化学习或部署总成本下的永恒常数。
9. **两层预算**：Chinchilla 优化预训练内部的 $N/D$；测试时计算文章优化推理阶段的候选、搜索和验证，二者正交。
